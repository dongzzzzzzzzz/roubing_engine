## 一、先理解整套方法在做什么

roubing 的重点不是预测某只股票一定涨，而是不断回答下面六个问题：

1. 现在的市场适不适合承担风险？
2. 资金正在反复回到哪个方向？
3. 这个方向目前走到了什么阶段？
4. 方向里的每只重要股票分别承担什么任务？
5. 根据今天的表现，它明天本来应该怎样？
6. 明天的真实表现是在确认原判断，还是在推翻原判断？

所以，完整流程必须按下面的顺序进行：

1. 明确当前能使用到什么时间的数据；
2. 判断市场环境；
3. 判断主流方向；
4. 确定当前节点；
5. 给方向内的股票划分角色；
6. 找出真正互相竞争的股票；
7. 为每只候选写出次日预期；
8. 准备主路径、替代路径和空仓路径；
9. 次日竞价验证；
10. 开盘后五分钟再次验证；
11. 决定低吸、半路、回封、尾盘确认或不行动；
12. 持有期间继续检查角色；
13. 预期、角色、板块或环境失效时退出；
14. 收盘后重新做下一天的判断。

任何一步没有完成，都不能直接跳到“买哪只股票”。

## 二、先分清原始数据、逐日推演和真正阻断

### 1. 什么叫信息截止时间

每次分析必须先写清楚：当前判断发生在什么时间。

例如：

- T 日收盘后；
- T+1 日 9:15；
- T+1 日 9:20；
- T+1 日 9:25；
- T+1 日开盘五分钟后；
- T+1 日收盘后。

这里的 T 日，是制定计划的当天；T+1 日，是执行和验证计划的下一个交易日。

盘后计划、竞价判断、开盘判断和收盘复盘必须分开保存。不能看到收盘结果以后，再把盘前理由改成“我早就知道”。

### 2. 接口应提供的原始事实

两套接口合用以后，正常的逐日分析至少应保存下面这些事实：

| 数据层 | 需要保存的内容 | 主要用途 |
| --- | --- | --- |
| 市场层 | 主要指数日线与分钟线、全市场成交额、上涨下跌家数、涨停跌停炸板数量 | 判断市场是扩张、轮动、退潮还是止跌候选 |
| 板块层 | 行业和题材指数、板块成交、涨幅、涨停家数、当前成分股 | 比较方向强度，跟踪主流的启动、分歧、修复和退潮 |
| 个股日线层 | 开高低收、成交量额、复权、上市日期、流通市值、涨跌停价格 | 识别突破、区间涨幅、趋势、换手和容量 |
| 涨停事件层 | 涨停、跌停、炸板池，涨停时间、封单、开板次数、连板高度 | 识别先锋、换手核心、连板高度、助攻和次日反馈 |
| 题材事实层 | 同花顺涨停原因、个股所属概念、入选题材日期和原因 | 先判断市场当日正在交易什么催化、哪些股票属于同一叙事 |
| 竞价层 | 9:15 至 9:25 的价格、匹配量、未匹配量、方向、封单变化和 9:25 成交 | 验证弱转强、撤单、排名迁移、假强真弱和竞价卡位 |
| 分时成交层 | 一分钟行情、成交明细、分时均线、上板炸板回封时刻 | 判断第一轮卖压、承接、主动进攻、回封和强弱分离 |
| 盘口层 | 实时五档价格与挂单量 | 实盘辅助观察压单、封单和瞬时流动性，不把它冒充完整委托队列 |
| 规则层 | 当日有效的交易所规则、监管公告、异动公告、停复牌和风险警示状态 | 计算当时真实的异动与监管空间 |

Financial-API 更适合补齐长周期日线、板块、历史涨跌停池、连板天梯、涨停原因和当日竞价终态；eltdx 更适合当日及可取得日期的竞价过程、09:25 正式撮合、分钟线、成交明细、实时五档和盘中事件。Financial-API 的竞价快照没有历史日期参数，不能把它当作历史逐股竞价库；历史竞价应优先尝试 eltdx，并以主站实际保存范围为准。两者的职责不是替 AI 给出“主流”“龙头”“卡位”结论，而是提供结论所依赖的事实。

### 3. 必须由 AI 逐日推演的结果

下面这些不是任何接口应当直接提供的字段，而是 AI 每个交易日根据截止当时的事实重新计算：

- 当前市场环境；
- 当日热点是否升级为弱主流、普通主流或超级主流；
- 主流处于启动、延续、分歧、修复、主升、震荡还是退潮；
- 总核心、情绪高度、容量核心、分支核心、助攻、补涨和跟风分别是谁；
- 哪些股票属于真正的同组竞争，谁先主动、谁被反推、谁完成卡位；
- 每只候选次日本来应该怎样，实际是超预期、符合预期还是不及预期；
- 板块修复是否仍有质量，旧核心是否被新核心替代；
- 这一天应继续原路径、切换替代路径还是不行动。

历史主流尤其不能向数据源索要一个“历史主流”字段。正确方法是从最早交易日开始，严格按日推进：T 日只能使用 T 日收盘前已经发生的行情、涨停原因和当时有效规则；得到 T 日结论后，再读取 T+1 日数据进行验证和状态迁移。后面的结果不能倒灌到前一天。

### 4. 催化和产业判断怎样落地

短线流程里，先以同花顺涨停原因作为市场叙事的事实入口：

1. 汇总当天所有涨停股的涨停原因；
2. 把原因相近的股票聚成候选方向；
3. 区分新出现的原因、连续发酵的原因和已经反复交易的旧原因；
4. 检查同一原因下是否同时出现先锋、容量、连板和后排扩散；
5. 次日检查这些股票是否继续给买方溢价，原因对应的方向是否继续扩散；
6. 只有“原因持续出现 + 资金持续选择 + 分歧后能修复”同时成立，才把催化升级为主流依据。

涨停原因回答的是“市场正在用什么理由交易这只股票”，不能单独证明公司长期产业价值。但在本项目当前的短线推演范围内，先用它完成催化、题材归组和产业映射，不再把新闻或产业库缺失列为流程阻断。

### 5. 监管数据怎样处理

监管和异动规则不属于不可获得数据。系统需要建立按日期生效的规则表，并在每个历史交易日读取：

- 股票所属交易所和板块；
- 当日有效的异常波动、严重异常波动、停复牌和风险警示规则；
- 交易所或上市公司已经发布的监管、异动、停牌公告；
- 作者案例常用的区间涨幅与偏离值计算所需的指数和复权价格。

规则变化时必须按生效日期切换，不能用 2026 年规则回算更早年份。具体规则应以交易所正式文件和当时公告为准，帖子中的“十日百分之百”“三十日百分之二百”等只能作为作者当时的使用案例，不能代替规则库。

### 6. 当前真正的阻断项

目前只保留下面三项 `BLOCK`：

1. **完整历史严格盘中回放：`BLOCK`。** 历史秒级竞价、分钟和成交明细的保存范围无法保证覆盖所有旧交易日；如果某天只剩 9:25 最终开盘，就不能复原 9:15 初始封单、9:20 撤单和中途排名迁移。
2. **历史盘口与委托队列回放：`BLOCK`。** 现有接口可提供实时五档，但不能保证还原旧交易日每一时刻的挂单、撤单和队列位置。
3. **完整逐笔委托与撤单 Level-2：`BLOCK`。** 成交明细不等于完整委托流，因此不能伪造某笔撤单者或队列意图。

历史日线、板块、涨停原因、历史 09:25 正式撮合和部分分钟/成交明细能回补到什么范围，应在实际接入时逐日验收。某日确实取不到竞价或盘中过程数据，只阻断依赖该过程的判断，不阻断当日环境、主流、角色和日线层推演。

### 7. 五类内容必须分开写

1. 已经观察到的事实。
2. 作者在原帖中的解释。
3. 根据事实作出的推断。
4. 因数据不足而无法确认的部分。
5. 判断时间之后才发生的结果。

这样可以防止把推测写成事实，也可以防止用后来的结果污染当时的判断。

### 8. 数据获取与落库操作手册

这一节是本项目的数据接入说明。后续执行不需要再先阅读两个开源项目的 README，但接口升级后仍要以项目最新契约做兼容性检查。

本次核对来源为 `https://github.com/HiThink-Tech/Financial-API` 和 `https://github.com/electkismet/eltdx`。核对时的提交分别为 `44b7aa34dd504675f3ddaa15b3d478ea16f97884` 和 `20a1eefaefbb1b66a75579efb6de858dca818cb0`，日期为 2026-09-10。后续版本如果修改方法名、字段或能力边界，应先更新本节再运行采集程序。

#### 8.1 两套数据源怎样分工

| 数据任务 | 首选来源 | 备用或校验来源 | 使用边界 |
| --- | --- | --- | --- |
| 全市场多年日线 | Financial-API Market Dumps | eltdx `client.bars.get()` | 全量建库不要逐股请求 REST |
| 少量个股日线、复权日线 | Financial-API 历史 K 线 | eltdx K 线 | 必须保存复权口径 |
| 指数和板块日线 | Financial-API 指数历史 K 线 | eltdx 指数 K 线 | Financial-API 只有日线，分钟看 eltdx |
| 板块目录和当前成分 | Financial-API 板块目录、成分股 | eltdx 概念板块 | 返回的是当前成分，不能倒推历史成分 |
| 历史涨停、跌停、炸板、涨停原因 | Financial-API 特色数据 | eltdx F10 涨跌停列表 | 盘后最终事实优先保存 Financial-API，差异不能静默覆盖 |
| 当日实时连板和封单 | eltdx 实时涨停梯队 | Financial-API 当日涨停池 | Financial-API 更适合终态或低频快照，不替代五档实时观察 |
| 当日竞价 9:15—9:25 过程 | eltdx `client.auctions.series()` 或 `auction_data()` | Financial-API `stage=live` 只做逐股当前快照校验 | Financial-API 不返回完整过程序列 |
| 当日 09:25 正式撮合 | eltdx `client.helpers.auction_data()` | Financial-API `stage=final` | 竞价过程中的 09:25 虚拟快照不等于正式成交 |
| 历史 09:25 正式撮合 | eltdx `opening_match_history()` | 无稳定完整备用源 | 取不到即只阻断依赖历史开盘撮合的结论 |
| 历史竞价过程 | eltdx `client.auctions.series(code, date)` | 无 | 主站留存不保证，属于已列出的 `BLOCK` 范围 |
| 当日和历史分钟 | eltdx `minutes.today/history()` | 无 | 历史日期能否取得要逐日验收 |
| 当日和历史成交明细 | eltdx `trades.all_today/all_history()` | 无 | 成交明细不是完整逐笔委托和撤单 |
| 实时五档 | eltdx `helpers.full_quotes()` | 无 | 只能表示抓取时刻的五档，不代表完整队列历史 |
| 个股题材、入选日期和原因 | eltdx F10 热点题材 | Financial-API 当日涨停原因 | F10 题材是公司关联事实，涨停原因是当日市场交易叙事，两者不可混为一列 |
| 公告列表和公告链接 | eltdx F10 公告 | 交易所和巨潮资讯原文 | 关键监管结论必须回到正式公告原文核对 |
| 监管规则 | 交易所、证监会正式规则库 | 帖子只作线索 | 必须按生效日期版本化，不能用现行规则回算历史 |

#### 8.2 Financial-API：安装、认证和通用协议

Financial-API 的 REST 基址是 `https://fuyao.aicubes.cn`。公开数据端点当前使用 `GET`，认证头为 `X-api-key`。统一响应是 `{code, message, request_id, data}`；必须同时满足 HTTP 200 和 `code == 0` 才算成功。`data=null`、字段为 `null` 或返回空集合都不能擅自补零。

API Key 应保存到环境变量 `HITHINK_FINANCE_API_KEY` 或系统凭据库，不能写进本文档、代码、日志和 Git。

CLI 安装与首次检查：

```bash
npm install -g @hithink-tech/hithink-finance-cli
hithink-finance auth login
hithink-finance capabilities --format json
hithink-finance data init --format json
```

REST 最小调用格式：

```bash
curl 'https://fuyao.aicubes.cn/api/a-share/prices/snapshot?thscodes=600519.SH' \
  -H "X-api-key: $HITHINK_FINANCE_API_KEY"
```

常见错误处理：`1001` 补必填参数，`1002` 修正格式，`1003` 缩小窗口或分页，`2001/2003` 检查认证，`3001` 先消歧代码，`3002` 保留 `request_id` 后稍后再查，`4001` 做有界退避，`5xxx` 有界重试并保留 `request_id`。不得在失败时制造模拟数据。

#### 8.3 Financial-API：本流程实际使用的接口

**代码表和交易日历**

```text
GET /api/meta/tickers/search?q=贵州茅台&asset_type=a-share&limit=5
GET /api/meta/tickers/list?exchange=SH,SZ,BJ&asset_type=a-share&limit=1000&offset=0
GET /api/a-share/calendar/trading-days
```

- 检索字段：`thscode`、`ticker`、`name`、`exchange`、`asset_type`、`currency`。名称或纯代码出现多个结果时，必须按资产类别和交易所消歧，不能猜后缀。
- 代码表使用 `limit/offset` 分页，完整 A 股列表必须显式包含 `BJ`；默认交易所只有沪深。
- 交易日历只返回上海时区最近一年。更早的历史交易日应由全量日线实际日期补建并与交易所日历核对，不能假定自然日连续。

**个股行情与日线**

```text
GET /api/a-share/prices/snapshot?thscodes=600519.SH,000001.SZ
GET /api/a-share/prices/historical?thscode=600519.SH&interval=1d&start=<毫秒>&end=<毫秒>&adjust=forward
```

- 快照主要字段：`thscode`、`ticker`、`last_price`、`price_change_ratio_pct`、`open_price`、`high_price`、`low_price`、`prev_price`、`volume`、`turnover`。快照不返回中文名。
- 历史日线主要字段：`date_ms`、`open_price`、`high_price`、`low_price`、`close_price`、`volume`、`turnover`。
- `historical` 单次只能查一只股票，窗口最长十年，只支持 `1d`；`adjust` 可用 `none`、`forward`、`backward`。

**指数和板块**

```text
GET /api/a-share-index/catalog/ths-index-list?tag=cn_concept
GET /api/a-share-index/catalog/ths-index-list?tag=industry
GET /api/a-share-index/constituents/ths-stock-list?thscode=886042.TI
GET /api/a-share-index/prices/snapshot?thscodes=000300.SH,000001.SH
GET /api/a-share-index/prices/historical?thscode=886042.TI&interval=1d&start=<毫秒>&end=<毫秒>
```

- 目录的 `tag` 可取 `cn_concept`、`region`、`tszs`、`industry`。
- 板块目录字段为 `thscode`、`name`；成分字段为 `thscode`、`ticker`、`name`。
- 成分接口只返回当前成分。做历史回放时，只能使用当日已经保存的成员快照，或者用当日涨停原因重新归组；严禁拿今天的成分名单覆盖过去。
- 指数历史接口单次一只、窗口最长十年、只有日线且没有复权参数。

**涨停、跌停、炸板和原因**

```text
GET /api/a-share/special-data/limit-up-pool?date_ms=<上海零点毫秒>&page=1&size=200&sort_field=limit_up_time&sort_dir=asc
GET /api/a-share/special-data/limit-down-pool?date_ms=<上海零点毫秒>&page=1&size=200
GET /api/a-share/special-data/limit-break-pool?date_ms=<上海零点毫秒>&page=1&size=200&sort_field=open_times&sort_dir=desc
GET /api/a-share/special-data/limit-up-ladder
```

- 涨停池字段：`thscode`、`ticker`、`name`、`is_st`、`is_new`、`last_price`、`price_change_ratio_pct`、`limit_up_time`、`limit_up_reason`、`continue_day_text`、`continue_day_cnt`、`seal_money`、`max_seal_money`。
- 跌停池字段：`first_limit_time`、`last_limit_time`、`turnover_ratio_pct` 等。
- 炸板池字段：`open_times`、`turnover_ratio_pct`、`turnover` 等；`open_times` 是开板次数，不是连板数。
- 三个池都使用 `page/size`，单页最多 200。非交易日空集合不等于接口失败。
- 连板天梯是固定近 30 个交易日矩阵，只覆盖二板至七板以上，每个梯队最多四只，不能用它替代完整逐股涨停池。

当日题材归组以 `limit_up_reason` 为第一入口。同一股票可同时保留公司 F10 题材和当日涨停原因，但 AI 判断“今天市场在交易什么”时优先读取当日涨停原因。

**集合竞价**

```text
GET /api/a-share/auction/snapshot?thscodes=600519.SH,000001.SZ&stage=live
GET /api/a-share/auction/snapshot?thscodes=600519.SH,000001.SZ&stage=final
GET /api/a-share/auction/short-term-benchmark?date=2026-08-14
```

- 逐股快照字段：`auction_price`、`auction_pct`、`auction_volume`、`auction_amount`、`auction_unmatched`、`auction_turnover_pct`、`auction_yesterday_ratio_pct`、`auction_volume_ratio`、`pre_close_price`、`open_price`、`last_price`、`float_market_cap`。
- `stage=live` 是当前竞价阶段快照，`stage=final` 是当前竞价终态；两者均没有历史日期参数。
- `short-term-benchmark` 可按 `YYYY-MM-DD` 查询，返回 `thscode`、`ticker`、`name`、`auction_pct`、`tags`，适合恢复当日风向标排名，不等于恢复每只股票 9:15—9:25 的过程。

**全市场历史建库**

```text
GET /api/dump/market-dumps/daily-k/download-url
GET /api/dump/market-dumps/daily-k-10d/download-url
GET /api/dump/market-dumps/adjustment-factors/download-url
```

这三个端点先返回有效期约五分钟的 `data.presigned_url`，随后立即下载 Parquet。全量日 K 约覆盖最近十年；近十日文件用于日常增量；复权文件保存分红、送股和配股事件。日 K 按 `(thscode, date_ms)` 去重或更新。若本地落后超过七个交易日，不依赖十日增量猜测缺口，重新拉全量或逐日验收。

Financial-API 当前公开能力不包括分钟 K、tick、Level-2、A 股新闻公告原文和研报，因此这些内容不能从该接口强取。

#### 8.4 eltdx：安装和统一调用入口

安装：

```bash
pip install eltdx
```

本流程统一使用模块化 `TdxClient`，不使用旧版扁平入口。最小示例：

```python
from eltdx import TdxClient

with TdxClient(timeout=3) as client:
    day = client.bars.get("sz000001", period="day", adjust="qfq", count=200)
    auction = client.helpers.auction_data("sz000001", "2026-05-20")
    minute = client.minutes.history("sz000001", "2026-05-20")
    trades = client.trades.all_history("sz000001", "2026-05-20")
    quotes = client.helpers.full_quotes(["sz000001", "sh600000"])
```

常用代码格式是 `sz000001`、`sh600000`、`bj920856`。不能把 Financial-API 的 `000001.SZ` 原样传入而不做适配。建议落库统一保存 `thscode`，调用 eltdx 时再转换：`.SZ -> sz`、`.SH -> sh`、`.BJ -> bj`。

eltdx K 线备用调用：

```python
day = client.bars.get("sz000001", period="day", adjust="qfq", count=200)
minute_k = client.bars.get("sz000001", period="1m", count=240)
history = client.bars.get("sz000001", period="day", all_pages=True, page_size=800)
```

`KlineBar` 主要字段为 `time`、`open`、`high`、`low`、`close`、`volume_lots`、`amount`。`period` 支持 `1m`、`5m`、`15m`、`30m`、`60m`、`day`、`week`、`month` 等；`adjust` 支持 `none`、`qfq`、`hfq`。扩展秒级或自定义周期是否有数据以主站实际返回为准，不能因为参数可传就假定历史完整。

#### 8.5 eltdx：竞价、分钟、成交和五档怎样取

**竞价聚合入口**

```python
auction = client.helpers.auction_data("sz000001")
history = client.helpers.auction_data("sz000001", "2026-05-20")
```

`AuctionData` 把三类事实放在一起：

- `series.points`：竞价过程点，主要字段为 `time_label`、`time_seconds`、`price`、`matched_volume`、`unmatched_volume`、`unmatched_direction_raw`；匹配量和未匹配量单位为手。
- `snapshot_0925`：09:25 正式撮合，主要字段为 `price`、`volume`、`order_count`、`event_kind="opening_match"`、`trade_amount_yuan`。
- 汇总字段：`pre_close_price`、`open_price`、`open_volume`、`open_amount`、`open_change_pct`。

如果只要过程，可用：

```python
series = client.auctions.series("sz000001", "2026-05-20")
```

过程接口通常几秒一个点，也可能包含 14:57 后的尾盘竞价。过程里即使出现 `09:25`，仍可能只是虚拟撮合；正式开盘必须读取 `snapshot_0925` 或 `opening_match_history()`。历史覆盖由主站实际留存决定，没有数据时不能用 9:25 开盘价反造中途撤单和排名。

**分钟线**

```python
today = client.minutes.today("sz000001")
history = client.minutes.history("sz000001", "2026-05-20")
```

主要字段：`time_label`、`time`、`price`、`volume`、`avg_price`。历史接口的 `open_price` 和 `avg_price` 可能为空。当日接口本身不返回交易日期，采集系统必须用上海时区的实际交易日补充 `trade_date`，并检查周末或凌晨是否返回了最近交易日旧数据。

**成交明细和事件顺序**

```python
today = client.trades.all_today("sz000001")
history = client.trades.all_history("sz000001", "2026-05-20")
opening = client.trades.opening_match_history("sz000001", "2026-05-20")
```

`TradeTick` 主要字段：`time_label`、`trade_datetime`、`price`、`volume`、`order_count`、`event_kind`、`is_actual_trade`、`side`、`status_raw`、`trade_amount_yuan`。读取盘中主动性时使用 `actual_trades`，不要把 `status=8` 的竞价简化快照当成真实成交。`all_history()` 每页最多 1800 条并自动翻页，历史日期能否完整返回仍需逐日验收。

成交明细可以排列“谁先拉升、谁先上板、谁先炸板、谁随后被带动”的事件顺序，但它不是完整逐笔委托流，不能据此断言某一笔撤单者是谁。

**实时五档**

```python
quotes = client.helpers.full_quotes(["sz000001", "sh600000"])
```

主要字段：`last_price`、`pre_close_price`、`open_price`、`high_price`、`low_price`、`total_hand`、`amount`、`inside_dish`、`outer_disc`、`buy_levels`、`sell_levels`、`sum_buy_vol`、`sum_sell_vol`。每档只有 `price` 和 `volume` 等当前快照字段。它适合实盘观察压单、封单和瞬时流动性；若没有持续采样，就不能回放过去的五档变化。

#### 8.6 eltdx：涨跌停、题材、公告和市场宽度怎样取

**历史或盘后涨跌停明细**

```python
table = client.f10.limit_up_down_list("20260904", include_summary=True)
history = client.f10.limit_up_down_list("20260903", "20260904")
```

逐股字段：`trading_date_value`、`full_code`、`name`、`status`、`board_level`、`highest_board_level`、`industry`、`reason`、`seal_amount`、`limit_time`、`broken_count`。`status` 可为 `limit_up`、`broken`、`limit_down`。`board_level` 才是该股板位，`highest_board_level` 是当天最高板，不能混用。

`include_summary=True` 还返回 `advancing_count`、`declining_count`、`flat_count`、`limit_up_count`、`limit_down_count`、`today_amount`、`previous_amount` 和热门题材，可补市场宽度与成交额。汇总涨停家数和逐股明细行数口径可能不同，应分别保存。

**当日实时涨停梯队**

```python
ladder = client.helpers.limit_ladder(
    codes=["sz000001", "sh600000"],
    include_touched=True,

```

主要字段：`limit_status`、`ladder_level`、`limit_board_text`、`seal_amount`、`last_price`、`change_pct`、`open_change_pct`、`open_amount`、`opening_rush`、`prev_amount`、`auction_prev_volume_ratio`、`free_float_market_value`。该 Helper 要在集合竞价完成后使用；盘中高频观察应传候选代码，不要反复全市场扫描。

**股票名称、板块、流通股本、上市日期和市值**

```python

    ["sz000001", "sh600000"], trade_date="2026-08-28"
```

`stock_profile_table()` 主要字段：`name`、`category`、`board`、`last_price`、`amount`、`circulating_shares`、`total_shares`、`turnover_rate`、`circulating_market_value`、`total_market_value`、`ipo_date`、`updated_date`。这些字段用于判断主板范围、容量和上市初期状态，不直接决定角色。

`daily_price_limits()` 主要字段：`pre_close_trade_date`、`pre_close`、`limit_up_price`、`limit_down_price`、`limit_ratio_pct`、`limit_rule`、`limit_status`。它是按照 eltdx 本地规则计算的便利结果；历史严格回放仍应以本节建立的正式规则版本库复核，不能把当前软件内置规则无条件当作所有年份的权威答案。

**个股题材和当日题材强度**

#### 8.7 监管规则和监管公告怎样建立历史库

正式来源按优先级使用：

1. 上海证券交易所规则库：`https://www.sse.com.cn/lawandrules/sselawsrules/`；
2. 深圳证券交易所规则库：`https://www.szse.cn/lawrules/rule/`；
3. 北京证券交易所业务规则：`https://www.bse.cn/business_rules/`；
4. 中国证监会规章规则：`https://www.csrc.gov.cn/csrc/c100028/common_list.shtml`；
5. 上市公司正式公告原文，可由 eltdx 公告列表发现，再到交易所或巨潮资讯 `https://www.cninfo.com.cn/` 核验。

规则库不能只保存一份“当前规则”。每一版至少保存：`exchange`、`board`、`rule_name`、`rule_url`、`published_on`、`effective_from`、`effective_to`、`version`、适用证券范围、异常波动窗口、涨跌幅或偏离值口径、停牌或重点监控后果、原文文件哈希和抓取时间。

历史回放时，先按 `T日`、交易所、板块和风险状态选择当时有效版本，再计算监管空间。若只能找到现行规则、找不到 T 日有效旧版，则监管结论标记为“规则版本待核实”，不能拿现行阈值硬套，但这不阻断行情和角色推演。

#### 8.8 统一字段和单位，避免两套接口互相污染

| 项目 | 统一要求 |
| --- | --- |
| 交易日时区 | 一律按 `Asia/Shanghai`；服务器返回“当日”时必须核对真实交易日 |
| 股票主键 | 落库统一用 `thscode`，同时保存 eltdx `full_code` |
| 成交量 | 明确 `share` 或 `hand`；A 股一手通常为 100 股，不能直接相加 |
| 涨跌幅 | 字段名保留 `_pct`；`1.74` 表示 1.74%，不要再乘 100 |
| 价格 | 同时保存原始值和复权口径；竞价与盘中交易使用当日真实价 |
| 时间 | 同时保存业务发生时间 `event_time` 和抓取时间 `fetched_at` |
| 空值 | `null` 表示未知、不适用或尚未就绪，不得改成 0 |
| 来源 | 每行必须保存 `source`、接口或方法名、请求参数、`request_id` 或原始记录标识 |

建议至少建立下面十二张事实表：

| 表 | 主键或唯一键 | 必存内容 |
| --- | --- | --- |
| `stock_daily_bar` | `thscode + trade_date + adjust` | 开高低收、量额、复权口径、来源 |
| `index_daily_bar` | `index_code + trade_date` | 板块或指数开高低收、量额 |
| `board_membership_snapshot` | `board_code + thscode + as_of_date` | 当日保存的成分关系，禁止事后覆盖 |
| `limit_event` | `trade_date + thscode + source` | 涨停/跌停/炸板、时间、板位、开板次数、封单、原因 |
| `theme_fact_daily` | `trade_date + thscode + theme_or_reason` | 涨停原因、F10 题材、入选日期、事实类型 |
| `auction_point` | `trade_date + thscode + event_time + source` | 竞价价格、虚拟匹配量、未匹配量和方向 |
| `opening_match` | `trade_date + thscode` | 09:25 正式价格、量、额、昨收参考价 |
| `minute_bar` | `trade_date + thscode + minute` | 分钟价格、量、均价 |
| `trade_tick` | `trade_date + thscode + absolute_index` | 时间、价格、量、方向、事件类型、是否真实成交 |
| `depth_snapshot` | `trade_date + thscode + event_time` | 买卖五档、封单、抓取时刻 |
| `announcement` | `thscode + rec_id或url` | 公告时间、标题、类型、来源、原文链接 |
| `rule_version` | `exchange + board + rule_name + effective_from` | 生效区间、规则参数、原文和哈希 |

AI 推演结果另存 `reasoning_daily`，不得写回事实表。至少保存：信息截止时间、环境、主流、节点、角色、竞争组、次日预期、确认条件、取消条件、证据行 ID 和无法判断项。

#### 8.9 每个交易日何时采集

| 时间 | 必做采集 | 用途 |
| --- | --- | --- |
| 盘前 | 上一交易日日线、涨跌停池、涨停原因、板块日线、公告、当日有效规则 | 生成 T 日盘后计划或复核缺失数据 |
| 09:15—09:20 | 候选股竞价过程和当前排名 | 记录初始态；此时不把可撤单封单当最终强度 |
| 09:20—09:25 | 候选股竞价过程持续采样 | 观察撤单后价格、匹配量、未匹配量与同组排名迁移 |
| 09:25 后立即 | eltdx `auction_data()`、09:25 正式撮合、Financial-API `stage=final` | 固化开盘价、量、额和竞价终态 |
| 09:30—09:35 | 候选股五档快照、分钟、成交明细增量、板块和核心行情 | 验证第一轮卖压、承接、主动性和卡位 |
| 盘中关键事件 | 上板、炸板、回封、板块急拉急跌时追加行情、五档和成交明细 | 保存事件先后关系，不只保存收盘结果 |
| 收盘后 | 最终日线、涨停/跌停/炸板、原因、板块数据、市场宽度、公告 | 重算角色、主流和次日预期 |
| 数据就绪后 | Financial-API 近十日日 K 增量，按主键更新 | 维护长期历史库 |

竞价和五档的具体轮询频率应只针对候选池设置，并服从接口承载和本地限速。关键不是盲目全市场高频抓取，而是保证计划中的核心、容量、助攻和同组对手都有同时间轴数据。

#### 8.10 冲突、缺失和降级规则

1. 同一字段来自两套接口时，原始值分列保存，不先求平均；盘后最终涨停事实以 Financial-API 为主、eltdx 为校验，盘中过程以 eltdx 为主。
2. 两源在交易日、复权、单位、证券状态不同的情况下不直接比较，先完成口径归一。
3. 当前板块成分不能替代历史成分；缺历史成分时，用当日涨停原因和当时保存的题材事实做逐日归组，并明确覆盖不完整。
4. 只有 09:25 结果、没有 9:15—9:25 过程时，可以判断最终开盘强弱，不能判断撤单、假强真弱过程和中途卡位。
5. 有分钟、无成交明细时，可以判断分钟级承接和相对强弱，不能精确排列秒级主动进攻顺序。
6. 有成交明细、无委托队列时，可以判断成交事件先后，不能判断完整撤单意图。
7. 接口仓库文档说明了能力，不等于本地已经完成运行验收。每个历史日期都要记录 `available`、`partial`、`empty` 或 `error`，不得因为文档写“支持历史”就假定所有年份都有数据。

## 三、T 日盘后第一步：判断市场环境

判断环境的目的，不是给市场贴一个漂亮标签，而是决定：

- 是否应该出手；
- 可以持有多久；
- 应该关注核心还是只做短线套利；
- 当前适合延长观察，还是只做短验证后退出。

### 1. 固定观察顺序

1. 指数处在上升、震荡还是快速下跌结构。
2. 市场总成交是否支持大资金持续进攻。
3. 大成交股票是否持续给买方正反馈。
4. 昨日强势股次日是继续上涨，还是被核、跌停甚至连续跌停。
5. 赚钱效应集中在少数核心，还是扩散到整个板块。
6. 旧主流是否还有承接，新方向是否已经形成替代。

### 2. 四种环境

#### 主流主升环境

可以观察到：

- 先锋股和容量股共同上涨；
- 板块指数连续走强或突破；
- 板块分歧后，核心能够率先修复；
- 前一天参与的资金持续有利润；
- 原核心受到限制时，板块内部能出现新的承接载体。

这种环境下，可以围绕主流核心研究，持有时间也可以相对延长。

取消条件：原核心结束，板块没有新核心接替；或者板块分歧后，核心和容量股都无法修复。

#### 轮动震荡环境

可以观察到：

- 指数在一个区间里来回震荡；
- 板块今天涨、明天跌；
- 没有一个方向形成持续主升；
- 赚钱效应集中在极少数股票或很短的小周期里。

这种环境下，要缩小股票池、缩短持有时间，优先研究隔日交易或短波段，不追板块后排。

切换条件：某个方向开始连续走强，容量股加入，分歧后还能修复，它才可能从轮动升级为主流。

#### 下跌或系统性风险环境

可以观察到：

- 指数快速下行；
- 强势股与指数一起杀跌；
- 强势股跌停后，次日继续跌停；
- 亏钱效应不断扩散。

这种环境下，重点是等待，或只保留需要继续验证的核心候选，不能照搬主升期的持有方式。

切换条件：连续跌停停止扩散，指数停止杀跌，新题材和新核心开始连续得到确认。

#### 新旧秩序切换期

有时旧主流正在衰退，新方向又没有完全确认。此时证据互相冲突，不能强行归入主升、震荡或下跌。

正确处理是同时保留：

- 旧主流是否修复；
- 新方向是否接替；
- 两边都失败时的空仓路径。

“新旧秩序切换期”是为了避免强行判断而增加的研究容器，不是 roubing 给出的固定市场分类。

### 3. 环境怎样逐日迁移

环境判断可以执行，但不能被压成一个固定分数。每天按下面顺序迁移：

1. 先比较昨日强势股的次日反馈：普遍有溢价、分化，还是普遍低开和核按钮；
2. 再比较大成交核心：是否继续创新高，还是放量冲高回落；
3. 再看赚钱效应是否从核心向助攻和后排扩散；
4. 再看亏钱效应是否从后排向核心蔓延；
5. 最后看新方向能否在旧方向走弱时主动承接，并在下一日继续得到确认。

输出必须写成“与前一日相比，哪一类反馈增加、哪一类反馈减少，因此环境从什么候选迁移到什么候选”。总成交额和涨跌停数量是背景证据，不使用脱离历史分布的固定门槛，也不把没有固定门槛误写成规则缺失。

## 四、T 日盘后第二步：确认主流方向

主流不是当天涨停最多的板块，而是资金经过启动、延续和分歧以后，仍然愿意回去的方向。

### 1. 历史主流必须怎样逐日推演

系统必须为每个候选方向维护一份逐日账本，不能事后一次性回看完再下结论。

| 交易日 | 当日只能记录的事实 | 当日状态输出 | 下一日必须验证什么 |
| --- | --- | --- | --- |
| 启动候选日 | 涨停原因是否集中、先锋是否率先上板、容量股是否放量、板块指数是否转强 | 随机热点、试盘或启动候选 | 先锋能否延续，容量能否继续进攻，后排是否有严重负反馈 |
| 第二日 | 先锋是否连板、容量是否反包或继续大阳、板块是否增强 | 一日游、弱主流候选或普通主流候选 | 第三日能否保持梯队，板块指数能否继续走强 |
| 第三日及以后 | 前排、容量、后排和板块指数是否继续协同 | 主流确认、弱主流、分歧或退潮候选 | 第一次分歧后能否修复，买方是否继续得到溢价 |
| 分歧日 | 谁先弱、谁抗跌、谁仍维持涨停或换手，板块结构是否破坏 | 良性分歧、高位推进失败或退潮候选 | 次日核心是否率先弱转强，容量与板块是否响应 |
| 修复日 | 板块是否止跌或反包、核心是否领涨、后排是否停止负反馈 | 修复成功、弱修复或修复失败 | 修复能否继续抬高重心，还是再次冲高回落 |
| 震荡或二波候选 | 板块下轨是否守住、核心是否横盘而非持续下移、是否出现新载体 | 蓄势、残余人气反抽或二波候选 | 是否重新突破平台并恢复板块联动 |
| 退潮日 | 核心、容量、助攻和低位扩散是否连续失效，新主流是否接替 | 原主流降级或结束 | 是否仅有反抽，还是出现真正的新一轮主动修复 |

每一天的输出都要保存，第二天只能基于前一天留下的验证任务更新状态。这样，“历史主流”就是逐日推演结果，不是向接口索要的静态标签。

### 2. 判断主流必须回答五个问题

1. 这个方向是否至少经历过启动日、次日延续和后续分歧？
2. 是否同时存在前排高度、容量核心和扩散层？
3. 板块指数是否连续走强或突破？
4. 大分歧以后，核心和容量股能否率先修复？
5. 原核心受到监管、异动或高度限制时，内部是否出现新的承接载体？

只有单只股票上涨，或者只有一天涨停很多，最多只能叫热点候选。

### 3. 催化如何使用

roubing 偏好以前没有出现、仍在发酵、政策或产业不断产生新信息的题材。当前实现先读取同花顺涨停原因，把同一交易理由的股票聚成方向，再观察资金是否持续选择。

但催化只能决定研究方向，不能直接决定买点。分析时必须写清楚：

- 是事件、政策、产业还是业绩催化；
- 已经发生了什么；
- 可能影响几天、几周还是更长时间；
- 同一涨停原因是首次出现、继续扩散还是开始重复兑现；
- 哪些股票只是蹭同一关键词，哪些真正得到资金选择。

不能因为故事听起来很大，就直接认定它是主流。

### 4. 三日确认怎样使用

作者旧帖给过一个三日案例：

- 第一天出现先锋、容量中军和约十家涨停；
- 第二天前排继续连板，中军继续上涨，后排没有明显负反馈；
- 第三天先锋继续强，中军继续放量，板块指数继续收阳。

这组数字来自 2024-06-07 的具体表达，可以作为强主流的检查模板。它的稳定逻辑是“先锋延续、容量继续、后排不出现明显负反馈、板块指数放量走强”；三天、十家涨停和成交排名不能跨市场环境机械套用。

2024-06-21 对弱主流给出了更完整的状态迁移：第一天消息刺激、竞价强、直线板与容量上影试盘；第二天先锋必须连板、容量必须放量反包，否则按一日游处理；第三天若先锋大单一字但指数仍不共振，确认的是弱主流；第四天再从换手连板、强趋势、区间涨幅、人气和成交中确定人气核心，等核心分歧而不是追后排。

### 5. 什么叫超级主流

超级主流不是单纯涨幅更大，而是经过多轮压力测试以后，资金仍然回到同一个方向：

- 多次分歧后还能弱转强；
- 容量核心持续承接；
- 原核心受限时，内部可以切换载体；
- 每轮修复仍能给参与者利润。

2025 年末商业航天案例里，作者把多次分歧弱转强作为超级主流的验证链：第一次看萌芽，第二次看强化，第三次看巩固，第四次才确认穿越能力。这里不能机械规定必须四次，但必须保存每一次分歧前后的板块指数、核心、容量、梯队和次日溢价；只有修复仍在同一方向内部完成，才算穿越能力在增强。

不能因为“已经经历第四次分歧”，就机械认定它一定是超级主流；如果修复高点降低、容量滞涨、助攻失去溢价，次数再多也可能是衰竭。

## 五、T 日盘后第三步：确定当前节点

节点的意思是：原来阻挡资金继续前进的东西，是否发生了变化。

节点不是日期，也不是看到一根特殊 K 线就随便命名。

### 常见节点及确认方法

| 节点 | 盘后先找什么 | 次日怎样确认 | 什么情况取消 |
| --- | --- | --- | --- |
| 主流确认 | 板块指数、先锋和容量股共同转强 | 板块连续走强，先锋和容量不是孤立上涨 | 只有小票脉冲，板块和容量不跟 |
| 大分歧修复 | 板块已经分歧，但仍有核心维持热度 | 次日板块止跌或反包，核心率先修复 | 核心不能修复，后排继续大跌 |
| 突破 | 平台、前高、阴线高点等明确压力 | 放量越过并站稳，或回踩不破后再次向上 | 只短暂刺穿，随后重新跌回压力位下方 |
| 唯一性确认 | 先确定起算日和真正的竞争组 | 经过高度、涨幅、容量、竞价和主动性比较后，只有一个有效载体 | 新对手胜出，或原候选次日没有完成任务 |
| 强弱切换 | 旧核心功能减弱，新候选进入同一竞争组 | 新候选先主动上涨并带动板块 | 新候选只是被旧核心或其他强股带起来 |
| 高低切换 | 高位股受监管、空间限制或明显走弱 | 对应时间出现低位题材、首板或容量股主动走强 | 只是任意一只低位股上涨，没有对应关系 |
| 二波 | 首轮上涨有地位，调整时结构没有破坏 | 再次突破平台，并得到板块或容量支持 | 普通旧股只靠人气反抽，板块没有响应 |
| 超卖修复 | 指数出现超卖、底背离、下影线等止跌候选 | 指数停止杀跌，新题材或核心率先走强并延续 | 指数继续创新低，只因为跌得多就抄底 |

顶部或兑现节点不能只靠一个指标判断，要结合高位推进失败、修复衰减、助攻走弱和角色被替代。

## 六、T 日盘后第四步：画出方向内部的角色图

角色不是股票的永久身份，而是它当前必须为板块完成的任务。

### 1. 主要角色

#### 总核心或总龙

任务：组织整个方向、打开空间，并成为其他资金无法绕开的对象。

确认顺序：先在板块无序或旧核心退潮时走出持续性；再突破旧高度、旧趋势或原来的空间压制；随后能够带动中军、助攻和后排，而不是孤立上涨；板块分歧以后还能率先修复并继续给参与资金溢价。

失效：高位放量滞涨、不再带动板块、修复速度落后、助攻批量走弱，或者新核心已经主动接替。

#### 情绪核心或高度核心

任务：打开连板高度和短线风险偏好。

确认：突破此前的连板压制，最好不是全程无法成交的一字堆高；打开后经过换手仍能站住，次日继续给参与者溢价，证明新的连板赚钱空间得到市场接受。

失效：只靠连续一字板堆高，打开后无法换手续强，或者被新的高标替代。

#### 容量核心

任务：承接大资金，稳定板块的价格重心。

确认顺序：它先要代表板块核心逻辑；成交规模和流动性足以容纳大资金；启动或修复时能够带动板块；经历一次或两次大分歧后仍能快速走强；它的强弱会明显影响板块重心和市场情绪。

失效：只有巨额成交却不再上涨，板块修复时它明显落后，价格重心持续下移。

关于容量股的成交额，作者不同文章出现过 10 亿、30 亿、成交排名前十或前五十等不同口径。因此不能使用一个固定金额。真正稳定的共同点是：成交规模较大、容易进出、能够带动板块、分歧后仍有承接。

#### 分支核心

任务：负责主线内部某个细分方向。

确认：在自己的细分里领涨或承担容量，同时与总方向保持同步。

失效：只有单只股票脉冲，所属细分方向没有响应。

#### 助攻或伴飞

任务：扩大总核心的赚钱效应，形成中间梯队或低位扩散。

确认：在总核心破局、情绪转折或二波启动附近出现；不是单纯同题材，而是自身能够连板、反包或形成中间梯队，并把总核心的赚钱效应向外扩散。

失效：次日没有溢价、竞争失败、不能继续帮助板块扩散。2024-07-31 大众交通案例给出了明确锚定法：龙头加速阶段同步观察最佳助攻；助攻未延续前一日惯性或全部断板，龙头便失去支撑，进入边打边撤甚至全部退出阶段。

#### 补涨和低位伴生

补涨通常从总龙断板日出现的低位首板中寻找。盘后回看断板当天的首板池，优先保留实体涨停、分时直线拉板、所属题材仍有支撑的候选；次日再比较竞价强度、板上换手和谁先完成晋级。

低位伴生通常从总龙二波第一次明显分歧或停顿时出现的低位首板中寻找，用来判断高位溢出资金是否仍愿意向低位扩散、延长周期。

这些股票不能只凭出现日期就确认，还要继续比较竞价、换手、板块地位和次日持续性。

#### 旧核心的残余人气

旧核心结束后仍可能反抽，甚至再次出现二波候选。

关键区别是主动性：如果它能够主动突破并带动板块，才可能重新升级；如果它只在新核心涨停以后被带起来，更像残余人气反抽。

#### 跟风股

跟风股没有独立带动能力、容量价值或阶段唯一性，只是在核心上涨时被动受益。

主线分歧时，跟风股通常最先失去溢价和流动性。

### 2. 角色不是名单，而是一条演化链

早期帖子给出的角色演化比字母标签更可执行：

1. **情绪转折龙**：旧周期退潮后，突破旧高度或从恐慌中率先反包，负责打开新情绪；
2. **低位伴飞龙**：转折龙形成时同步出现的低位首板，后续通过换手和晋级证明自己；
3. **二波龙**：第一波已有地位，调整后结构未坏，再次主动突破并恢复带动；
4. **补涨龙**：总龙断板日出现的低位首板，靠首板力度、次日竞价和后续竞争胜出；
5. **低位伴生龙**：二波第一次分歧或停顿时出现，承接高位溢出资金并延长周期；
6. **容量核心**：贯穿其中的大资金载体，负责稳定板块重心并验证真实承接。

AI 每天应判断股票当前处于哪一个功能阶段，并写明它通过什么事件进入、又会因什么事件退出。不能把“龙头”“中军”“补涨”永久贴在股票名称上。

### 3. 字母载体和核心、容量、伴飞、补涨是什么关系

这里要把两套容易混在一起的角色系统分开。

第一套是**功能角色**：总核心、容量核心、情绪核心、助攻或伴飞、补涨、低位伴生、二波载体。它回答“这只股票现在为板块完成什么任务”。前面 2023—2025 年帖子已经给出这些角色的出现时间、竞争方式和失效条件。

第二套是 2026 年文章里偶尔出现的**字母载体**：A、B、D。它看起来是在描述总核心周围不同阶段或不同重要程度的承接层，但现有抓取正文没有给出完整字典。

#### 原文能够直接确认的关系

| 字母 | 原文案例 | 作者直接说明的功能 | 可以确认什么 |
| --- | --- | --- | --- |
| A | 百花医药 | “哈药股份二波主升中的连板助攻核心”，并称“医药行情中间梯队核心” | A 可以是总龙二波阶段的重要连板助攻或中段核心，但它不是总龙本身 |
| A | 万向德农 | 金健米业作为总核心时，万向德农以一字连板进行助攻 | A 也可以表现为强助攻载体，不要求它是容量股 |
| B | 汉森制药 | 哈药横盘后，板块内部出现强势连板主升，“对板块总龙头的最好助攻” | B 也是围绕总龙运行的强势连板助攻，并非容量核心的同义词 |
| D | 2026-09-05 对哈药周期的总结 | 原有载体提前结束，未出现 D 级载体给受监管约束的高位核心“继续续命” | D 明确偏向周期后段的续命承接层；原文没有点名具体股票，也没有直接写成补涨龙或低位伴生龙 |
| C | 当前抓取语料未见 | 无 | 不能补定义 |

#### 对“核心、容量、补涨、伴飞、二波伴生”的逐项判断

| 功能角色 | 能否直接等同某个字母 | 证据结论 |
| --- | --- | --- |
| 总核心或总龙 | 不能等同 A | 哈药、金健米业在同一篇中被单独称为总核心，而 A 级百花、万向是它们的助攻载体 |
| 容量核心或中军 | 不能等同 B | B 级汉森的原文特征是强势连板助攻；作者另用“中军”描述稳住板块重心的容量角色 |
| 助攻或伴飞 | 与 A、B 都有明确功能重叠 | A、B 的三个案例都在帮助总核心扩散赚钱效应；但为什么一个叫 A、另一个叫 B，原文没有给稳定判别式 |
| 补涨龙 | 可能与后段字母载体发生重叠，但不能写成 C 或 D 的固定等号 | 早期帖子给了“总龙断板日低位首板”的补涨选法；字母帖子没有把它直接命名为某一级 |
| 低位伴生龙 | 与 D 的“续命”功能最接近，但仍不是作者明示等号 | 低位伴生出现在二波第一次分歧或停顿附近，功能上能承接高位溢出；D 只明确了后段续命，没有给出现时点和选股规则 |
| 二波载体 | A 案例发生在总龙二波阶段，但 A 不等于二波龙 | 百花是“哈药二波主升中的连板助攻核心”，二波主体仍是哈药 |

所以，你的记忆里把它们联系到核心、容量、补涨、伴飞和二波伴生，是有来源的：这些确实都属于一轮周期里的不同资金载体。但现有原文支持的是“功能有重叠”，不支持“每个功能固定对应一个字母”。尤其是：

1. **总龙独立于字母载体。** 字母载体围绕总龙承接、助攻或续命。
2. **A 和 B 都落在广义助攻、中段承接这一层。** 当前证据不足以稳定区分二者。
3. **D 最接近后段续命层。** 它可能表现成低位补涨、低位伴生或新的承接核心，但这些是可能形态，不是 D 的完整定义。
4. **C 级仍未在已抓取正文中出现。** 不能为了凑齐四级而自行填入“容量”或“补涨”。

一个可以保留、但不能投入自动决策的待验证假设是：A、B、C、D 更像围绕总龙随周期推进而变化的阶段载体层，而不是“总龙、容量、补涨、伴飞”的一一对应表。现有案例只足以观察到 A/B 的中段助攻和 D 的后段续命，尚不能确定完整顺序。

#### AI 实际怎样使用

1. 先按可观察事实确定功能角色：总龙、容量、助攻、补涨、低位伴生或跟风。
2. 历史案例中作者明确写过 A、B、D 时，原样保留标签和原文日期。
3. 分析新股票时，`字母级别` 默认写“未判定”，不能按主观强弱自动分 A、B、C、D。
4. 即使字母级别无法判断，功能角色仍必须继续判断；不能因为不知道 C 级就停止角色、竞争和次日预期分析。
5. 后续如果在遗漏图片、评论或新帖子中找到完整定义，再以原文补充字典，并重新验证是否适用于所有周期。

### 4. 角色图必须包含什么

| 股票 | 当前角色 | 为什么是这个角色 | 真正竞争对手 | 明天必须完成什么 | 什么情况说明角色失效 |
| --- | --- | --- | --- | --- | --- |

每天都要检查角色是否迁移：

- 旧核心先弱，新候选主动走强并带动板块，可能是角色切换；
- 新旧核心一起弱，更接近整个板块退潮；
- 新候选在别人走强后才上涨，更接近被动跟随。

## 七、T 日盘后第五步：建立真正的竞争组

不能把所有热门股票放在一起排名。

只有以下条件相近的股票，才适合直接比较：

- 连板身位相同或接近；
- 属于同一板块；
- 承担相同功能；
- 成交规模和资金类型相近；
- 起算节点相同，例如同一板块启动日、同一旧龙断板日或同一指数止跌日。

### 1. 比较顺序

1. 先规定从哪一天开始比较；
2. 确定候选池；
3. 比较换手高度和区间涨幅；
4. 比较成交容量、流动性和板块带动性；
5. 比较题材映射以及监管、异动的剩余空间；
6. 比较竞价和盘中谁先主动、谁被谁反推；
7. 次日继续检查胜出者有没有完成角色任务。

所谓“唯一性”，是当前阶段竞争后的结果，不等于永久地位，也不等于最高板、涨幅第一或人气第一。

出现新的强对手、监管空间收窄、板块带动消失，或者次日没有完成任务，原来的唯一性就要取消。

### 2. 原帖已经给出的四种竞争方式

#### 同一起算日的区间竞争

先固定明确的启动日，再比较从该日到当前的累计涨幅、换手高度和持续性。2025-03-15、2025-03-20 和 2025-12-13 都使用过这种方法：启动首日通常无法确定最终核心，运行数日后才比较谁仍然保持涨停、谁区间最强、谁能在震荡后重新转强。

确认：区间领先者次日继续转强，并保持板块带动或唯一容量。

取消：区间第一只是左侧涨幅领先，尚未突破；或者新的对手在同一节点中完成更强的主动突破。

#### 同身位晋级竞争

比较同板块或同周期的二板、三板、换手板。不是谁先被列入股票池谁就赢，而是看首板力度、次日竞价、换手质量、谁先完成上板以及板块逻辑是否仍有效。

2023-12-10 的补涨案例明确使用“总龙断板日首板池 → 选实体直线板 → 次日竞价一字或强开 → 板上分歧继续比较”的顺序。

#### 容量核心竞争

容量股不能与小票只比涨幅。应比较谁先主动进攻、谁带动板块、谁在大分歧后仍能反包，以及谁的流动性能够持续容纳资金。

2025-01-16 的五洲新春案例说明：竞价高开只表示态度，必须等分时与指数反弹同步、随后上板并带动机器人板块，容量核心才得到确认。

#### 旧核心与新核心竞争

关键不是两者最后都涨了多少，而是事件顺序：

1. 谁先转强；
2. 谁先突破或上板；
3. 谁带动板块和另一只股票；
4. 谁必须等对方走强后才被反推；
5. 次日谁继续获得更强反馈。

2025-08-19 的恒宝股份与长城证券案例里，恒宝先高开反杀，长城证券拉板后恒宝才被反推上涨。即使恒宝盘中涨幅不小，也属于旧核心失去主动性后的残余人气反抽。

### 3. 卡位不是一次价格超过

“卡位”至少需要同时回答：

- 两只股票原本为什么是竞争关系；
- 新候选在竞价、上板或区间强度上超过了什么；
- 超过以后是否独立保持强势；
- 原候选是否因此失去唯一性或角色任务；
- 下一交易日市场是否继续承认新的排序。

2025-11-22 榕基软件案例能确认的是：它先经历炸板回封，次日竞价强度超过浪潮软件，随后在大冰点中回打后快速上板并分离其他旧核心。完整结论来自连续两天的竞争结果，不是只凭一次竞价涨幅。

## 八、T 日盘后第六步：给每只股票写次日预期

这里的“次日预期”，指的是：根据今天的状态和角色，明天本来应该怎样表现。

这不是 roubing 的固定术语，而是为了把她分散在帖子里的判断方式统一整理出来。

### 1. 先记录今天是什么状态

至少记录：

- 今天是一字板、秒板、换手板、爆量烂板、冲高回落、跌停，还是第一次明显分歧；
- 当前承担什么角色；
- 真正的同组竞争对手是谁；
- 板块和指数处于什么环境；
- 当前涨停、监管和异动规则是什么。

### 2. 次日必须进行三组比较

#### 和自己昨天比较

昨天很强，今天是否维持了与其强度相称的表现？

#### 和同组对手比较

谁竞价更强、谁先上板、谁主动排名上升、谁是在别人上涨以后才被带动？

#### 和板块环境比较

弱环境中仍保持强势，属于相对强；板块修复时核心明显落后，属于不符合角色要求。

### 3. 每只候选必须写清楚

| 项目 | 必须填写的内容 |
| --- | --- |
| 当前角色 | 它现在为板块完成什么任务 |
| 今日状态 | 一字、换手、烂板、冲高回落、分歧等 |
| 竞价预期 | 明天竞价至少应表现成什么样 |
| 开盘预期 | 第一轮卖压后应该怎样 |
| 板块配合 | 板块指数、容量股和助攻应该怎样响应 |
| 角色任务 | 明天必须完成什么，才能保留地位 |
| 最低确认 | 看到什么才允许继续观察或行动 |
| 直接取消 | 出现什么就证明原判断错误 |

作者在个别案例中给过高开 7%、封单 10 万手、20 万手等数字，但没有一个能够从“昨日强度”统一换算“次日应该高开多少”的公式。

这些数字只能留在原案例里，不能复制给其他股票。

### 4. 原帖可以直接提炼出的次日预期映射

| T 日事实 | T+1 日应完成的任务 | 确认 | 取消或降级 |
| --- | --- | --- | --- |
| 弱主流第一天出现直线先锋和容量试盘 | 先锋继续晋级，容量放量反包或继续大阳 | 前排、容量和板块共同增强 | 先锋断板且容量不反包，按一日游处理 |
| 板块分歧日某股主动进攻最强 | 次日仍应强于同组第二名 | 竞价、上板或带动继续领先 | 竞价已经弱于昨日第二名，原主动地位失效 |
| 换手核心在板块大爆发日涨停 | 次日应延续并争取连板 | 放量强开、承接后继续上攻 | 小幅低开且不能快速转强，反抽用于处理 |
| 前一日一字板或极强加速 | 次日强度必须与昨日惯性相称 | 继续大单强开，或分歧后迅速重新封住 | 封单显著衰减、最终不能按角色开盘，属于不及预期 |
| 主升核心第一次突破后放量分歧 | 次日应出现竞价或开盘弱转强 | 收回卖压、摸板或继续连板 | 压力位下分歧、无法收回、未完成至少摸板等角色任务 |
| 前日冲板回落但属于外部环境拖累 | 市场修复时应率先反包 | 竞价放量高开，或低开后快速拉红并带动板块 | 市场修复而它仍落后，说明“被动回落”假设不成立 |
| 恐慌日抗跌或逆势涨停 | 指数企稳时应率先主动进攻 | 快速翻红、突破分时均线、带动同组 | 仅随指数被动反抽，或重新跌回弱势 |
| 板块前一日大涨，核心本应领涨 | 次日核心继续稳住或加速 | 核心涨幅、上板和带动领先后排 | 核心小幅高开后冲高回落、涨幅落后跟风，属于该涨不涨 |
| 二波启动后本应一鼓作气 | 次日继续摸板、连板或至少保持主动 | 继续推进并保持同组第一 | 尾盘炸板、次日被新核心卡位，二波预期降级 |
| 超跌反弹中的日内领涨股 | 主要看隔日溢价，不先假定长周期 | 次日继续超预期才延长观察 | 次日上涨无力即结束，不把反弹当反转 |

这些映射的核心不是固定高开百分比，而是“角色与前一日强度决定次日任务”。同样是高开三个点，对普通跟风可能不弱，对前一日大单一字的核心却可能严重不及预期。

### 5. 怎样从前一日强度生成个股自己的标尺

对每只股票，按下面顺序写预期：

1. **先看 T 日角色。** 总核心要带动，容量核心要承接并稳定重心，助攻要继续扩散，补涨要晋级；
2. **再看 T 日表现。** 一字、缩量加速、换手板、烂板、冲高回落和第一次分歧，对次日要求不同；
3. **再看 T 日板块状态。** 板块高潮后的核心要求高于板块分歧日抗跌股；
4. **再看同组第二名。** 前一天最主动者，次日不能无解释地落后于原第二名；
5. **最后看监管和剩余空间。** 本应加速但临近有效监管边界时，要区分绕异动、主动突破和兑现，而不是只看开盘涨幅。

输出必须是自然语言任务，例如：“它是昨日核电分歧中主动性最强的容量股，因此明天竞价至少不能弱于尚纬股份，开盘后还应继续率先上攻；若竞价已经落后，则原角色取消。”不能只输出“预期分数 82”。

### 6. 盘后必须保留三条路径

#### 主路径

当前最可能继续得到资金选择的方向，以及它明天必须出现的确认。

#### 替代路径

如果主路径失败，哪个方向或哪只新核心可能接替，以及它怎样才算真正胜出。

#### 空仓路径

什么情况下不行动，什么时候才重新开始观察。

## 九、T+1 日竞价：只验证计划，不临时发明计划

竞价的任务不是重新选股，而是检查盘后写好的预期有没有被确认。

### 1. 数据完整时的观察顺序

1. 9:15：记录初始封单、委托规模和同组初始排名；
2. 9:20：记录撤单、加强、转弱和排名变化；
3. 9:25：记录最终开盘、最终排名和板块前排结构；
4. 判断前排是否集中在同一方向，还是只有一只股票孤立强势；
5. 检查旧核心、容量股和同组对手是否支持盘后主路径；
6. 判断这只股票是否完成了它的角色任务，而不是只看高开百分比。

需要特别注意：完整的 9:15、9:20、9:25 排名迁移，在现有资料中只在 2026-08-01 的图片案例里明确出现。可以把三个时间点作为数据记录框架，但不能说这是作者多年固定使用的公式。

### 2. 竞价重点判断四件事

#### 初始强度有没有保留下来

初始封单很强，但大量撤单以后最终开盘明显变弱，说明初始展示没有转化成真实强度。

#### 同组排名有没有变化

原本排名靠后的候选不断加强，旧候选不断转弱，说明资金可能正在换目标。

#### 是否假强真弱

初始看起来大单封死，最终却不能按照它的角色开盘；或者最终封单远弱于昨日惯性，都要降低原判断。

#### 高开是否已经透支

高开越多，不一定越好。还要结合涨停空间、监管限制、昨日强度和是否能够实际成交。

作者没有给出一个适用于所有股票的“高开超过多少就透支”的百分比。

### 3. 竞价结束后的结论只能是

- 原路径保留；
- 原路径降级；
- 原路径取消；
- 数据不足，无法判断。

如果盘前没有写预期，看到竞价以后不能补写“它本来就应该这样”。

## 十、开盘后五分钟：检查竞价强度是否经得住卖压

竞价只能生成候选。开盘后还要观察真实成交、卖压、承接和板块响应。

### 1. 固定观察顺序

1. 第一轮卖压从哪里来；
2. 股票是否快速拉红、低点抬高、站回分时均线，或守住昨日低点和突破平台；
3. 承接以后是否继续主动向上，而不是只出现一笔直线拉升；
4. 板块指数、容量核心和同组股票是否同步响应；
5. 股票是否完成盘前写下的角色任务；
6. 如果竞价强但开盘五分钟无法延续，取消竞价强势结论。

### 2. 什么叫承接

不能只写“承接很好”，必须描述具体行为，例如：

- 低开后快速拉红；
- 下探以后低点逐步抬高；
- 回踩平台、昨日低点或关键支撑没有跌破；
- 放量重新站回分时均线；
- 炸板后仍有持续成交，随后重新封住涨停。

### 3. 什么叫弱转强

至少要满足：

1. 前一天确实处于弱势或分歧状态；
2. 次日竞价或开盘没有继续原来的弱势；
3. 第一轮卖压出现以后能够收回；
4. 收回以后继续主动推进；
5. 表现强于同组竞争者；
6. 最好得到板块或容量股响应；
7. 开盘后不能很快重新跌回原弱势状态。

只高开、只翻红或只拉一笔，都不能单独确认弱转强。

### 4. 主动和被动怎样判断

主动与被动不是看收盘涨跌，而是还原资金行为的先后关系。

#### 主动进攻

观察顺序：

1. 指数或板块是否仍在下跌、震荡或尚未修复；
2. 目标股票是否先停止跟跌；
3. 是否出现连续大单向上、低点抬高、率先翻红、突破或上板；
4. 它上涨以后，板块指数、同组股票或市场情绪是否跟随改善。

确认：目标先动，随后带动别人。2025-01-09 文章中的利欧股份，就是指数形成分时底背离时不再跟跌，随后大单主动进攻，上板后带动指数和算力板块回升。

取消：板块或其他核心已经先涨，目标只是在后面跟随；或者只有一笔脉冲，没有持续成交和后续带动。

#### 被动回落、被动分歧或被动炸板

观察顺序：先检查指数和板块是否已经广泛分歧，再看目标是否随后被拖下；同时检查它原来的结构和角色是否仍在。

确认候选：外部环境先弱，目标后弱；目标并非本组最先兑现；次日环境修复时，它能率先反包或弱转强。2025-01-24 文章中的汉得信息、2024-12-07 文章中的利欧股份、2026-05-23 文章中的红板科技，都属于作者用这种关系解释的案例。

取消：板块修复时目标仍落后、关键结构破坏、次日不能收回，则不能继续用“被动”替它辩护。

#### 被动反抽

更强的竞争对手先转强或拉板，旧核心随后才被反推上涨。即使旧核心盘中涨幅不小，只要它已经失去领涨和带动，就属于角色降级后的反抽候选。2025-08-19 恒宝股份是明确案例。

#### 主动分歧

作者明确使用过两种语境：

- 核心已经突破并处在上升中，第一次出现放量分歧；
- 临界爆发前，竞价主动给出可承接的分歧，随后快速拉红。

它不是“自己故意下跌”的意思，而是作者对特定主升位置和可交易分歧的命名。压力位下尚未突破的分歧不属于这一类。

#### “主动炸板”仍只能保留为案例标签

2025-11-22 只写到榕基软件 11 月 19 日“主动炸板回封”，次日竞价卡掉浪潮软件；抓取到的正文和评论没有解释为什么该次炸板叫“主动”，也没有给出统一的订单变化、时间顺序或成交阈值。全文其他帖子不足以把它扩展成通用算法。

因此系统可以判断主动进攻、被动回落和被动反抽，也可以按位置识别作者所说的主动分歧；但遇到“主动炸板”必须列出原始事件顺序，只能标“与榕基软件案例相似”或“无法确认”，不能自行发明定义。

## 十一、什么时候可以采取动作

任何动作都必须建立在环境、主流、节点、角色和次日预期已经完成的基础上。形态本身不能自动产生买点。

### 1. 低吸候选

前提：已经确认主流、核心或关键节点，不能只因为跌幅大就低吸。

确认过程：

1. 回踩昨日低点、分时低点、五日线或刚突破的平台；
2. 价格不再继续下破；
3. 出现拐头、翻红、低点抬高或重新站回关键位置；
4. 板块和角色仍然有效。

没有停止下跌和向上拐头，只是在接下跌，不叫低吸。

### 2. 半路候选

前提：盘前已经标记了明确的前高、平台、阴线高点或其他阻力。

确认：开盘后放量越过阻力，能够站稳并继续主动向上，同时获得板块或同组支持。

取消：只有瞬间直线拉升，突破后立即回落，板块和容量股都不响应。

### 3. 开板分歧和回封候选

前提：板块、角色和第一次上板力度已经成立。

确认：开板后出现真实换手和承接，随后重新封住。

取消：反复开板、角色已经落后、板块不支持，或者炸板后无法重新封住。

不能因为主观认为这是“被动炸板”，就跳过承接和回封确认。

### 4. 尾盘确认候选

作者会用尾盘确认异动是否触发、板块分歧是否回流、突破能否保持，但没有统一的尾盘时间和成交要求。

所以使用尾盘确认时，必须写清楚自己具体在等什么，不能形成“固定几点以后买”的规则。

### 5. 不行动

以下情况直接不行动：

- 环境、主流或节点无法确认；
- 只有个股上涨，板块和容量不响应；
- 竞价很强，但开盘承接消失；
- 旧核心和新候选一起走弱；
- 缺少关键竞价、分时或同组数据；
- 无法写出动作的取消条件。

## 十二、买入以后怎样持有

持有不是停止判断，而是持续检查股票是否仍然完成自己的角色任务。

每天检查：

| 检查对象 | 继续持有需要看到什么 | 风险信号 |
| --- | --- | --- |
| 总核心 | 继续领涨、率先修复、带动板块和助攻 | 不再带动，修复落后 |
| 容量核心 | 大成交后仍能推进，回踩能收回，板块修复时同步 | 只有成交额大，价格却不再推进 |
| 助攻和低位扩散 | 次日有溢价，梯队能够延续，还有新载体接棒 | 助攻批量失去溢价，没有新载体 |
| 监管和异动 | 当前规则下仍有空间，市场愿意承接 | 弱周期触及限制，板块又没有替代载体 |
| 修复质量 | 每次修复仍能抬高价格、改善上板质量并带动板块 | 修复高点越来越低，响应越来越少，该强时不强 |

“下一批资金够不够”不是外部接口字段，而是用赚钱反馈逐日推演：

1. **先看昨日买方。** 昨日涨停、半路和回封资金次日能否带着利润离开；如果强板普遍低开、核按钮或无溢价，说明接力意愿下降。
2. **再看助攻。** 最佳助攻能否延续前一日惯性；助攻仍是一字、连板或强反包时，总核心通常仍有外部支撑。
3. **再看梯队。** 高位、中位、容量和低位是否都有载体，还是只剩一只高位股孤立上涨。
4. **再看分歧后的接手。** 开板、下探或板块回落后，是否有真实成交把价格重新推回，能否形成反包或回封。
5. **最后看扩散。** 核心上涨以后，同题材涨停原因是否继续增加，后排是否获得次日溢价，而不是只在当日跟涨。

输出不写“资金足够”这种空话，而写成：昨日买方反馈改善或恶化、最佳助攻是否延续、梯队是否新增、分歧是否被接住、扩散是否有次日奖励。五项共同决定继续、降级或结束当前路径，但不使用固定打分。

## 十三、什么时候退出

退出不等待某一个万能技术指标，而是看原先成立的条件在哪一层失效。

### 1. 该强不强

本来应该高开、摸板、承接、带动板块或给助攻溢价，却没有完成。

处理：利用冲高、反抽或分时修复降低风险，不必等固定均线破位。

### 2. 角色被替代

新核心先主动领涨，旧核心只能被动跟随；或者旧核心原有的唯一性消失。

处理：旧核心降级。后续残余人气反抽更偏向退出机会，而不是自动重新买入。

### 3. 板块秩序同时恶化

核心、容量、助攻和低位扩散同时出现问题，说明板块退潮风险明显上升。

作者没有给出“失效两项减仓、失效三项清仓”这样的固定计数器，不能自己编造。

### 4. 高位推进失败

高位放量却不再上涨、涨停封不住、助攻同步走弱、反抽不能创新高。

这些现象组合起来，说明继续上行的任务可能已经失败。

### 5. 结构被破坏

平台、趋势重心或关键均线被有效跌破。

但作者对五日线的使用存在两种口径：

- 一部分文章把五日线当作主升结构的生命线；
- 另一些案例认为，当板块、角色和高位风险已经共同恶化时，应在跌破五日线以前处理。

因此，五日线只能作为结构参考，不能成为唯一退出规则。采用左侧还是右侧处理，必须在交易前写清楚，不能事后切换。

### 6. 逻辑、监管或环境失效

- 催化已经兑现或事实被证伪；
- 异动和监管空间不足，板块内部又没有新载体；
- 市场从主升转为震荡，或从震荡转为快速下跌。

出现这些变化时，持有周期要同步缩短，原路径应降级或取消。

### 7. 收盘后必须独立重算

每天收盘后重新回答：

1. 今天这只股票是否真正完成角色任务？
2. 板块秩序是增强还是减弱？
3. 今天参与的资金是否有利润安全垫？
4. 明天还有没有新的接棒载体？
5. 监管、公告和外部风险是否改变了路径？
6. 假设现在空仓，明天还会不会把它列为优先候选？

最后一个问题用于减少持仓成本和个人情绪对判断的影响，是研究整理时增加的纪律，不是作者固定原话。

## 十四、容易误解的核心概念

### 1. 反人性

反人性不是机械逆势，也不是跌了就买。

必须同时存在：

- 市场大多数人的惯性预期；
- 与惯性预期相反的真实行为；
- 原来的逻辑、角色或关键结构没有破坏；
- 卖压释放以后出现资金确认。

恐慌中必须先看到停止下跌和主动修复；高潮中要观察该强不强、推进失败和后续买家不足。

### 2. 分歧

分歧本身不是买点，要从三个角度分类：

- 发生位置：突破后第一次分歧、压力位下分歧，还是高位推进失败；
- 外部关系：板块和指数先弱，还是这只股票自己先弱；
- 后续反馈：次日率先修复、只有反抽，还是继续走弱。

只有结构没有破坏，并且后续出现修复，才进入动作候选。

### 3. 唯一性

唯一性是某个阶段、某个竞争组里的胜出结果。必须说明起算日、候选池、比较维度和失效条件。

最高板、成交最大或人气最高，都不能单独证明唯一性。

### 4. 共振

每次写共振，都必须列出到底是谁和谁同步：

- 指数、板块和个股；
- 板块指数、情绪核心和容量中军；
- 产业消息和技术突破；
- 市场恐慌和个股主动修复；
- 旧核心走弱和新核心接替。

只写“形成共振”而不列对象，等于没有分析。

### 5. 分离

必须先规定与谁比较。

指数、板块或旧核心先弱，新候选仍然独立保持强势并主动推进，才是分离候选。如果其他核心先拉板，它随后才上涨，更接近被动跟随。

### 6. 上升停顿

停顿只是等待分类的状态：

- 高位放量、价格推不动、板块高潮时核心反而落后，更偏向兑现；
- 第一轮上涨后缩量横盘、重心不下移、关键支撑不破，之后重新突破，更偏向二波蓄势。

不能看到十字星就直接定义为顶部或空中加油。

### 7. 巨量

低位第一次巨量可能代表充分换手；高位巨量但价格推不动，更偏向兑现风险。

作者没有给出适用于所有股票的“巨量倍数”。必须和这只股票自己的历史成交、当前位置和板块角色比较。

### 8. 洗盘和出货

作者会把缩量调整、关键支撑不破、次日重新突破的部分案例解释成洗盘。

但“主力正在吸筹、控盘、洗盘或出货”没有可独立验证的统一算法。

AI 应当只写看得见的事实：成交是否缩小、支撑是否跌破、次日是否重新突破、板块和角色是否修复。

### 9. 冰剑双战法

可以把它理解为同一套流程中的防守和进攻：

- 冰：识别风险、等待验证、预期失效或结构破坏时处理；
- 剑：主流确认、关键突破、弱转强、回封和半路跟随；
- 闭环：每次进攻以前，必须先写防守和退出条件。

### 10. 瓶底

瓶底用于形成中周期研究方向，关注产业周期、政策、估值、资金供需、筹码和业绩。

它不能直接生成短线买点。当前短线流程先用同花顺涨停原因识别市场正在交易的产业映射，再用板块、容量、节点、竞价和开盘反馈验证。是否具备长期产业价值属于另一项基本面核实任务，不作为本流程的 `BLOCK`。

## 十五、九类常见场景怎样使用

下面九类不是作者正式命名的九套战法，而是把跨帖案例按使用场景归纳到一起。它们只能帮助寻找相似案例，不能跳过前面的完整流程。

| 场景 | 需要什么前提 | 怎样确认 | 怎样取消 |
| --- | --- | --- | --- |
| 超级主流板块弱转强 | 已经形成多角色主流，随后出现板块级分歧 | 板块指数、核心和容量共同修复 | 只有一只小票反包 |
| 主流大分歧后转一致 | 分歧日仍有前排维持热度 | 次日板块止跌或反包，核心率先修复 | 后排继续大跌，核心无法修复 |
| 突破初期 | 盘前已有明确平台、前高或阻力 | 放量越过并站稳，最好有板块支持 | 突破后立即跌回 |
| 唯一性破局 | 旧高标或同身位竞争者受阻 | 候选通过换手、竞价卡位和次日持续性胜出 | 只是最高板，次日没有主动性 |
| 主流内部强弱切换 | 主线整体仍有效，旧载体功能下降 | 新载体先主动接替并带动板块 | 主线指数破位，新旧一起弱 |
| 二波 | 第一轮上涨有地位，调整结构没破坏 | 重新突破，并得到板块或容量支持 | 只有旧人气反抽 |
| 底部或超卖修复 | 指数超卖或底背离，跌速开始减缓 | 指数止跌，新题材或核心率先走强并延续 | 指数继续创新低 |
| 赚钱效应复制 | 已有前例展示了可解释的资金行为 | 新案例的环境、节点、角色和竞争关系相似 | 只有 K 线外形相似 |
| 高位兑现 | 高位一致、修复衰减、该涨不涨 | 背离、封单衰减、巨量滞涨和助攻走弱等组合出现 | 只有一个风险信号，随后又重新突破 |

使用相似案例时，必须回答：

1. 当前环境为什么相似？
2. 当前节点为什么相似？
3. 股票承担的角色为什么相似？
4. 竞争关系为什么相似？
5. 哪些关键条件不同？
6. 什么情况确认？
7. 什么情况取消？

## 十七、AI 绝对不能做的事情

- 使用“必然、随便买、百分之百、稳赚不亏、无风险”等表达；
- 用固定分数或“满足几项就买”替代具体环境；
- 把 A、B、D 的局部案例补成完整的 A、B、C、D 自动评级，或把总龙、容量、补涨、伴飞强行与字母一一绑定；
- 把主动和被动的局部案例补成适用于所有炸板的分类器；
- 把五日线、五周线、百分之七十等距、固定量能、成交额和封单额写成永久规则；
- 只展示成功案例，不记录同期失败候选和排除理由；
- 根据收盘结果倒推竞价封单、撤单和资金意图；
- 只看 K 线就断言主力正在吸筹、洗盘、控盘或出货；
- 把作者对公司、业绩和资金流的陈述，当作已经独立核实的事实。

以下情况必须明确回答“数据不足，无法判断”：

- 没有竞价快照，却要求判断 9:15 到 9:25 的封单和排名变化；
- 没有分时和事件顺序，却要求判断承接、回封、主动或被动；
- 要求从当前已抓取语料中补出尚未找到的 C 级和完整字母升级降级算法；
- 要求仅凭“主动炸板”四个字自动分类所有炸板；
- 某条旧文规则只存在于没有抓取到的图片中，又要求复原图片里的具体盘口数值。

真正属于系统 `BLOCK` 的只有历史竞价过程、历史盘口/委托队列和完整逐笔委托。主流、角色、竞争、预期和催化仍必须使用能够取得的日线、分钟、涨停原因和次日反馈继续推演，不能因为没有现成标签就停止分析。

## 十九、最后只记住这五句话

1. 先判断环境，再研究个股。
2. 先确认资金反复回到的方向，再给股票划分角色。
3. 没有盘后预期，就没有所谓强于预期或弱于预期。
4. 上涨不一定强，关键看它是主动带动别人，还是被别人带起来。
5. 每条路径都必须写取消条件；无法说明怎样证明自己错，就说明判断还不能执行。
