## 0. 本手册解决什么问题

本手册不是帖子摘要，也不是历史答案库。它要回答的是：

```text
每一步要看什么数据
→ 按什么顺序比较
→ 哪些事实支持什么状态
→ 哪些相似现象不能得出该结论
→ 下一步应该验证什么
→ 最终为什么选择、降级、替代或不行动
```

证据状态：

| 标记 | 含义 | 使用方式 |
| --- | --- | --- |
| `[S]` | 多篇原帖可以形成稳定观察程序 | 可以进入 AI 执行流程，但必须保留前提和取消条件 |
| `[K]` | 只有案例、局部定义或一次性数字 | 只能作为观察线索，不能生成通用阈值 |
| `[X]` | 作者不同文章口径冲突 | 只保留稳定交集，冲突部分必须显式输出 |
| `[R]` | 为防后验、幻觉和强行分类增加的工程纪律 | 必须执行，但不能冒充作者原话 |
| `[M]` | 交易所规则或外部可核验市场事实 | 使用时必须保存生效日期和正式来源，不归因于作者 |

## 1. 整套方法的真正主轴

roubing 的方法不是“先找涨得最好的股票”，而是先寻找市场正在形成的有序资金路径，再在路径的关键变化点选择承担特定任务的股票。

```text
冻结信息边界
→ 判断市场允许哪种持有和试错方式
→ 逐日判断哪个方向正在形成或维持资金秩序
→ 找到当前阻力发生变化的节点
→ 由节点产生候选池
→ 给股票分配功能角色
→ 只在真正可比的股票之间竞争
→ 根据今日前态写次日必须完成的任务
→ 保存主路径、替代路径和不行动路径
→ 用竞价验证预期
→ 用开盘卖压验证真实承接和主动性
→ 选择低吸、半路、回封、尾盘确认或不行动
→ 持续检查角色和板块秩序
→ 预期、角色、结构或环境失效时退出
→ 收盘后重新计算，不沿用持仓立场
```

每一步的输出都是下一步的前提。前一步没有确认，后一步不得跳过它直接选股。

## 2. Stage 0：冻结信息边界

### 2.1 这一阶段解决什么问题

先确定 AI 在当前时间真正知道什么，防止使用未来结果、作者历史答案或缺失盘口编造结论。

### 2.2 必须读取

1. `as_of`：盘后、09:25、09:35 或其他明确时点。
2. 当时已经存在的指数、板块、个股和事件事实。
3. 前一交易日已经冻结并通过审计的状态账本。
4. 当前数据覆盖：日线、涨跌停、竞价、分钟、成交、板块成员、公告和监管。
5. 当前使用的方法版本。

### 2.3 禁止读取

- roubing 原帖正文、帖子检索片段和作者历史结论；
- 当前时点之后的涨幅、涨停、收盘和最终赢家；
- 用今天的板块成分倒推过去；
- 用日 K 反推竞价撤单、分时承接和逐笔买卖意图；
- 用作者旧帖补齐缺失的逐日状态账本。

### 2.4 输出

```text
AVAILABLE：事实完整，可继续判断
PARTIAL：只能判断部分关系
BLOCKED：依赖的关键过程数据不存在
UNKNOWN：事实存在，但方法没有通用定义
```

### 2.5 下一步

只有市场环境所需的最低事实存在，才进入 Stage 1。缺少前一日账本时仍可做当日截面判断，但禁止输出“继续、延续、修复、切换完成”等跨日状态。

## 3. Stage 1：判断市场环境

### 3.1 这一阶段解决什么问题

环境判断不是为了给市场命名，而是决定：

- 是否允许行动；
- 允许研究核心还是只能研究短套利；
- 能否延长持有；
- 对失败信号需要多快响应；
- 后续主流判断需要多高的确认标准。

### 3.2 必须观察的数据

| 数据 | 要回答的问题 |
| --- | --- |
| 指数日线和分时路径 | 上升、区间震荡、止跌候选还是快速下跌 |
| 全市场成交及其历史位置 | 是否有足够流动性支持容量股持续活动；不设固定金额 |
| 涨停、跌停、炸板和连板结构 | 风险偏好是扩张还是收缩 |
| 昨日强势股今日反馈 | 昨日买方普遍获利、分化还是被核 |
| 大成交核心反馈 | 大资金载体是在推进、滞涨还是杀跌 |
| 赚钱效应分布 | 只集中在极少数核心，还是向助攻和后排扩散 |
| 亏钱效应传播 | 从后排开始，还是已经蔓延到核心和容量 |
| 旧方向与新方向 | 旧主流是否仍有承接，新方向是否在旧方向走弱时接管 |

`[K]` 作者没有给出赚钱效应、增量资金和市场成交的统一统计窗口与阈值。因此必须描述分布和相对变化，不能算一个固定环境分数。

### 3.3 固定观察顺序

1. 先看指数是否存在系统性快速下行。
2. 再看昨日强势股是否普遍有次日奖励。
3. 再看大成交股票是否仍能推进价格。
4. 再看赚钱效应由核心向外扩散，还是亏钱效应由后排向核心蔓延。
5. 最后看旧方向走弱时，有没有新方向主动承接。

成交额和涨跌家数只能作为背景，不能越过上述关系直接决定环境。

### 3.4 四种输出状态

#### A. `MAIN_TREND_CANDIDATE`：主流主升环境候选 `[S]`

支持链：

1. 指数没有系统性快速下行；
2. 至少一个方向跨日持续获得资金；
3. 该方向有先锋、容量和扩散层；
4. 分歧后核心能够率先修复；
5. 昨日参与者继续得到溢价；
6. 原核心受限或疲劳时，方向内部出现新载体接住资金。

不能这样确认：

- 只因当日上涨家数多；
- 只因涨停家数多；
- 只因某一只股票连续涨停；
- 只因某篇历史帖子说该方向是主流。

下一步：进入 Stage 2，判断具体方向处于启动、延续、主升、分歧还是修复。

#### B. `ROTATION`：轮动震荡 `[S]`

支持链：

1. 指数区间震荡；
2. 板块今天强、次日弱，持续性反复中断；
3. 没有稳定高度或没有容量持续推进；
4. 赚钱集中在极少数辨识度股票或很短的小周期；
5. 多个方向轮流脉冲，没有一个完成分歧后修复。

下一步：只允许节点清晰、角色明确的核心候选；默认缩短观察和持有，不追后排。

升级条件：某方向跨日增强、容量加入、分歧后修复并继续给买方奖励。

#### C. `DECLINE`：下跌或系统性风险 `[S]`

支持链：

1. 指数快速下行或沿短期趋势持续杀跌；
2. 强势股和指数同步放量杀跌；
3. 高标跌停后次日继续跌停；
4. 昨日强板普遍没有溢价；
5. 亏钱效应从后排向核心扩散。

下一步：默认不行动。只保留底部修复、明确分离或情绪转折候选，并要求次日确认。

降级结束条件：跌停不再连续扩散、指数停止杀跌、新方向和新核心连续得到确认。

#### D. `REGIME_SWITCH_UNCERTAIN`：新旧秩序切换但尚未确认 `[R]`

适用：旧方向功能衰减，新方向出现主动增强，但两者都没有完成最终确认。

必须同时保存：

- 旧方向修复路径；
- 新方向接替路径；
- 两边都失败的不行动路径。

不能因某只新股票单日最强，就宣布切换完成。

### 3.5 环境逐日迁移规则

每一天必须写“相对前一日发生了什么变化”：

```text
昨日买方反馈改善/恶化
→ 大成交核心推进/滞涨
→ 扩散增加/减少
→ 亏钱效应是否向核心传播
→ 新方向是否在旧方向走弱时主动接管
→ 环境状态维持、升级、降级或无法确认
```

缺少昨日状态时：只能输出“今日截面偏强、偏轮动或偏风险”，不能输出环境迁移。

## 4. Stage 2：识别方向并逐日确认主流

### 4.1 这一阶段解决什么问题

判断市场正在持续交易哪条资金路径，而不是统计今天哪个题材涨停最多。

### 4.2 方向怎样产生

1. 用当日涨停原因、公告和可核实催化形成初始方向。
2. 将同一交易理由的股票归组，同时保留一只股票的多个属性。
3. 区分首次出现、继续发酵、反复兑现和纯关键词蹭题材。
4. 检查方向内部是否同时出现先锋、容量、连板和扩散。
5. 与其他方向比较跨日资金反馈，不用单日数量直接定主流。

催化只能决定“值得研究什么”，不能直接生成买点。

### 4.3 每个方向必须维护的逐日状态

| 状态 | 当日可见事实 | 下一日必须验证 |
| --- | --- | --- |
| `RANDOM_HOTSPOT` 随机热点 | 只有个股或零散涨停，无方向结构 | 是否出现同原因扩散和前排延续 |
| `START_TRIAL` 启动试盘 | 新原因集中，出现直线先锋、容量试盘或板块转强 | 先锋能否晋级，容量能否反包或继续推进 |
| `CONTINUATION_CANDIDATE` 延续候选 | 先锋延续，容量继续，后排没有严重负反馈 | 是否形成完整梯队和板块连续性 |
| `WEAK_MAINSTREAM` 弱主流 | 方向连续但指数不共振，赚钱集中在少数核心 | 核心是否继续、分歧后能否修复 |
| `MAINSTREAM_CONFIRMED` 主流确认 | 前排、容量、扩散和板块指数跨日协同 | 第一次大分歧能否被接住 |
| `MAIN_UP` 主升 | 核心持续推进，容量承接，参与者持续获利 | 是否出现推进失败或修复衰减 |
| `DIVERGENCE` 分歧 | 板块回落或炸板增加，但仍有核心维持热度 | 次日核心和容量能否率先修复 |
| `REPAIR` 修复 | 板块止跌/反包，核心先修复，后排负反馈停止 | 修复能否抬高重心并继续给溢价 |
| `OSCILLATION` 震荡 | 板块在区间内反复，核心与分支轮动 | 下轨是否守住，是否重新突破 |
| `SECOND_WAVE_CANDIDATE` 二波候选 | 首轮有地位，调整结构不坏，出现新启动 | 是否突破平台并恢复板块联动 |
| `DECLINE_CANDIDATE` 退潮候选 | 修复高点降低、容量滞涨、助攻走弱 | 是否有新载体接替；没有则降级 |
| `ENDED` 结束 | 核心、容量和助攻连续失效，板块无新承接 | 只观察残余反抽或新周期 |

### 4.4 启动到主流的判断链 `[S]`

#### 第一天：只能叫启动试盘

观察：

- 是否有新的消息、政策、产业或业绩原因；
- 是否出现率先上板的先锋；
- 是否有大成交股票放量大阳、冲高试盘或反包；
- 板块指数是否止跌、反转或突破；
- 是否形成同方向多个股票响应。

输出：随机热点、启动试盘或启动候选。当天不能直接认定最终核心。

#### 第二天：验证不是一日游

必须检查：

- 第一天先锋是否继续晋级；
- 容量是否放量反包或继续大阳推进；
- 后排是否出现大面积负反馈；
- 板块指数是否继续增强；
- 新进入资金是否得到溢价。

先锋断板且容量不反包，原则上降级为一日游或失败启动。

#### 第三日及以后：确认方向结构

检查：

- 高度、容量、分支和后排是否仍协同；
- 板块指数是否继续走强；
- 是否出现明确人气或容量核心；
- 第一次分歧后能否修复。

`[X]` 三日是作者多次使用的案例框架，不是所有环境的硬性天数。有些周期能更快确认，有些弱主流需要更长观察。稳定逻辑是角色跨日协同，不是固定第三天。

### 4.5 判断主流必须回答的七个问题

1. 方向是否经历了启动和至少一次跨日延续？
2. 是否有前排或高度载体打开空间？
3. 是否有容量载体承接大资金并推进价格？
4. 是否有分支、助攻或低位扩散给新资金参与位置？
5. 板块指数是否持续走强或突破，而非个股孤立上涨？
6. 分歧后核心和容量能否率先修复？
7. 原核心受限、疲劳或走弱时，内部有没有新载体接住功能？

缺少任一关键层级不必立即否定方向，但必须降低状态级别并把缺口写入下一日任务。

### 4.6 普通主流与超级主流

超级主流不是“涨得更多”，而是方向经历多轮不同压力后，资金仍回到同一方向，并能更换载体继续制造赚钱效应。

每一轮压力测试必须单独记录：

```text
分歧前的方向状态
→ 分歧由谁先发起
→ 核心、容量、助攻和后排怎样表现
→ 次日谁先修复
→ 修复是否抬高重心
→ 新参与者是否得到溢价
→ 是否仍在原方向内部完成载体切换
```

不能因为“已经发生四次分歧”就自动认定超级主流。修复高点降低、容量滞涨、助攻失去溢价时，多次修复也可能是在衰竭。

### 4.7 方向之间怎样选主路径

不做总分，按淘汰顺序判断：

1. 先排除只有单票、没有板块响应的方向。
2. 再排除只有当日爆发、没有次日或历史连续状态的方向。
3. 再比较哪个方向有更完整的先锋、容量、扩散结构。
4. 再比较哪个方向的昨日买方反馈更好。
5. 再比较哪个方向分歧后修复更主动。
6. 再比较哪个方向在竞争方向走弱时主动承接，而非同步上涨。
7. 最后检查监管空间、催化是否仍在发酵及数据完整度。

在上述淘汰层级中未被否定、证据链完整且未知假设较少的方向成为主路径。另一个方向只有在自身独立成立条件完整时才能成为替代路径。无法拉开差异时，不强行选唯一主流，保留竞争状态。

## 5. Stage 3：识别节点并生成候选池

### 5.1 节点的定义

节点不是某个日期或某根 K 线，而是“原来阻挡资金继续前进的因素正在发生变化”。

每个节点必须回答：

1. 原来的阻力是什么；
2. 哪个可观察事实正在改变阻力；
3. 哪一类资金或角色可能受益；
4. 哪些股票在节点发生时自然进入候选池；
5. 次日怎样确认；
6. 什么情况证明节点判断错误。

### 5.2 十二类候选生成场景

#### G1 情绪转折核心 `[S]`

- 前态：连续退潮、旧高度被压制、高标容易快速亏损。
- 触发：某股通过真实换手、盘中反转或突破旧高度，打破原来的连板惩罚。
- 候选池：完成破局的股票本身。
- 次日确认：换手后站住、继续给溢价，并改善同类情绪。
- 取消：只触及旧高度后回落，或次日失去溢价。

#### G2 情绪转折日低位伴飞 `[S]`

- 前态：G1 已经形成情绪转折。
- 起算日：转折核心形成的同一天。
- 候选池：该日低位首板，不是以后任意低位股。
- 比较：实体换手、晋级、上板先后和自身持续性。
- 确认：后续通过换手和连续晋级，在同组中胜出。
- 取消：没有从同日首板池持续晋级，或只依赖总龙被动上涨。
- `[K]` “换手三板”是明确案例路径，不应作为所有周期固定天数。

#### G3 伴飞升级为二波载体 `[S]`

- 前态：第一波已经获得伴飞或重要助攻地位。
- 额外条件：出现新催化；首波没有被监管封死空间；调整后接近或突破历史压力。
- 候选池：第一波同功能、有二波资格的股票。
- 确认：主动突破压力；竞争者回落时仍推进；重新获得板块带动。
- 取消：只有旧人气反抽，没有新催化、空间或板块响应。

#### G4 总龙断板后的补涨 `[S]`

- 前态：总龙第一次断板，但原板块逻辑尚未结束。
- 起算日：总龙断板当天。
- 候选池：当日低位首板。
- 初筛：实体涨停、分时拉板有力度、所属方向仍有支撑。
- 次日比较：竞价强度、能否晋级、板上换手以及谁先完成任务。
- 取消：原板块整体退潮；孤立消息票；竞价落后且开盘无法夺回。
- 当天只能叫补涨候选，不能提前叫补涨龙。

#### G5 二波分歧后的低位伴生 `[S]`

- 前态：已有二波核心，并出现第一次明显放量分歧或持续上升后的停顿。
- 起算日：二波第一次分歧日。
- 初始候选池：当日首板。
- 确认集合：初始候选中，在高位核心停顿后的确认日再次涨停或主动增强者。
- 继续比较：题材属性、趋势、上板时间和同组唯一性。
- 取消：高位核心彻底结束且板块不修复；低位股只是孤立轮动。

#### G6 主流大分歧后的修复核心 `[S]`

- 前态必须全部满足：方向此前已是主流或强分支；发生板块级大分歧；分歧日仍有前排或核心保持热度。
- 候选池：原总核心、分支核心、容量核心、分歧日抗跌者，以及次日率先修复者。
- 确认：次日板块止跌或反包；候选高开或下探后承接；主动强于同组；容量和板块响应。
- 取消：后排继续大阴或跌停；核心不能反包；只有一只小票孤立上涨。
- 禁止：把任何既有主流方向都自动套进 G6。

#### G7 容量核心候选 `[S/X]`

- 前态：新热点、主流修复或旧核心结束后的承接环境。
- 候选池：方向内成交规模相对大、流动性好、具备核心逻辑的股票。
- 必须验证：大成交后价格仍推进；回踩能收回；修复时与指数/板块同步；自身上涨能带动其他股票。
- 取消：只有大成交没有推进；板块修复时落后；被其他核心反推；重心持续下移。
- `[X]` 不设固定 10 亿、30 亿、40 亿或成交排名阈值。

#### G8 同起算日唯一性 `[S]`

- 前态：存在明确节点日、板块启动日、情绪止跌日或共同首板日。
- 候选池：同日起步且功能相近的完整集合。
- 当日起算时：全组都只能是待验证候选，不能预选赢家。
- 后续比较：换手和持续性、区间强度、容量和带动、竞价主动性、监管空间、次日任务完成情况。
- 确认：经过数日竞争只剩一个阶段有效载体。
- 取消：新对手主动胜出，原候选任务失败或失去带动。
- `[K]` 观察数日是方法，三到四天不是硬规则。

#### G9 旧核心与新核心切换 `[S]`

- 前态：主线整体仍有效，旧核心功能减弱，新候选进入同一功能竞争。
- 事件顺序：旧核心先该强不强、滞涨、破位或竞价弱；新候选随后主动高开、突破、上板或逆势推进；板块响应新候选。
- 确认：新候选持续完成任务，旧核心失去唯一性。
- 取消：新候选只是被旧核心或其他强股带起；主线指数破位且新旧一起弱。

#### G10 高低切换与空间迁移 `[S]`

- 前态：高位核心受到监管、异动、连板空间或推进失败限制，但方向资金尚未整体离开。
- 候选池：对应切换日的低位新题材、首板、容量或主流内剩余空间更大的载体。
- 确认：低位载体先主动走强，原方向资金和板块随后响应。
- 取消：只是任意低位股票上涨；高低一起弱；原方向资金没有延续。

#### G11 底部或恐慌修复中的主动带动者 `[S/K]`

- 前态：指数超跌、底背离或极度恐慌，且跌速开始放缓。
- 候选池：下跌中仍保持上升结构、先停止跟跌、率先主动进攻的辨识度或容量股票。
- 确认：指数停止杀跌；候选率先翻红、突破或上板；随后带动板块、指数或情绪；次日继续获得反馈。
- 取消：指数继续新低；候选只是随指数被动反抽；没有后续带动。
- `[K]` 超卖和底背离的指标参数没有统一定义。

#### G12 突破后的第一次主动分歧 `[K]`

- 前态：股票已经有核心或辨识度地位，并完成有效突破。
- 触发：突破以后第一次明显放量分歧，而不是压力位下尚未突破的弱势分歧。
- 次日任务：竞价或开盘不继续弱；卖压后收回并继续推进；角色与板块仍有效。
- 取消：不能收回弱势、关键支撑破坏、原角色被替代。
- 这是局部案例方法，不能把所有分歧或炸板称为主动分歧。

### 5.3 节点选择顺序

同一方向可能同时出现多个节点，不进行总分，按以下逻辑处理：

1. 先确认节点前态是否真实存在；不存在则节点作废。
2. 再确认阻力是否真的发生变化；只有形态相似不够。
3. 再确认节点能否产生明确、完整的候选池。
4. 再确认次日任务是否可以用现有数据验证。
5. 优先保留与主流状态一致、前态最清楚、候选池最完整的节点。
6. 相互排斥的节点分别进入主路径和替代路径。
7. 所有节点都缺关键前态或验证数据时，进入不行动路径。

## 6. Stage 4：建立功能角色图

角色不是永久身份，而是股票当前为方向完成的任务。必须分别记录“角色候选”“角色确认”和“角色失效”。

### 6.1 总核心或总龙 `[S]`

- 功能：组织方向、打开空间、让其他资金无法绕开。
- 进入候选：在无序或旧周期衰退时先走出持续性；突破旧高度、旧趋势或空间压制。
- 确认：带动容量、助攻和后排；分歧后率先修复；持续给参与者溢价。
- 每日任务：保持领涨或修复优先权，继续维持方向秩序。
- 失效：高位放量滞涨；不再带动；修复落后；助攻批量走弱；新核心主动接替。

### 6.2 情绪或高度核心 `[S]`

- 功能：打开连板高度和短线风险偏好。
- 进入候选：突破此前高标惩罚或连板压制。
- 确认：不是全程无法交易的一字堆高；打开后真实换手仍站住；次日继续给溢价。
- 失效：打开后无法换手续强；高开低走；被新高标替代。

### 6.3 容量核心 `[S/X]`

- 功能：容纳大资金、稳定板块价格重心、确认承接真实性。
- 进入候选：方向核心逻辑相关；成交和流动性在该方向内相对突出。
- 确认顺序：成交扩大后价格仍推进 → 回踩能收回 → 分歧后能快速修复 → 自身上涨带动板块或与情绪核心互相加强。
- 每日任务：维持价格重心，不在板块修复时明显落后。
- 失效：只有成交没有推进；高点和重心下移；板块修复时落后；被另一容量载体替代。
- 禁止：按固定成交金额直接授予容量核心角色。

### 6.4 分支核心 `[S]`

- 功能：负责主线内部某个细分、交易板块或资金类型。
- 确认：在所属分支领涨或承担容量，同时与总方向保持同步。
- 失效：只有单票上涨，细分方向没有响应；总方向失效后仍把它当主线分支。

### 6.5 助攻或伴飞 `[S]`

- 功能：扩大总核心赚钱效应，连接中间梯队或低位扩散。
- 出现位置：总核心破局、情绪转折或二波启动附近。
- 确认：自身能晋级、反包或形成中间梯队；不是只因题材相同被动上涨。
- 反向验证：最佳助攻继续强，说明总核心仍有外部支撑；助攻批量断板，核心持有逻辑降级。
- 失效：次日无溢价、竞争失败、不能继续扩散。

### 6.6 补涨 `[S]`

- 出现位置：总龙第一次断板日。
- 初始身份：只能是补涨候选。
- 确认：从断板日首板池中，通过首板力度、次日竞价、晋级和后续同组竞争胜出。
- 失效：原板块退潮、候选不晋级、被同组替代。

### 6.7 低位伴生 `[S]`

- 出现位置：二波核心第一次明显分歧或持续上升后停顿附近。
- 功能：承接高位溢出资金并延长周期。
- 确认：属于初始节点日首板；确认日再次主动增强；与高位核心或板块属性形成响应；同组竞争胜出。
- 失效：高位核心彻底结束且方向无修复；低位票只有孤立轮动。

### 6.8 二波载体 `[S]`

- 前态：第一波已有明确地位，调整期间结构和重心没有持续破坏。
- 确认：重新突破平台或重要压力；恢复主动带动；得到板块或容量支持；监管空间允许继续验证。
- 失效：普通旧人气反抽；突破后不能站稳；新核心已经接替。

### 6.9 旧核心残余人气 `[S]`

- 特征：仍有人气和反抽能力，但已失去领涨或组织功能。
- 判断关键：如果更强对手先转强，旧核心随后才上涨，则属于被动反抽。
- 处理：更偏退出窗口，除非它重新主动突破并恢复板块带动。

### 6.10 跟风 `[S]`

- 特征：没有独立带动、容量价值、节点地位或阶段唯一性；依赖核心上涨。
- 风险：主线分歧时最先失去溢价和流动性。
- 处理：弱势、轮动和退潮环境原则上排除。

### 6.11 字母载体的使用边界 `[K]`

原文只能确认 A、B、D 在个别历史周期中的助攻、承接或后段续命功能；没有 C 级、完整排序、稳定差异和升级降级算法。

工程规则：

1. 新股票不自动分 A/B/C/D。
2. 先判断总核心、容量、助攻、补涨、伴生、二波等功能角色。
3. 字母标签只保留在离线历史研究中，不参与实时选择。

### 6.12 角色迁移判断 `[S]`

```text
旧角色未完成应有任务
→ 新候选是否先主动增强
→ 板块是否响应新候选
→ 旧角色是否必须依赖新候选反推
→ 次日新排序是否继续得到确认
```

- 新强、旧弱、板块仍有效：角色切换候选。
- 新旧一起弱：方向退潮候选，不叫切换。
- 旧核心先强、新候选后跟：新候选仍是跟随，不能升级。

## 7. Stage 5：建立真正的竞争组

### 7.1 这一阶段解决什么问题

这一阶段不是把所有热门股票放在一起排名，而是回答：

```text
这些股票是不是在争同一个任务
→ 如果是，它们从哪一天开始竞争
→ 当前谁先完成任务
→ 谁只是暂时领先
→ 谁已经取得阶段唯一性
→ 什么事实会让当前排序失效
```

如果竞争组建错，后面所有“最强、卡位、唯一性、主动性”都会失去比较基础。

### 7.2 一张竞争组必须先写清六项定义 `[R]`

| 字段 | 必须回答的问题 |
| --- | --- |
| `trigger_node` | 是哪个节点生成了这组候选，例如总龙断板日、板块启动日、指数止跌日或大分歧日 |
| `start_date` | 从哪一个交易日开始计算竞争，不能随赢家变化而改起算日 |
| `direction` | 候选属于同一方向，还是在争夺同一条替代资金路径 |
| `role_task` | 它们争的是高度、补涨、容量、修复、伴生、二波还是其他同一功能 |
| `capital_type` | 小市值连板、换手连板、大成交容量等资金类型是否可比 |
| `candidate_set` | 起算时符合条件的完整候选集合，以及每只股票的纳入原因 |

其中这些字段名是工程化记录方式，不是作者原词；它们用于防止事后只挑赢家。

### 7.3 哪些股票可以直接比较 `[S]`

至少应满足以下关系中的大部分，且“同一任务”必须满足：

1. 来自同一个可确认的起算节点；
2. 属于同一方向，或正在争夺同一资金承接功能；
3. 承担相同角色任务；
4. 连板身位、趋势阶段或成交容量具有可比性；
5. 使用同一个 `as_of` 时点的事实；
6. 次日可以用相同类型的任务验证。

典型可比关系：

- 总龙断板日的同批低位首板，竞争补涨角色；
- 同一板块启动日的首板，经过数日竞争主升唯一性；
- 同板块、同阶段的两只大成交股票，竞争容量核心；
- 主线仍有效时，旧核心与新候选竞争同一个组织或领涨功能；
- 大分歧日的多只抗跌核心，竞争次日修复核心。

### 7.4 哪些股票不能用一个排名直接比较 `[S/R]`

- 总核心与容量核心承担不同任务，可以同时成立；
- 小市值一字连板与大成交换手容量，不能只比涨幅；
- 总龙断板日的补涨候选，不能与二波分歧日的伴生候选混成一组；
- 旧方向残余人气与新方向启动先锋，只有在争夺同一资金路径时才能比较事件顺序，不能直接比板数；
- 当日首次出现的首板，不能与已经运行多日的趋势核心仅按日内强度排序；
- 公告一字、无法真实换手的股票，不能仅凭连板高度自动战胜可交易换手核心；是否排除仍要结合该组任务，不能建立“一字一律排除”的规则；
- 数据截止时点不同的股票不能比较，例如用 A 股 09:25 数据与 B 股收盘结果比较。

### 7.5 竞争组的建立步骤

#### 第一步：由节点生成候选，而不是由涨幅榜生成候选

例如：

- G4 总龙断板 → 只回看断板当日的低位首板池；
- G5 二波第一次分歧 → 只回看该分歧日的首板池；
- G6 主流大分歧 → 回看原核心、容量、抗跌者和次日率先修复者；
- G8 同起算日唯一性 → 保存启动日完整候选，不提前删掉后来可能胜出的股票。

#### 第二步：按角色任务拆组

同一方向可同时存在：

```text
高度竞争组
容量竞争组
补涨竞争组
低位伴生竞争组
二波竞争组
旧核心—新核心替代组
```

一只股票可以同时进入两个待验证组，例如既是大成交容量候选，又是板块修复候选；但每个身份必须分别给出证据和取消条件。

#### 第三步：保存完整候选和排除理由

候选不能因为后来没涨就从历史池中消失。每只被排除股票必须记录：

- 是起算时就不符合条件；
- 还是后续任务失败；
- 或者数据不足，暂时不能比较。

#### 第四步：先做硬淘汰，再比较强弱

先淘汰：

- 节点前态不存在；
- 角色任务已经失败；
- 方向已经结束；
- 关键结构已经破坏且没有修复；
- 监管或交易条件使原任务无法继续；
- 关键数据缺失，无法证实其胜出。

剩余候选才进入相对比较，不能用加分抵消任务失败。

### 7.6 四类原帖明确支持的竞争方法

#### A. 同一起算日的区间竞争 `[S/K]`

观察：从板块启动日、指数止跌日或其他明确节点开始，比较区间持续性、换手高度、累计推进和后续转强。

部分案例在运行数日后才识别区间唯一性，但具体天数不是硬性算法。稳定关系是：首日通常只能建池，经过后续任务竞争才知道谁仍在推进。

确认链：

```text
同日起步
→ 多日仍保持相对强度
→ 震荡或分歧后再次主动转强
→ 继续获得板块或资金认可
```

取消：只在左侧累计涨幅领先但尚未突破；竞争者随后更主动突破；原方向不再响应。

#### B. 同身位晋级竞争 `[S]`

观察：首板力度、次日竞价、真实换手、谁先上板、板上分歧后谁能继续封住，以及题材是否仍有效。

稳定顺序是：总龙断板日建立完整首板池 → 检查实体和上板过程 → 次日比较竞价 → 板上分歧继续淘汰。当天不能提前宣布补涨龙。

#### C. 容量核心竞争 `[S]`

不能只比较涨幅或成交额，必须看：

1. 谁先主动进攻；
2. 谁在大成交后仍推动价格；
3. 谁在板块分歧后先修复；
4. 谁能稳定板块重心；
5. 谁的上涨带动板块和其他股票；
6. 谁只是被另一个核心反推。

竞价高开只形成容量态度候选，容量角色要到分时推进和板块响应出现后才得到确认。

#### D. 旧核心与新核心竞争 `[S]`

按事件顺序判断：

```text
旧核心本应完成什么
→ 旧核心是否先失去任务
→ 新候选是否在旧核心未修复时先主动突破或上板
→ 板块是否响应新候选
→ 旧核心是否只能等待新候选走强后被反推
→ 次日市场是否继续承认新排序
```

旧核心即使盘中大涨，只要是新候选先完成突破或上板、旧核心随后才被反推，旧核心仍应按强转弱后的残余反抽候选处理。

### 7.7 统一比较顺序：不是总分，而是逐层淘汰

#### 第一层：任务有没有完成

不同角色先按各自任务淘汰。补涨不晋级、容量不推进、修复核心不修复、二波载体不能继续主动，都应先降级。

#### 第二层：谁先主动

记录竞价排名变化、停止跟跌、翻红、突破、上板和带动发生的先后。先动以后还要保持，单笔脉冲不算胜出。

#### 第三层：谁能承受分歧

比较真实换手、回踩是否收回、炸板能否回封、竞争者走弱时是否仍推进。

#### 第四层：谁完成了角色的外部功能

高度核心是否打开空间，容量是否稳住重心，修复核心是否带动板块，助攻是否扩大赚钱效应。

#### 第五层：次日买方是否继续得到奖励

当日胜出只是临时结果。次日没有溢价、竞价落后或不能继续完成任务，排序必须重算。

#### 第六层：监管和剩余空间

当两个候选前述关系接近时，再比较真实监管约束、异动空间和可交易性。不能为了绕监管，选择一个已经失去带动的弱票。

### 7.8 “卡位”的最低证据 `[S]`

一次价格超过、竞价高一点或先触板，都不足以单独叫卡位。必须回答：

1. 两只股票为何原本属于同一竞争组；
2. 新候选超过了原候选的哪一项角色任务；
3. 超过以后是否独立保持强势；
4. 是否带动板块或使原候选失去角色；
5. 次日是否继续确认新的排序。

完整的卡位证据链应包含：节点进入候选 → 经历分歧并保持 → 次日相对直接对手增强 → 在压力环境中继续完成角色 → 与旧核心形成持续分离。不能只截取“竞价更高”一个片段。

### 7.9 唯一性的状态机 `[R]`

作者没有给出正式枚举，工程上按以下状态记录，避免首日就宣布赢家：

| 状态 | 含义 | 允许输出 |
| --- | --- | --- |
| `GROUP_OPEN` | 候选刚由节点生成，尚未竞争 | 全部为待验证候选 |
| `LEADER_CANDIDATE` | 某只暂时领先，但未经历足够压力或次日确认 | 临时领先，不叫最终唯一 |
| `PROVISIONAL_UNIQUE` | 多项比较领先，组内暂时只剩它完成任务 | 阶段唯一性候选 |
| `CONFIRMED_UNIQUE` | 继续主动、完成角色、板块认可且次日排序未被推翻 | 当前阶段唯一性 |
| `REPLACED` | 新对手先主动并接管原任务 | 原候选降级为旧核心或跟随 |
| `CANCELLED` | 整个方向、节点或角色任务失效 | 该组竞争结束 |
| `DATA_INSUFFICIENT` | 缺完整候选、同时间轴或关键过程数据 | 不得宣布胜出 |

唯一性只在“某个节点、某个方向、某个角色组、某段时间”内成立。市场可以同时存在一个情绪高度核心和一个容量核心；这不是逻辑冲突。

### 7.10 Stage 5 必须输出

| 输出项 | 内容 |
| --- | --- |
| 竞争组定义 | 节点、起算日、方向、角色、资金类型 |
| 完整候选 | 纳入原因、当前状态、数据覆盖 |
| 当前排序 | 只写关系和证据，不写综合分 |
| 暂时领先者 | 它先完成了什么任务 |
| 未确认项 | 仍需竞价、开盘、板块或次日反馈确认什么 |
| 替代条件 | 哪个对手在什么条件下会接管 |
| 取消条件 | 什么情况使整个竞争组作废 |
| 次日动作收敛 | `action_shortlist` 最多两只；其余全部进入 `validation_only` |

### 7.11 完整候选池不等于次日动作名单 `[S/R]`

完整候选池的作用是防止后验删对手；次日动作名单的作用是让人能够执行。两者必须分层保存：

```text
complete_candidate_pool：节点产生的全部合法候选，不能删除
action_shortlist：盘后已经能写出明确条件的唯一或唯二对象
validation_only：其余候选，只用于证明路径、角色和唯一性是否成立
```

原始语料中反复出现“唯一盘前思路”“唯一备选”“唯二观察”的做法，也出现过从二十多只节点首板中先收敛到两只、再由次日竞价处理的案例。稳定关系不是固定选一只，而是盘前先大幅收敛，不能把整个候选池留给竞价现场重新讲故事。

收敛顺序：

1. 先固定当前节点真正需要的一个动作角色；
2. 删除只承担验证作用、却不是当前动作角色的股票；
3. 在同角色组中检查是否已经形成区间、身位、分支、容量、主动性或结构突破的唯一性；
4. 已有 `PROVISIONAL_UNIQUE` 或 `CONFIRMED_UNIQUE` 时，只保留该股为主动作对象；
5. 若两个直接对手仍需由次日相对竞价决定，可保留“条件二选一”，但必须盘前分别写好谁在什么条件下胜出；
6. 若仍有三只及以上无法排除，说明盘后没有形成可执行唯一性，该节点次日只观察，不行动；
7. 其余完整候选继续留在数据库，若后续形成新节点再重新进入动作收敛，不能在当天临时插队。

`[R]` 为避免接口把一大组股票伪装成作战计划，工程规定每个节点的 `action_shortlist` 最多两只。这个数量上限是根据“唯一/唯二”执行风格增加的工程纪律，不冒充作者给出的普遍数学定律。

只有首日集体大涨但尚未形成唯一性的方向，原则上不得把全部前排列为次日买入候选。它可以作为路径验证对象；动作应等待唯一性出现、分歧后的第一次强回流，或另一个已经定义清楚的节点。特定补涨节点若能在盘后根据首板过程和分支功能收敛到一两只，才允许建立次日条件预案。

下一步：只给 `action_shortlist` 写次日动作任务；给 `validation_only` 写路径验证任务。没有明确动作角色、对象和取消条件的股票不得进入作战计划。

## 8. Stage 6：生成次日预期和逐票任务

### 8.1 预期到底是什么

这里的预期不是猜明天涨几个点，而是：根据股票今天的角色、状态和环境，写出它明天必须完成的可证伪任务。

```text
角色决定“它负责什么”
→ 今日状态决定“明天需要延续还是修复”
→ 板块环境决定“要求提高还是持有周期缩短”
→ 同组对手决定“至少不能落后于谁”
→ 监管与空间决定“正常加速是否仍可直接解释”
→ 最终写成竞价、开盘、盘中和失败四段任务
```

`[R]` “次日任务”是为执行作者的预期差方法建立的统一记录形式，不是作者给出的固定公式。

### 8.2 生成次日任务的固定顺序

#### 第一步：写角色基础义务

先回答“如果它真是这个角色，明天必须为板块做什么”。

| 角色 | 次日基础义务 |
| --- | --- |
| 总核心 | 继续组织方向；分歧时率先修复；不能长期依赖后排反推 |
| 情绪高度核心 | 维持高度和风险偏好；打开后要经真实换手站住 |
| 容量核心 | 大成交后继续推进或稳住重心；板块修复时不能明显落后 |
| 分支核心 | 在本分支领先，同时仍与总方向保持有效联系 |
| 助攻/伴飞 | 继续给溢价、晋级或反包，扩大总核心的赚钱效应 |
| 补涨候选 | 从节点日首板池中继续晋级并强于同组对手 |
| 低位伴生候选 | 在高位核心停顿后主动增强，确认资金仍在原方向内部延续 |
| 二波载体 | 突破后继续主动推进并恢复板块带动，不能只靠旧人气反抽 |
| 旧核心 | 若不能重新取得主动和带动，只能按残余人气处理 |
| 跟风 | 没有独立角色任务，原则上不进入行动候选 |

#### 第二步：写今日状态修正

同一角色因今天的走势不同，明天的任务也不同。

##### A. 一字板或极强加速 `[S/K]`

- 正常要求：次日强度应与前一日惯性相称；至少不能在没有外部解释时突然落后于同组。
- 如果全市场恐慌导致本应加速的核心打开，可能形成作者所说的特殊预期差，但必须看到真实换手、承接和重新转强。
- 取消：初始封单强但持续撤单，最终开盘和开盘承接都明显不符合角色；或者同组新对手先完成任务。
- `[K]` 原帖中的 10 万手、20 万手等是个案标尺，不能复制成通用阈值。

##### B. 健康换手涨停 `[S]`

- 正常要求：次日应有与角色相称的溢价；核心和补涨候选还应继续争取晋级或率先上攻。
- 不要求所有健康换手板都必须一字高开；关键是竞价和开盘后不能在同组中无解释落后。
- 取消：板块修复而它不修复；竞价弱于原第二名且开盘不能夺回；放量但价格不推进。

##### C. 爆量烂板或反复开板 `[S]`

先判断位置：

- 低位新题材、平台突破、板块大分歧中的“烂而不弱”，次日任务是弱转强；
- 高位多次加速后的反复烂板，更偏卖压和推进失败风险；
- 只有次日竞价、开盘承接和同组领先才能区分，不能见烂板就自动看多。

##### D. 炸板或冲高回落 `[S/K]`

先还原事件顺序：外部板块是否先弱、目标是否本组先兑现、关键结构是否仍在。

- 若外部先分歧、目标后回落且角色未破坏：次日环境修复时应率先反包或弱转强；
- 若目标先滞涨、先炸板并带弱板块：更接近主动走弱或推进失败；
- 无完整过程数据时只写“待确认”，不能自行归为主动/被动炸板。

##### E. 阴线、断板或第一次明显分歧 `[S]`

- 主升结构、核心角色和方向仍有效时，次日任务是停止继续弱势并主动修复；
- 已经多次分歧、修复高点降低或角色被替代时，不能再机械套弱转强；
- 压力位下尚未突破的分歧，不属于“突破后的第一次主动分歧”。

##### F. 突破后的第一次放量分歧 `[K]`

这一模式只得到局部案例支持。次日应竞价或开盘转强、收回卖压并继续推进。

案例中出现过“至少触及涨停”等具体任务，但不能扩展成所有突破分歧股票的通用条件。通用部分仅是：如果仍处于强主升，次日必须继续做出与角色相称的向上尝试，不能全天被动走弱。

##### G. 恐慌日抗跌或逆势进攻 `[S]`

- 次日指数或板块止跌时，它应率先翻红、突破、上板或继续带动；
- 如果只在指数先反弹后跟随，则“主动分离”假设降级；
- 如果指数继续新低且它也破坏结构，则节点取消。

##### H. 平台整理后再次转强 `[S]`

- 必须先有历史地位或同节点区间唯一性；
- 盘中重新突破时要看到持续成交和板块响应；
- 仅因震荡二至三天后拉一笔，不足以确认重新主升。

##### I. 二波启动或二波候选 `[S]`

- 第一波地位、调整结构、新催化或板块关系必须仍在；
- 次日要继续推进、守住突破并恢复带动；
- 尾盘炸板、次日被新核心卡位或只有被动反抽，二波预期降级。

#### 第三步：加入方向和环境修正

| 环境/方向 | 对次日任务的影响 |
| --- | --- |
| 主流启动第二日 | 先锋要晋级，容量要反包或继续推进，后排不能立即大面积负反馈 |
| 主流主升 | 核心和容量应继续组织，角色任务要求最高；后排加速不自动成为新买点 |
| 板块高潮后 | 重点看核心能否维持，默认不追后排；次日加速后出现分歧要缩短持有 |
| 主流大分歧后 | 候选必须率先修复并带动板块，单票反包不够 |
| 修复日后 | 修复必须继续抬高重心并给买方奖励，否则只是反抽 |
| 轮动环境 | 即使任务完成，也先按短反馈处理；对落后和不及预期更敏感 |
| 下跌环境 | 默认不行动，只保留恐慌修复、主动分离和破局核心，且要求更强确认 |
| 新旧切换未决 | 旧路径和新路径分别写任务；新方向不能只靠旧方向失败自动胜出 |

### 8.3 与自己、对手、板块三重比较 `[S]`

每只股票的预期必须同时回答：

1. **与自己比较：** 今天的强度和角色，要求明天保持什么惯性；
2. **与同组比较：** 它至少不能无解释地落后于哪一个直接竞争者；
3. **与板块比较：** 板块弱时它是否先抗跌，板块修复时它是否先修复，板块强时它是否真正带动。

如果某候选在板块分歧日是同组最主动者，次日竞价和开盘仍应完成相对直接对手的任务；若无解释地落后且不能夺回，原主动地位失效。这里的规则是“前一日最主动者次日仍需完成相对任务”，不是固定高开百分比。

### 8.4 四段式次日任务

每只作战候选必须在 T 日盘后写完以下内容：

| 阶段 | 要写什么 |
| --- | --- |
| 竞价任务 | 相对昨日惯性和同组对手，至少应保留什么强度；哪些数据缺失 |
| 开盘卖压任务 | 第一轮下探、开板或回踩后，需要守住或收回什么关系 |
| 盘中角色任务 | 要不要晋级、反包、突破、带动板块或稳住容量重心 |
| 直接失败条件 | 哪个事实一出现，就不再为它寻找解释 |

禁止只写“看是否弱转强”“看承接”“看表现”。必须写明比较对象和可观察动作。

### 8.5 预期结果的判定状态 `[R]`

| 状态 | 判断方式 |
| --- | --- |
| `EXCEEDS_EXPECTATION` | 完成基础任务之外，还主动超过同组、带动板块或使原路径升级 |
| `MEETS_EXPECTATION` | 完成盘前写定的角色任务，原路径继续有效 |
| `PARTIAL_CONFIRMATION` | 完成一部分，但板块、对手或后续承接尚未确认 |
| `FAILS_EXPECTATION` | 明确未完成角色任务，或直接失败条件出现 |
| `DATA_INSUFFICIENT` | 缺少完成判断所需的同时间轴数据 |

这些状态只能对盘前已经冻结的任务判定。看到结果后补写“本来就应该如此”，属于后验。

### 8.6 板块级超预期与个股级超预期必须分开 `[S]`

- **板块级超预期：** 原本震荡或被看弱的方向，核心、容量、板块指数和扩散共同快速增强，可能改变持有周期；
- **个股级超预期：** 某只股票超过自己的角色任务，但板块未必升级；
- **短期情绪弱转强：** 可以有首日快速奖励，但次日后排通常要更谨慎，不能自动当长期主线；
- **单票孤立高开：** 没有板块和容量响应，不得写成板块级超预期。

板块级启动与短期情绪反转都可能被描述为“超预期”，但前者需要多角色协同，后者可能只有短反馈；二者的持有和次日处理不能混用。

### 8.7 Stage 6 必须输出的逐票卡片

```text
股票：
竞争组：
当前角色及证据：
今日状态及所处位置：
竞价最低任务：
开盘卖压后的任务：
盘中必须完成的角色任务：
必须强于/不能依赖的对象：
所需板块配合：
直接失败条件：
数据不足项：
```

### 8.8 盘后必须形成“条件—股票—动作”决策卡 `[S/R]`

完整候选的逐票任务用于审计，真正交给次日执行器的只能是下面这张收敛卡：

```text
当前动作节点：
主动作股票：具体代码和名称，或 NONE
主动作成立条件：竞价必须怎样；开盘后必须怎样
备用股票：具体代码和名称，或 NONE
从主动作切到备用的条件：主动作哪项明确失败；备用哪项独立完成
验证股票：只负责验证方向、容量或高度，不允许自动变成动作对象
两只都不做的条件：
禁止临时加入的股票：完整候选池中除主动作和备用以外的全部股票
```

若本阶段只能写出“竞价看谁强就买谁”，说明预案没有完成。必须进一步回答：只看哪两只、为什么只有这两只、A 怎样才买、A 失败后 B 怎样才允许替代。若回答不了，则 `主动作股票=NONE`，该节点次日只观察。

下一步：把明确到具体对象的决策卡组织成主路径、替代路径和不行动路径，而不是生成一个无条件买入名单。

## 9. Stage 7：建立三条路径并决定“最终选哪个”

### 9.1 为什么不能盘后直接给唯一股票答案

盘后只能根据 T 日事实生成条件化计划。真正的选择还取决于 T+1 竞价和开盘卖压是否验证。

因此输出结构应是：

```text
如果主路径完成 A、B、C，且盘前指定股票 X 完成自己的触发 → 只进入 X 的开盘验证
如果 X 明确失败，且盘前指定备用股票 Y 独立完成 D、E → 只进入 Y 的开盘验证
如果 X、Y 都没有完成，或所需数据不足 → 不行动
```

X 和 Y 必须在盘后已经写明代码、名称、角色和条件，不能到竞价后再从完整候选池里挑。若盘后无法指定 X 或 Y，正确预案就是该节点不行动。

### 9.2 主路径怎样确定

主路径必须来自 Stage 2 已建立的方向状态，并同时满足：

1. 方向不是单日孤立热点；
2. 当前节点前态清楚；
3. 核心、容量或扩散结构至少有可验证载体；
4. 昨日买方反馈和修复质量没有明显否定它；
5. 已建立完整竞争组；
6. 次日任务能被现有数据验证；
7. 依赖的未知假设少于其他路径。

主路径必须写：方向为何领先、当前是什么节点、关键角色是谁、明天哪三个左右的关键事实必须出现、哪个事实会立即取消。这里的“三个左右”只是表达控制，不是固定计数规则。

### 9.3 替代路径不是“第二高分” `[S/R]`

替代路径必须有自己的正向成立条件，例如：

- 旧主流走弱时，新方向率先出现先锋、容量和板块共振；
- 主路径旧核心失效时，同方向新核心主动接管并带动板块；
- 高位受监管或空间限制时，低位载体在对应节点主动承接；
- 主流分歧无法修复时，另一个已连续运行的方向获得买方反馈。

只看到主路径失败，不足以证明替代路径成功。新路径也必须独立完成任务。

### 9.4 不行动路径必须事先写好 `[S/R]`

至少包括：

- 环境继续系统性下行；
- 主流和替代方向都没有形成角色协同；
- 主路径失败，新路径没有主动接管；
- 只有小票高开，容量和板块不响应；
- 竞价展示很强，开盘承接迅速消失；
- 竞争组数据不完整，无法确认谁胜出；
- 所有剩余候选都触发了直接失败条件；
- 无法为动作写出明确取消条件。

不行动不是分析失败，而是三条路径中的正式结果。

### 9.5 T+1 的路径切换状态机 `[R]`

| 观察结果 | 处理 |
| --- | --- |
| 主路径完成任务，替代路径未独立增强 | 保留主路径 |
| 主路径部分完成，替代路径也未确认 | 延后到开盘验证，不提前切换 |
| 主路径失败，替代路径先主动且板块响应 | 替代路径升级为当前主路径 |
| 主路径失败，替代路径只被动跟涨 | 两条都降级，进入不行动 |
| 新旧核心一起弱 | 判断方向退潮候选，不叫角色切换 |
| 数据缺少，无法确认事件顺序 | 输出数据不足，不允许模型补叙事 |

### 9.6 盘后动作收敛与次日确认的七步法

这七步不是让竞价执行器从大池中继续选股。第 0—6 步必须在 T 日盘后完成并冻结；T+1 只执行第 7 步。

#### 第 0 步：确认数据允许做这个判断

若动作依赖分钟路径、同组竞价或板块同步，而数据不存在，直接停止在 `DATA_INSUFFICIENT`。

#### 第 1 步：先确定次日允许验证的路径

根据 T 日已知事实确定主路径、替代路径和不行动路径。路径没有形成合法节点，股票不能因为次日可能大涨而越级进入动作名单。

#### 第 2 步：在路径内固定当前真实节点

例如当前到底是总龙断板补涨、主流大分歧修复、旧新核心切换，还是二波启动。节点不同，应该选择的角色不同。

#### 第 3 步：只进入该节点对应的角色竞争组

- 补涨节点选补涨竞争组；
- 大分歧修复选修复核心和容量竞争组；
- 旧新切换选承担同一功能的新旧核心组；
- 二波节点选有首波地位和结构的二波组。

不能因为另一组股票涨幅更大就临时换组。

#### 第 4 步：先剥离验证股票

高度、容量、助攻和扩散可以共同证明路径，却不一定都是当前节点要买的角色。只承担验证任务的股票全部移入 `validation_only`，不得进入动作叶子。

#### 第 5 步：用 T 日已经发生的事实收敛同角色候选

只使用截至 T 日收盘已经看见的节点地位、区间唯一性、身位、分支功能、容量承载、主动性、承压和外部带动逐层淘汰。不能把“明天再看谁强”当成盘后没有完成的工作。

#### 第 6 步：冻结 PRIMARY、BACKUP 或 NONE

- 只剩一只具有明确动作角色和触发：它成为 `PRIMARY`；
- 只剩两个直接对手，且可以盘前分别写清相对任务：可以形成条件唯二，一只是 `PRIMARY`，另一只是 `BACKUP`；
- 三只及以上仍无法排除，或一只也没有形成足够唯一性：该节点 `PRIMARY=NONE`、`BACKUP=NONE`，次日只验证；
- 两个不同路径各自已经有唯一对象：可以分别成为主、备，但备用必须独立成立。

#### 第 7 步：T+1 只验证冻结叶子

Stage 8 先运行 PRIMARY/BACKUP 的竞价条件树，最多命中一个 `current_action_candidate`；Stage 9—10 只验证这一个对象的卖压、承接和具体动作。没有出现回踩拐头、主动突破、真实回封或明确尾盘确认时，即使盘后逻辑最好，也是不行动。完整候选池和意外强势股不得在盘中补入。

### 9.7 多个候选同时成立时怎么办

作者没有给出适用于所有节点的固定角色优先级，因此不得写成“总核心永远优先于容量”或“涨幅第一永远优先”。按以下方式处理：

1. 先看当前节点究竟需要哪个角色完成任务；
2. 再看哪个候选的确认链更短、未知假设更少；
3. 再看谁已经通过真实卖压和板块响应；
4. 若两只承担不同功能，只把当前节点所需角色保留为动作对象，另一只进入验证对象；
5. 若同角色只剩两个直接对手，可以写成盘前条件唯二；三只及以上仍无法拉开则该节点不行动；
6. 若两个独立路径各自已有唯一动作对象，可以组成 PRIMARY/BACKUP；若任何路径都没有唯一对象，则不行动。

### 9.8 最终选择必须能用普通话解释

合格解释示例：

```text
今天选择的不是“全市场涨得最快的股票”。
当前确认的是主流大分歧后的修复节点，因此只比较原板块里负责修复的核心和容量。
A 股竞价先于 B 股转强，开盘下探后先收回，并带动板块指数和 B 股跟随；
B 股只能在 A 股走强以后反弹，所以 A 完成了修复核心任务，B 降级为跟随。
如果 A 再次跌回卖压低点、板块也不响应，则本次选择取消，不切去 B。
```

不合格解释：

- “综合评分最高”；
- “原帖说它是主流”；
- “人气高、题材好、可能涨停”；
- “主路径失败，所以自动买替代方向”；
- “它是龙头，所以继续持有”。

### 9.9 Stage 7 必须输出

```text
主路径：方向、节点、成立条件、动作竞争组、验证角色、取消条件
替代路径：独立成立条件、动作竞争组、验证角色、取消条件
不行动路径：触发条件、重新开始观察的条件
当前盘后优先级：为什么主路径暂时优先
主动作股票：具体代码和名称，或 NONE
备用股票：具体代码和名称，或 NONE
T+1 条件树：09:25 哪个条件保留主动作，哪个条件切到备用，哪个条件直接放弃
验证对象：哪些股票只看、不允许买
```

### 9.10 次日执行必须是封闭条件树 `[S/R]`

盘后输出的动作叶子最多两个：

```text
PRIMARY：股票 X
  IF 主路径成立 AND X 完成竞价最低任务
  THEN 开盘只验证 X

BACKUP：股票 Y 或 NONE
  IF X 触发直接失败 AND Y 自己的路径与任务独立成立
  THEN 开盘只验证 Y

ELSE：NO_ACTION
```

备用不是“竞价第二强”。Y 必须在盘后已经进入 `action_shortlist`，并拥有独立触发。如果 X 只是数据不足而不是明确失败，不能自动切 Y；因为这时无法证明排序真的改变。

两只同组候选可以写成条件二选一，例如：若 X 的正式开盘和相对任务强于 Y，则只验证 X；若顺序反转，则只验证 Y。这类预案的关键是盘前只保留 X、Y，而不是竞价后从二十多只股票中找最强者。

若两个不同方向各自已有唯一动作对象，可以分别作为 PRIMARY 和 BACKUP；但切换到 BACKUP 仍需其方向独立增强，不能只因 PRIMARY 失败。

完整候选池、验证对象和当天新出现的强票均不得在 09:25 后加入动作叶子。它们只能触发下一次收盘重算。

下一步：进入竞价验证。竞价只能运行这棵已经冻结的条件树，不能重新读取原帖、重做盘后选股或临时发明新的交易故事。

## 10. Stage 8：09:15、09:20、09:25 竞价验证

### 10.1 这一阶段解决什么问题

竞价不负责从零选股，只回答：盘后路径和逐票任务，今天早上有没有得到初步确认。

```text
盘后已冻结的预期
→ 09:15 看初始展示
→ 09:20 看强度是否保留、同组排序是否改变
→ 09:25 看最终可执行开盘结果
→ 检查板块性、容量和旧核心是否支持
→ 保留、降级、取消或等待开盘验证
```

如果盘后没有明确预期，竞价后不得补写“它本来就应该这么开”。

### 10.2 竞价前必须已经具备的内容

1. 主路径、替代路径和不行动路径；
2. 每只股票的角色和真正竞争组；
3. 前一日状态：一字、换手、烂板、冲高回落、分歧或其他；
4. 逐票竞价最低任务和直接失败条件；
5. 需要同步验证的板块、容量和旧核心；
6. 当时有效的涨跌停、异动、停牌和交易规则；
7. 数据覆盖清单。

缺少 1—4 时，竞价只能记录事实，不能评价“超预期或不及预期”。

### 10.3 所需数据

#### 个股数据

- 09:15—09:25 每个可得时间点的虚拟成交价、匹配量和匹配金额；
- 未匹配买卖量及方向；
- 09:25 最终开盘价和撮合金额；
- 昨收、涨跌停价、前一日成交、自由流通规模；
- 同组全部候选的相同时间轴数据；
- 停牌、风险警示和交易状态。

未匹配方向可以描述当前申买、申卖的不平衡，但不能单独证明“主力主动买入”或未来一定封板。

#### 板块和市场数据

- 方向内前排股票的竞价分布；
- 情绪核心、容量核心、助攻和旧核心的竞价；
- 板块指数或可复现的成分股集合；
- 全市场涨停开盘、跌停开盘和高低开分布；
- 相关指数的最终开盘状态。

只看一只股票，无法判断它是板块共振还是孤立展示。

### 10.4 三个时间点分别能说明什么

#### 09:15：初始意向，不是结论 `[S/M]`

记录：

- 初始是否涨停或明显高开；
- 匹配金额在同组中的位置；
- 前排是否集中到同一方向；
- 前一日弱势候选是否出现反常强势；
- 前一日极强候选是否维持应有展示。

基于集合竞价规则，09:15—09:20 允许撤单，因此初始大单只能表示展示意向，不能直接确认真实开盘强度。不得只凭 09:15 下最终结论。

#### 09:20：观察保留、撤退和排序迁移 `[K/M]`

记录从 09:15 到 09:20：

- 初始大单是否明显消失；
- 匹配金额是增强、稳定还是衰减；
- 原领先者是否被同组对手超过；
- 弱势候选是否持续加强，而不是只闪现一笔；
- 板块前排是否仍具有群体性。

09:20—09:25 按交易所规则不接受撤单，后段展示通常比 09:15 更有约束力；但完整的 09:15→09:20→09:25 排名迁移只得到局部案例支持。因此三时点是合理的数据记录框架，不得宣传成作者给出的统一公式。

#### 09:25：最终开盘结果 `[S]`

必须检查：

1. 最终开盘是否保住前面的强度；
2. 最终匹配金额是否支持该开盘，而非只剩价格外观；
3. 同组最终排序是否改变；
4. 是否满足股票自己的角色任务；
5. 板块前排、容量和旧核心是否共同支持；
6. 是否存在高开透支、无法成交或监管空间问题。

只有 09:25 最终数据时，只能判断最终开盘关系，不能反推出 09:15—09:20 是否撤单或加强。

### 10.5 原始数字必须经过可比化，但不生成总分 `[R]`

不同股票的价格、股本和昨日成交差异很大，不能只比较“多少手”。至少同时保存：

- 开盘相对昨收的位置；
- 匹配金额，而不仅是股数；
- 匹配金额相对自身前一日成交的关系；
- 未匹配量相对自身流通规模的关系；
- 同组原始排名和变化。

这些标准化只为避免量纲错误，不产生“竞价分数”。作者没有提供通用权重或阈值。

### 10.6 竞价判断的固定顺序

#### 第一步：先和股票自己的昨日状态比较

- 前一日大单一字或秒板，今天是否保留与其惯性相称的强度；
- 前一日烂板、阴线或冲高回落，今天是否出现真正的反常增强；
- 前一日主动最强者，今天是否仍能维持相对领先；
- 前一日已经走弱的旧核心，今天高开是否只是人气残余。

#### 第二步：再和同组竞争者比较

比较同一时间点的价格位置、匹配金额、加强/衰减和最终开盘。原领先者落后后，还要等开盘看能否夺回，不能只凭竞价一刻完成永久卡位。

#### 第三步：再看板块是不是一起确认

- 多只前排同时增强，且容量核心没有缺席：板块路径得到支持；
- 只有一只小票顶一字，容量和其他角色普遍弱：降级为单票行为；
- 新方向前排增强，旧方向核心和容量同步走弱：形成切换候选，仍待开盘因果顺序确认。

#### 第四步：最后检查交易空间和可成交性

高开不等于更好。必须结合：

- 距离涨停还剩多少盘中空间；
- 前一日已经兑现了多少强度；
- 是否接近有效监管边界；
- 是可真实成交的换手，还是无法参与的一字；
- 开盘后需要承受多大的获利盘和套牢盘卖压。

作者没有给出跨股票通用的“高开超过多少就透支”公式。

#### 第五步：只在盘前的 PRIMARY 和 BACKUP 中执行条件树

```text
PRIMARY 满足竞价最低任务
→ current_action_candidate = PRIMARY
→ BACKUP 继续只作验证，不同时进入动作

PRIMARY 触发明确失败，且 BACKUP 独立完成自己的方向、角色和竞价任务
→ current_action_candidate = BACKUP

PRIMARY 只是数据不足，或 BACKUP 只因 PRIMARY 变弱才相对显得更强
→ current_action_candidate = NONE

PRIMARY 和 BACKUP 都失败
→ NO_ACTION
```

竞价中其他股票即使更强，也只能记入 `unexpected_observer`，不得加入当日动作。收盘后再判断它是否形成了新的唯一性和下一日节点。

### 10.7 四类竞价结论

#### `AUCTION_CONFIRMS_PATH`

逐票任务得到满足，同组排序没有被推翻，板块和关键角色共同支持。仍需开盘卖压验证，不等于立即买入。

#### `AUCTION_NEEDS_OPEN_VALIDATION`

竞价部分满足，但存在以下任一情况：

- 高开但承接未知；
- 同组排序接近；
- 单票强、板块尚未响应；
- 前一日弱势只完成了竞价修复；
- 高开较多，是否透支需要看开盘。

#### `AUCTION_REJECTS_PATH`

直接失败条件出现，例如：

- 前一日最主动者明显落后于原第二名；
- 本应极强却持续衰减，最终未按角色开盘；
- 主路径核心、容量和助攻共同弱；
- 新旧核心一起弱；
- 替代方向没有独立增强。

#### `DATA_INSUFFICIENT`

缺前态、同组、过程或板块数据，无法判断。不得改写成“竞价一般”或“可能弱转强”。

### 10.8 竞价常见误判

- 看到涨停价就叫超预期，却没有和昨日强度比较；
- 只按封单股数排名，不考虑价格、股本和自身历史成交；
- 用 09:15 初始大单当最终事实；
- 只有最终开盘，却编造中途撤单；
- 小票强就宣布板块强，不看容量和前排群体；
- 主路径失败就自动切换替代路径；
- 一字无法成交，却在回测中按涨停价默认买入；
- 临近开盘才为已经走强的股票补写盘前逻辑。

### 10.9 Stage 8 必须输出

```text
路径结论：保留 / 降级 / 取消 / 数据不足
盘前 PRIMARY：
盘前 BACKUP：
条件树命中的对象：PRIMARY / BACKUP / NONE
个股昨日任务：
09:15 事实：
09:20 变化：
09:25 最终事实：
同组排序变化：
板块与角色支持：
仍需开盘验证：
直接取消条件是否触发：
竞价意外强势但禁止临时加入的股票：
```

下一步：进入开盘后第一轮卖压验证。竞价结论必须能被开盘推翻。

---

## 11. Stage 9：开盘五分钟、承接、弱转强和主动/被动

### 11.1 这一阶段解决什么问题

竞价看到的是开盘前的供需展示；开盘后才开始承受真实卖压。这个阶段要判断：

- 竞价强度能否延续；
- 第一轮卖压是否被吸收；
- 谁先主动，谁只是跟随；
- 股票是否完成角色任务；
- 路径是确认、延后还是取消。

“五分钟”来自作者多篇操作框架中的重点观察窗口，但不是到了 09:35 就自动得出答案。五分钟内没有完成确认，可以继续观察；不能为了按时输出而强行分类。

Stage 9 不再对完整候选池逐票寻找买点。进入本阶段的动作对象只能是 Stage 8 条件树命中的一只 `current_action_candidate`。其他股票继续作为板块、容量、同组或高度验证对象；即使它们开盘后突然大涨，也不能当日临时替换。

### 11.2 开盘前必须冻结的参照物

每只股票至少标记：

- 昨收、今开、昨日高低点；
- 前一日关键分时均价或平台；
- 最近突破位、平台、前高和重要支撑；
- 涨停价和跌停价；
- 同组直接对手；
- 板块指数、容量核心和旧核心；
- 盘前写定的第一轮卖压任务。

开盘后临时挑一个刚好守住的价格当“关键支撑”，属于后验。

### 11.3 所需数据精度决定能判断到哪一层 `[R]`

| 数据 | 可以判断 | 不能严格判断 |
| --- | --- | --- |
| 只有日线和开盘价 | 高低开、最终日线结果 | 五分钟路径、承接、先后顺序 |
| 一分钟线 | 下探、收回、低点抬高、相对板块先后候选 | 逐笔主动买卖、精确撤单者 |
| 秒级/逐笔成交 | 更精细的事件顺序、连续成交方向候选 | 未有委托队列时仍不能知道所有隐藏意图 |
| 逐笔委托和队列 | 撤单、挂单、成交的更完整变化 | 仍不能把账户动机写成确定事实 |

没有逐笔数据时，可以写“价格路径主动候选”，不能写“某类主力资金确定主动买入”。

### 11.4 开盘后固定观察顺序

#### 第一步：确认第一轮卖压发生了什么

记录：

- 是高开直接上攻，还是先下探；
- 下探最低到哪个盘前关键位置；
- 成交是否明显放大；
- 板块、指数或同组谁先走弱；
- 目标是否本组最先兑现。

#### 第二步：看价格是否停止继续走弱

可见行为包括：

- 下探后没有继续创新低；
- 多次回踩的低点逐步抬高；
- 重新站回开盘价、昨收、分时均价或预先标记的关键位；
- 炸板后没有连续失速下坠；
- 板块仍弱时，目标先停止跟跌。

停止下跌只是承接候选，还不是进攻确认。

#### 第三步：看收回以后有没有继续推进

- 重新突破开盘后的第一波高点；
- 连续成交把价格向上推，而非一笔脉冲；
- 触及或突破盘前阻力；
- 尝试上板或完成回封；
- 推进过程中低点和价格重心继续抬高。

收回后再次跌回原弱势，承接确认取消。

#### 第四步：还原同组和板块的事件顺序

记录到秒或分钟：

```text
目标停止跟跌时间
目标翻红/突破/上板时间
对手对应事件时间
板块指数转强时间
容量核心转强时间
旧核心反抽时间
```

目标先动且后续对象响应，才有主动带动候选；板块或更强对手先动、目标后跟，属于被动跟随候选。

#### 第五步：回到角色任务

同样的价格路径，对不同角色含义不同：

- 补涨候选必须继续晋级或取得同组领先；
- 容量核心需要推进并带动，不能只守住不跌；
- 修复核心需要率先修复，不能等板块全面转强后跟随；
- 旧核心只有重新取得主动和带动，才可能恢复角色；
- 助攻只抗跌但不能扩散，仍可能任务失败。

### 11.5 承接的可执行定义 `[S/R]`

承接不是一个形容词，而是一段过程：

```text
卖压出现
→ 预先标记的关键关系没有持续破坏
→ 新的成交把价格收回
→ 收回后不立即失守
→ 价格继续推进或完成角色任务
```

可输出状态：

| 状态 | 条件 |
| --- | --- |
| `SUPPORT_CANDIDATE` | 已停止继续下跌或守住关键位，但尚未重新推进 |
| `SUPPORT_CONFIRMED` | 收回关键关系后保持，并继续推进或完成角色任务 |
| `FALSE_SUPPORT` | 短暂收回后迅速失守，低点和重心继续下移 |
| `DATA_INSUFFICIENT` | 没有分钟或成交路径 |

作者没有给出“多少分钟不破、多少成交额即承接”的统一阈值。

### 11.6 弱转强的完整判断链 `[S]`

#### 必要前态

前一日必须真的弱、分歧、烂板、冲高回落或遭遇外部恐慌。如果前一日本来就很强，次日继续强属于延续，不叫弱转强。

#### 竞价候选

次日没有延续弱势，出现相对昨日和同组的增强。但竞价只生成候选。

#### 开盘确认

1. 第一轮卖压没有使其重新回到原弱势；
2. 下探后收回，或高开后持续推进；
3. 强于同组直接对手；
4. 板块或容量至少不明显反向；
5. 完成当前角色任务。

#### 取消

- 高开后快速跌回原弱势；
- 只拉一笔，随后重心下移；
- 同组对手先主动并持续领先；
- 板块修复而它仍落后；
- 关键平台、昨日低点或盘前失败位被持续破坏。

### 11.7 常见弱转强路径，不是固定形态公式

| 前态 | 次日可观察路径 | 仍需确认 |
| --- | --- | --- |
| 阴线或大分歧 | 放量高开，卖压后继续向上 | 同组领先和板块响应 |
| 低开预期 | 实际不杀，快速拉红并抬高低点 | 不是指数先拉后的跟随 |
| 平台突破烂板 | 高开或下探后重新站回突破位 | 继续突破而非假修复 |
| 炸板回落 | 环境修复时率先反包 | 前一日确为外部拖累候选 |
| 跌停或极弱预期 | 竞价、开盘显著脱离原弱势 | 只适用于仍有角色和结构的核心候选 |

任何一行都不能脱离节点、角色和竞争组单独触发动作。

### 11.8 主动进攻怎样判断 `[S/R]`

至少需要下面的事件链：

1. 指数、板块或同组尚未明显修复；
2. 目标先停止跟跌或先稳住；
3. 目标出现持续向上的成交和价格推进；
4. 目标率先翻红、突破、上板或回封；
5. 目标走强以后，板块、容量或同组出现响应；
6. 目标不是很快跌回原位。

可复用的核心关系是：指数或板块仍在恐慌中 → 目标先不跟跌 → 持续向上推进 → 完成突破或上板 → 指数、板块或同组随后改善。

若只有一分钟线，可确认价格事件顺序；若要写“主动买单持续”，需要逐笔成交；若要写撤单者和挂单意图，需要更完整委托数据。

### 11.9 被动回落、被动分歧和被动反抽

#### 被动回落/被动分歧候选 `[K]`

作者多次用以下关系解释个案：

```text
大盘或板块先广泛走弱
→ 目标随后回落或炸板
→ 目标不是本组最先走弱者
→ 原角色和关键结构暂未破坏
→ 次日环境修复时目标率先收回
```

前四项只能形成“被动候选”，次日率先修复才是关键验证。板块修复而目标不修复时，不得继续用“被动”替它辩护。

#### 被动反抽 `[S]`

新核心或更强对手先拉升、突破或上板，旧核心随后才被反推。即使旧核心涨幅很大，只要没有重新领涨和带动，仍属于角色降级后的反抽候选。

#### 无法确认的情况

只有日 K、没有同步板块时间轴，无法知道谁先走弱；只能写“收盘回落”，不能写“被动回落”。

### 11.10 主动分歧和主动炸板的边界

#### 主动分歧 `[K]`

原文至少出现两类语境：

- 已经突破并处于主升中的核心，第一次出现放量分歧；
- 临界爆发前，竞价先给出可承接分歧，随后快速转强。

这更像对“位置合适、后续可修复的分歧”的案例命名，不等于资金主观故意下跌。系统应记录位置、卖压、收回和次日任务，不推断动机。

#### 主动炸板 `[K]`

现有语料只在少数案例中使用过该标签，没有统一定义：

- 没有通用订单流模式；
- 没有统一撤单/卖单阈值；
- 没有完整说明炸板发起者；
- 不能把“股票先炸”自动叫主动炸板。

工程输出只能是：

- 列出可观察事件顺序；
- 标记“符合局部案例关系，但尚无通用分类”；或
- 输出“无法确认主动/被动炸板”。

### 11.11 资金迁移只能做条件化判断 `[R]`

价格和板块时间轴可以支持：旧方向先弱、新方向后主动增强、随后旧方向资金活跃度下降。但公开行情通常不能证明同一笔资金从 A 板块转入 B 板块。

因此只允许写：

- “路径切换候选”；
- “新方向在旧方向走弱时主动承接市场注意力”；
- “成交和强势家数同步转向”。

禁止写“商业航天资金确定流入人脑工程”，除非有可验证的账户级或资金流证据。

### 11.12 Stage 9 必须输出

```text
竞价结论是否保留：
第一轮卖压路径：
预先标记的关键位表现：
承接状态：候选 / 确认 / 假承接 / 数据不足
目标与对手、板块、容量的事件顺序：
弱转强状态：候选 / 确认 / 失败 / 不适用
主动性证据级别：价格路径 / 逐笔成交 / 委托队列
角色任务完成情况：
路径结论：确认 / 延后 / 取消 / 数据不足
下一步允许等待的动作：
```

下一步：只有环境、路径、节点、角色、竞争和开盘验证没有失效，才进入具体动作选择。

## 12. Stage 10：选择低吸、半路、回封、尾盘确认或不行动

### 12.1 动作不是另一套选股逻辑

股票必须先通过 Stage 0—9。动作只回答“确认发生在什么位置”，不能用某个形态把前面的主流、节点和角色全部跳过。

```text
先确定为什么是它
→ 再确定今天必须完成什么
→ 再看确认发生在回踩、突破、开板还是尾盘
→ 最后选择对应动作
```

### 12.2 低吸候选 `[S]`

#### 必须前提

- 主流、核心或明确节点已经成立；
- 盘前已标记回踩参照；
- 角色没有被替代；
- 板块没有进入明确退潮。

#### 可用参照

- 昨日低点或前一日分时支撑；
- 当日第一轮卖压低点；
- 刚突破的平台或阴线高点；
- 五日线或趋势重心；
- 分时均价。

这些不是同等优先的固定列表。必须说明为什么当前参照与这只股票的结构和角色有关。

#### 触发链

```text
回踩预定位置
→ 不再继续下破
→ 出现低点抬高、拐头、翻红或重新站回关键位
→ 板块和同组没有否定
→ 继续向上确认
```

只有跌到支撑附近，没有停止下跌和向上拐头，不叫低吸。

#### 取消

- 支撑被持续跌破；
- 反抽不能站回；
- 板块和容量同步走弱；
- 同组新核心已经接管；
- 需要分钟数据但数据缺失。

### 12.3 半路候选 `[S]`

#### 必须前提

- 盘前已标出平台、前高、阴线高点、开盘第一波高点或其他阻力；
- 候选属于有效路径和角色竞争组；
- 不是看见涨速后才临时找理由。

#### 触发链

```text
接近预定阻力
→ 成交持续放大并越过
→ 突破后站稳或回踩不破
→ 继续主动推进
→ 板块、容量或同组产生支持
```

半路确认必须先吸收前日抛压并企稳，再突破预定阻力；容量确认还必须看到分时与指数或板块的同步关系和外部带动，竞价本身只表示待验证态度。

#### 取消

- 一笔直线拉升后立即跌回；
- 只刺穿阻力，没有站稳；
- 板块先涨、它只是后跟；
- 突破发生在已明显高位推进失败的结构中；
- 角色任务已经由别的股票完成。

### 12.4 开板分歧和回封候选 `[S]`

#### 必须前提

- 第一次上板本身有节点、角色和板块意义；
- 开板前候选没有已经落后；
- 不是为了给任何炸板找理由。

#### 观察顺序

1. 谁先导致开板：市场、板块还是个股自身；
2. 开板后下探幅度和成交路径；
3. 是否出现真实换手而非流动性突然消失；
4. 是否重新收回涨停附近；
5. 回封时板块和同组是否仍支持；
6. 回封后是否再次快速打开。

#### 确认

卖压出现后被真实成交吸收，股票重新封住，并仍完成其角色任务。

#### 取消

- 反复开板且重心下移；
- 板块已经转弱；
- 同组新对手先完成任务；
- 炸板后无法重新封住；
- 只有作者式“被动炸板”主观标签，没有实际承接。

### 12.5 尾盘确认候选 `[K]`

尾盘不是固定时间买点。必须明确在等哪一种确认：

- 当日涨幅是否避开有效异动或监管触发；
- 主流分歧是否真正回流；
- 突破到收盘是否仍保持；
- 高位核心是否从修复重新转为滞涨；
- 当日强势是否能够带给次日可验证预期。

不同目的需要不同数据，作者没有统一的“几点以后、多少成交”规则。

### 12.6 一字或无法成交怎样处理 `[R]`

- 一字可以验证方向和角色强度；
- 不能在回测中默认能够按涨停价成交；
- 若竞价或开盘打开，必须重新经过卖压、换手和回封判断；
- 不因买不到核心，就自动买后排跟风。

### 12.7 动作之间怎样选择

| 确认发生的位置 | 动作候选 | 核心证据 |
| --- | --- | --- |
| 回踩关键位后停止下跌并拐头 | 低吸 | 支撑、承接、角色仍有效 |
| 越过预定阻力并主动推进 | 半路 | 突破、站稳、板块响应 |
| 上板后经卖压和换手重新封住 | 回封 | 首板意义、承接、重新封住 |
| 必须等收盘才能确认监管、回流或突破保持 | 尾盘确认 | 等待事项已盘前写明 |
| 任一前提或数据不足 | 不行动 | 无法形成完整证据链 |

同一只股票可能先出现低吸候选、随后出现半路确认；也可能竞价强但开盘失败，所有动作取消。不能因为错过早期位置，就降低后续确认标准追入。

### 12.8 强制不行动条件

- 环境、方向或节点未确认；
- 竞争组不完整，无法知道谁真正胜出；
- 竞价和开盘路径相互否定；
- 只有个股强，板块、容量和同组不支持；
- 弱转强只停留在高开，没有承接；
- 突破只是一笔脉冲；
- 炸板没有回封；
- 新旧核心一起弱；
- 动作依赖的数据缺失；
- 无法写出动作取消条件；
- 核心无法成交，而替代品只是后排。

### 12.9 Stage 10 必须输出

动作对象只能是 Stage 8 已选中的 `current_action_candidate`，最终只能输出一只股票或 `NONE`。Stage 10 只选择触发方式，不重新选股。

```text
动作对象：
动作类型：低吸 / 半路 / 回封 / 尾盘确认 / 不行动
它来自哪个路径、节点和竞争组：
动作前已确认的事实：
本次具体触发：
同步验证对象：
立即取消条件：
尚未确认的风险：
```

本手册只输出研究动作和失效条件，不输出用户仓位比例，也不执行交易。

## 13. Stage 11：持有、角色迁移和退出

### 13.1 持有的真正理由

持有不是因为成本低、已经盈利或曾经被叫做龙头，而是：

- 所属路径仍然成立；
- 当前节点尚未结束；
- 股票仍完成角色任务；
- 同组没有更主动的替代者；
- 板块的容量、助攻和扩散没有共同恶化；
- 次日买方仍得到反馈；
- 监管、催化和结构没有否定原逻辑。

任何一项变化，都要重新判断持有层级。

### 13.2 盘中持有检查顺序

#### 第一层：动作触发有没有立即失败

- 低吸后支撑继续破坏；
- 半路突破后迅速跌回；
- 回封后再次打开并重心下移；
- 尾盘等待事项最终没有确认。

动作自身失败时，不能用更长期题材逻辑掩盖。

#### 第二层：角色有没有继续完成任务

- 总核心是否继续组织或率先修复；
- 容量是否继续推进并稳定重心；
- 助攻是否继续给溢价和扩散；
- 补涨或伴生是否继续胜出；
- 二波载体是否保持主动；
- 旧核心是否只剩被动反抽。

#### 第三层：板块路径有没有被市场推翻

核心、容量、助攻和板块指数分别记录。不能因单票尚未下跌，就忽略整条路径已退潮。

### 13.3 角色迁移的盘中处理

```text
旧角色先未完成任务
→ 新候选先主动增强
→ 板块响应新候选
→ 旧角色只能被反推
→ 新排序在后续时段或次日继续成立
```

- 前三项出现：新角色接管候选；
- 后续继续确认：角色正式迁移；
- 新旧一起弱：方向退潮，不是迁移；
- 旧角色重新先修复并带动：原角色保留；
- 缺同时间轴：只写迁移待确认。

### 13.4 退出信号按原理由失效处理

#### A. 该强不强 `[S]`

本应高开、摸板、晋级、修复、带动或给溢价，却没有完成。优先按预期失败处理，不必等固定均线。

稳定关系是：前一日角色和力度决定次日任务；任务失败后，若反抽不能恢复主动与带动，则反抽只提供处理窗口。

#### B. 角色被替代 `[S]`

新核心先主动，旧核心随后被反推；或原唯一性因新对手、监管和失去带动而取消。旧核心的残余人气更偏退出窗口，不自动视为重新买点。

#### C. 板块秩序恶化 `[R]`

分别检查核心、容量、助攻、低位扩散和板块指数。作者没有规定“失效几项就退出”，因此只能描述哪些关系在恶化，以及哪项直接破坏原路径。

#### D. 高位推进失败 `[S]`

组合证据包括：

- 高位放量但价格不再推进；
- 涨停附近封不住或反复打开；
- 修复高点逐次降低；
- 板块高潮时核心反而背离；
- 同批助攻大跌；
- 反抽不能创新高；
- 竞价初始假强、最终不按角色开盘。

单一十字星、孕线、巨量或背离只能是风险提示，不能自动宣判顶部。

#### E. 结构破坏 `[S/X]`

平台、突破位、趋势重心、前一日关键支撑或五日线被有效破坏，且不能快速收回。

作者对五日线存在冲突口径：有时作为主升生命线，有时在角色和板块已经转弱时要求跌破前先处理。因此必须结合环境与角色，不能统一成唯一止损。

#### F. 催化、监管和环境失效 `[S/M]`

- 催化已经充分传播或兑现；
- 产业或公告事实被证伪；
- 有效监管空间收窄且没有内部新载体；
- 市场由主升转轮动，或由轮动转系统性下跌。

这些变化会缩短持有周期或直接取消原路径。

### 13.5 左侧退出与右侧退出

#### 左侧退出 `[S]`

依据：明确的不及预期、角色被替代、监管空间、修复衰减、高位背离或板块与核心的顶部共振。在结构完全破坏前先处理。

#### 右侧退出 `[S]`

依据：平台、趋势重心或关键支撑已经有效跌破，反抽不能收回后处理。

盘前必须说明该候选主要采用哪一种退出逻辑。不能上涨时说等右侧、下跌后又声称早有左侧信号。

### 13.6 “借反抽退出”的使用边界 `[S/R]`

适用前提：

- 角色或预期已经失败；
- 股票仍有足够辨识度和流动性；
- 市场没有继续快速系统性杀跌；
- 反抽没有重新夺回主动和角色。

反抽如果由新核心带动，更证明旧核心被动。若价格持续下坠、没有反抽或风险继续扩大，不能为了等待理想价格而忽略已经触发的失败。

### 13.7 收盘后必须重新计算

收盘后不继承持仓立场，重新回答：

1. 今天动作触发是否有效；
2. 股票是否完成角色任务；
3. 竞争组排序是否变化；
4. 方向状态维持、升级、降级还是结束；
5. 今日买方明天需要得到什么反馈；
6. 是否出现新的助攻、补涨、伴生或容量接棒；
7. 催化和监管事实是否变化；
8. 下一交易日的主路径、替代路径和不行动路径是什么。

`[R]` 增加一个去持仓偏见问题：如果现在没有持仓，仅根据收盘事实，明天还会不会把它列入同一优先级。这个问题用于审计，不冒充作者原话。

### 13.8 状态账本必须更新

| 对象 | 收盘后更新内容 |
| --- | --- |
| 市场 | 环境状态、相对昨日变化、买方反馈 |
| 方向 | 启动/延续/主升/分歧/修复/退潮状态 |
| 节点 | 是否成立、完成、失败或等待确认 |
| 角色 | 候选、确认、迁移、降级或失效 |
| 竞争组 | 完整候选、当前排序、唯一性状态 |
| 个股任务 | 今日完成情况、明日新任务、失败条件 |
| 路径 | 主路径、替代路径、不行动条件 |
| 数据 | 缺失项和因此禁止的结论 |

这个账本是下一交易日 Stage 0 的唯一历史状态来源。不能用原帖或未来结果补回去。

### 13.9 Stage 11 必须输出

```text
原持有理由：
今日路径状态：
今日角色任务完成情况：
同组排序与角色迁移：
继续有效的事实：
已经失效的事实：
处理结论：继续观察 / 降级 / 退出候选 / 已失效 / 数据不足
采用左侧还是右侧逻辑：
明日重新验证任务：
账本更新：
```

处理结论只描述研究状态，不给出仓位数字，也不自动执行买卖。

## 14. 特殊概念的操作边界

本章处理原帖中容易被口号化的词。这些概念不是独立选股器，也不能绕过 Stage 0—11。它们只能帮助 AI 描述环境、节点、价格行为或动作方式。

统一纪律：

```text
先确认环境、方向、节点、角色和竞争组
→ 再判断特殊概念是否适用
→ 把概念翻译成可观察事实
→ 写出反方解释和下一步确认
→ 未确认时只保留候选状态
```

禁止仅凭“反人性、冰剑、瓶底、洗盘、低熵”等词直接生成最终选择。

### 14.1 反人性：不是逆势抄底 `[S/R]`

#### 它真正描述什么

稳定含义是：市场多数可见行为已经偏向某种旧预期，但节点、角色和价格事实出现了可验证的相反变化。交易者不跟随表面恐慌或亢奋，而是等待新的市场选择得到确认。

“别人害怕我就买”“跌得多所以反人性”都不是完整逻辑。

#### 必须观察

1. **旧预期是什么：** 连续亏钱效应、板块一致恐慌、旧高标惩罚、高潮后一致看多，或前一日强弱惯性；
2. **节点是否存在：** 必须属于 G1—G12 中可确认的节点，不能凭情绪想象节点；
3. **谁在逆旧预期：** 是高度核心、容量核心、修复核心还是同组唯一性候选；
4. **相对强度：** 它是否先停止跟跌、先转强、先突破或在同组中保持任务；
5. **外部响应：** 板块、容量、助攻或指数是否随后响应；
6. **真实卖压：** 竞价展示之后，开盘卖压能否被接住。

#### 推断顺序

```text
旧预期清楚
→ 合法节点存在
→ 候选承担稀缺角色
→ 候选先于参照物逆转
→ 开盘真实卖压后仍保持
→ 板块或同组响应
→ 才能确认反人性节点有效
```

前四项出现时只能输出 `COUNTER_CONSENSUS_CANDIDATE`。开盘确认和外部响应出现后，才可以写“反人性节点得到市场验证”。

#### 取消

- 系统性下跌仍在加速，候选与核心一起破位；
- 只有低开或下跌，没有停止下跌和主动修复；
- 候选只是指数先反弹后的跟随；
- 竞争组中已有更主动者完成任务；
- 所谓“市场都恐慌”没有可观察事实支持。

#### 下一步

回到对应节点和角色：恐慌修复看 G11，情绪破局看 G1/G8，主流分歧修复看 G6。反人性本身不决定选择哪只股票。

### 14.2 分歧：先说明谁在什么范围内分歧 `[S/R]`

#### 四个不同对象

| 对象 | 可观察事实 | 不能混写成什么 |
| --- | --- | --- |
| 市场分歧 | 指数往返、涨跌家数分化、炸板与跌停增加、昨日强势反馈恶化 | 某只股票炸板 |
| 方向分歧 | 板块指数回落、前后排分化、核心与容量不同步、涨停成功率下降 | 全市场退潮 |
| 竞争组分歧 | 同任务候选有人晋级、有人落后，排序变化 | 板块整体结束 |
| 个股分歧 | 放量震荡、开板、冲高回落、阴线或关键位反复争夺 | 自动等于洗盘或出货 |

#### 每次必须写明

```text
分歧对象：
开始时间：
直接参照物：
价格变化：
成交变化：
核心、容量、助攻分别怎样：
关键结构是否破坏：
下一时点需要谁先修复：
```

#### 怎样判断良性还是破坏性

分歧发生当天通常不能直接定性。按下面顺序等待：

1. 分歧中是否仍有前排、核心或容量维持热度；
2. 卖压后关键结构是否保留；
3. 次日原核心是否率先修复；
4. 容量和板块是否响应；
5. 修复是否抬高重心；
6. 新参与者是否继续得到奖励。

能够换手、修复并继续推进，才是良性分歧候选；核心、容量和助攻一起恶化且修复失败，则是结构破坏或退潮候选。

### 14.3 共振：多个独立层级共同确认 `[S/R]`

#### 最低定义

共振不是“几个指标都好看”，而是两个以上相对独立的市场层级在同一观察窗口内共同支持同一路径。

可用层级包括：

- 市场指数或风险偏好；
- 方向指数、涨停宽度和成交活跃度；
- 情绪或高度核心；
- 容量核心；
- 助攻、中间梯队和低位扩散；
- 可核实的政策、公告或产业催化。

#### 必须记录事件时间

```text
最先变化的对象
→ 第二个响应对象
→ 容量是否加入
→ 板块宽度是否扩大
→ 是否保持而非瞬时脉冲
```

同一时刻共同上涨只能确认“同步”，不自动证明谁带动谁。要判断主动带动，仍须使用 Stage 9 的事件顺序。

#### 输出级别

| 状态 | 条件 |
| --- | --- |
| `SINGLE_STOCK_MOVE` | 只有单票变化 |
| `PARTIAL_RESONANCE` | 两个层级同向，但容量、板块宽度或持续性未确认 |
| `RESONANCE_CONFIRMED` | 核心、容量或板块至少两个关键层级共同保持，并完成当前路径任务 |
| `FALSE_RESONANCE` | 同步只持续极短时间，随后各层级重新分散或反向 |
| `DATA_INSUFFICIENT` | 缺少同时间轴板块或关键角色数据 |

只有小票上涨、容量缺席、板块指数不响应时，不得写“板块共振”。

### 14.4 分离与强弱切换：必须先有原竞争关系 `[S/R]`

#### 分离前提

1. 两只股票属于同一竞争组，或确实在争夺同一资金承接功能；
2. 已知它们分离前的排序和各自任务；
3. 使用相同截止时间和同精度数据；
4. 有可以比较的关键事件：停止跟跌、翻红、突破、上板、回封、失守。

#### 分离确认链

```text
原来同向或可比
→ A 先失去任务或继续走弱
→ B 在 A 未修复时先主动增强
→ B 保持推进而非一笔脉冲
→ 板块或相关角色响应 B
→ 后续时段或次日继续承认新排序
```

前三项只构成 `SEPARATION_CANDIDATE`。板块响应和后续确认出现后，才是强弱切换确认。

#### 不能确认的情况

- 一个上涨、一个下跌，但原本不在同一竞争关系；
- 板块先整体上涨，两只股票只是涨幅不同；
- 新候选冲高后立即回落；
- 旧核心先拉升，新候选随后跟随；
- 只有收盘日线，没有盘中同时间轴。

强弱切换不仅要求“新强旧弱”，还要求新候选接过原任务，例如打开空间、稳住重心、修复板块或扩散赚钱效应。

### 14.5 上升停顿：只能先标记方向待定 `[X]`

作者存在两种明确口径：

- 上涨后出现停顿、该涨不涨或向下变盘，可作为降低观察和退出信号；
- 上升停顿也可能是控速、换手、消化浮筹和二次突破前的蓄力，并不自动等于趋势结束。

稳定交集是：上涨速度停止以后，下一段方向尚未确认，必须等待向上或向下的市场选择。

#### 进入条件

- 此前存在可确认的上涨段或主升段；
- 价格推进速度明显降低，出现十字、窄幅整理、横盘、冲高不创新高或量价不再同步；
- 当前还没有足够证据确认继续突破或结构破坏。

统一输出：`PAUSE_PENDING_DIRECTION`。

#### 向上确认

- 关键支撑保留；
- 整理期间重心没有持续下移；
- 重新放量突破预先标记的阻力；
- 回踩不破并继续推进；
- 原角色与板块重新响应。

可以升级为“空中加油或二次启动候选”。

#### 向下确认

- 竞价或开盘出现该强不强；
- 跌破关键支撑或前一日有效站位；
- 反抽不能收回；
- 同组新候选先走强并接管任务；
- 核心、容量或助攻同步恶化。

可以降级为“推进失败或退出候选”。

不得看到一根十字星就直接判断洗盘，也不得看到横盘就自动判顶。

### 14.6 巨量：位置、价格结果和次日反馈必须一起看 `[K]`

作者没有给出跨股票通用的巨量倍率。系统只记录相对事实，不设置“超过多少倍必然如何”的 roubing 规则。

#### 必须比较

1. 当日成交相对自身近期成交分布；
2. 成交额和换手相对自由流通规模；
3. 处于低位、平台突破、主升途中还是高位加速后；
4. 巨量当天价格是推进、滞涨、回落还是承受分歧后站稳；
5. 巨量后次日竞价、开盘和收盘反馈；
6. 同组、板块和容量是否同步确认。

#### 四种候选解释

| 位置与价格结果 | 只能形成的候选 | 下一步验证 |
| --- | --- | --- |
| 低位首次明显放量且价格站稳/突破 | 成本重置或资金确权候选 | 次日不重回原跌势，继续推进并带动 |
| 低位放量但冲高大幅回落 | 分歧未决 | 能否收回、是否只是消息脉冲 |
| 高位放量且价格继续有效推进 | 高位换手延续候选 | 次日仍给溢价、角色不失效 |
| 高位放量滞涨、助攻转弱 | 推进失败或派发风险候选 | 竞价能否修复、反抽能否创新高 |

“吸筹、派发、锁仓”涉及账户动机，公开量价不能直接确认。输出必须使用“候选解释”，不能把主力意图写成事实。

### 14.7 洗盘与出货：只能通过后续结果区分 `[S/K/R]`

#### 洗盘候选的可观察关系

- 原方向、角色和上升结构此前成立；
- 调整期间关键支撑没有持续破坏；
- 缩量回调、反复上影或借市场恐慌回踩，但收盘和重心仍可维持；
- 突破后回踩能重新站回；
- 市场或板块继续弱时，目标先停止跟跌；
- 后续出现弱转强、重新突破或继续带动。

只有前五项时仍是 `WASHOUT_CANDIDATE`；最后一项出现才算“调整后重新走强得到验证”。

#### 出货风险候选的可观察关系

- 已处高位或经历连续加速；
- 前一日极强，次日竞价明显低于逐票任务且不能快速修复；
- 放量但价格滞涨，日内高点形成后长期不能夺回；
- 同批助攻、容量或后排持续大跌；
- 板块有修复机会但它不修复；
- 次日买方反馈继续恶化。

组合出现时可输出 `DISTRIBUTION_RISK_CANDIDATE` 或“高位推进失败”，但不能声称已经知道某个主力账户正在出货。

#### 强制反方检查

每次判断必须同时回答：

- 如果这是洗盘，下一步必须出现什么重新走强行为？
- 如果这是出货风险，什么修复事实会推翻该判断？
- 当前结论依赖日线、分钟、逐笔还是委托数据？

图形相似不能代替环境、位置、角色与次日反馈。

### 14.8 超买、超卖、背离和等距浪：只做辅助，不做独立开关 `[K/R]`

#### 作者没有统一给出的内容

- RSI、KDJ、MACD 等采用哪个指标；
- 指标参数；
- 60 分钟、日线、周线哪个级别优先；
- 超买或超卖阈值；
- 背离需要持续几根 K 线；
- 第一波和第三波如何精确确定起终点；
- 等距允许多大误差。

因此，这些内容不能被写成作者的固定算法。

#### 工程可怎样使用

工程可以保存带版本的辅助特征，例如：

```text
indicator_name
parameter_version
timeframe
value
reference_window
signal_time
```

但输出必须写成：

- 超卖修复候选；
- 超买或高位风险候选；
- 价格—成交或价格—指标背离候选；
- 等距浪案例相似候选。

#### 必须叠加的市场确认

- 超卖：跌速放缓、跌停不再扩散、候选先停止跟跌、出现板块修复；
- 超买：角色推进失败、容量和助攻恶化、修复高点降低；
- 背离：第二次推进不能突破或量能/动能衰减，随后出现结构破坏；
- 等距：只能作为落袋和风险检查线索，还须检查催化、量能、角色和板块。

第一波与第三波等距只得到单篇案例支持，禁止变成全市场自动顶部公式。

### 14.9 效应复制：复制完整关系，不复制股票名字和 K 线 `[S/K/R]`

#### 一个可复制效应必须先形成模板

```text
效应发生时的环境
节点前态
方向状态
候选承担的角色
真正竞争组
当日触发
次日买方反馈
失效条件
```

只有前一个样本已经得到次日或后续反馈，才可以建立“效应模板”。当天看到一只股票上涨，不能立即把其他相似股票叫效应复制。

#### 新候选匹配顺序

1. 当前环境是否与模板允许的环境一致；
2. 是否存在同类节点，而不只是 K 线相似；
3. 新候选是否承担同一角色任务；
4. 是否属于完整竞争组中的胜出候选；
5. 竞价和开盘是否完成同类触发；
6. 板块热度和买方反馈是否仍在；
7. 当前是否已经出现多次复制后衰减。

前五项出现可标 `EFFECT_REPLICATION_CANDIDATE`。必须继续用下一日反馈检验。

#### 必须保存失败对照

作者没有给出效应复制何时耗尽的通用算法，也缺少同期失败对照。工程必须保存：

- 所有匹配模板的候选；
- 最终成功和失败者；
- 失败发生在哪一环；
- 第几次复制以后反馈开始衰减。

不能只用后来成功的股票证明“模式一直有效”。

### 14.10 冰剑：是动作层的攻守分类，不是选股源 `[K/R]`

#### 冰：确认后的低吸防守

适用：有效趋势、主流或核心路径仍在，等待市场回落到预先标记的支撑后确认承接。

```text
有效路径和角色
→ 预先标记支撑
→ 回踩
→ 停止下跌并拐头
→ 重新站回或继续推进
→ 冰式低吸候选
```

只有“价格跌了”不属于冰；没有支撑、承接和角色确认时禁止行动。

#### 剑：确认后的主动突破

适用：有效路径中出现超预期破局、平台突破或强弱切换。

```text
有效路径和角色
→ 预先标记阻力
→ 放量越过
→ 保持主动推进
→ 板块或同组响应
→ 剑式进攻候选
```

只有涨速或一笔直线拉升不属于剑。

#### 离场闭环

- 冰式触发后支撑继续破坏；
- 剑式突破后迅速跌回；
- 上升停顿向下确认；
- 角色被替代；
- 板块路径结束。

冰剑不能绕过 Stage 1—7 生成候选，也不能替代 Stage 8—10 的竞价、卖压和动作确认。

### 14.11 瓶底：只能建立中周期方向假设 `[K/R]`

#### 六层事实必须分开核验

| 层级 | 需要的独立事实 | 不能使用的替代物 |
| --- | --- | --- |
| 产业周期 | 产品、技术、供需、价格或产业里程碑 | 作者帖子中的产业断言 |
| 政策定位 | 正式政策原文、发布时间和生效范围 | 新闻标题或转述 |
| 估值位置 | 可复现估值序列及同行比较 | 单纯股价低 |
| 资金供需 | 成交、换手、融资或可核验资金结构 | “主力吸筹”主观描述 |
| 高低切换 | 高位旧方向衰减、新方向主动增强的时间轴 | 两个板块一涨一跌的收盘截图 |
| 筹码结构 | 历史成交密集区、换手和成本重置代理 | 声称筹码已经洗干净 |

作者没有给出六层因素的固定权重。系统不得计算一个冒充作者方法的“瓶底总分”。

#### 允许的推断

```text
多层底部事实候选
→ 形成中周期方向研究假设
→ 回到 Stage 2 检查市场是否实际开始交易该方向
→ 由节点生成候选
→ 容量、核心、竞争和买点继续确认
```

仅仅冷门、超跌、估值低或长期横盘，不能确认瓶底。瓶底假设正确，也不代表当天存在动作机会。

#### 取消

- 政策或产业事实被证伪；
- 估值低但盈利继续恶化，原比较基础失效；
- 资金没有进入，价格继续形成新低；
- 只有消息脉冲，没有方向持续性；
- 新方向不能形成核心、容量和扩散。

### 14.12 低熵秩序：是结构比喻，不是数学熵分数 `[S/R]`

作者所说的低熵，是市场暂时从杂乱轮动变成可识别、可验证的资金秩序。它不等于信息论意义上的熵，也没有原文公式。

#### 可观察的有序结构

1. 方向连续，不是每天更换；
2. 总核心或情绪核心负责打开空间；
3. 容量核心或中军稳定板块价格重心；
4. 助攻和低位扩散把赚钱效应向外传递；
5. 分歧后存在清楚的修复顺序；
6. 次日买方持续得到奖励；
7. 原核心疲劳时，内部新载体有序接棒；
8. 角色和节奏能够提前写出可证伪任务。

#### 无序或高熵候选

- 热点每天轮换；
- 只有随机单票脉冲；
- 高度、容量和助攻互相否定；
- 昨日强势股连续没有奖励；
- 核心高位滞涨，容量和后排批量掉队；
- 修复高点逐次降低；
- 新旧主线都无法建立角色协同。

#### 使用方式

低熵结构是 Stage 1 环境和 Stage 2 主流判断的总结结果，不是另一个评分模型。系统可以逐项记录结构是否存在，但不得把未经回测的加权结果称为“低熵指数”。

### 14.13 特殊概念统一输出

```text
概念名称：
适用的环境、方向、节点和角色：
看到的原始事实：
直接参照物与事件顺序：
当前状态：候选 / 确认 / 失败 / 不适用 / 数据不足
最强反方解释：
需要下一步确认的行为：
取消条件：
该概念禁止推出的结论：
```

如果一个特殊概念不能被翻译成上面这些字段，它就只能保留为离线研究词，不能进入每日推理。

## 15. 数据获取、落库与结论降级

本章是本手册的唯一数据入口。前面各阶段写的是“需要看什么”，本章说明“从哪里取得、保存成什么、缺少时还能判断到哪一层”。

本章接口能力核对基准：

- Financial-API：`https://github.com/HiThink-Tech/Financial-API`，核对提交 `44b7aa34dd504675f3ddaa15b3d478ea16f97884`；
- eltdx：`https://github.com/electkismet/eltdx`，核对提交 `20a1eefaefbb1b66a75579efb6de858dca818cb0`；
- 核对日期：2026-09-10。

接口版本以后发生变化时，必须先重新运行能力验收并更新 `data_contract_version`，不能根据本章旧方法名盲目调用。

### 15.1 数据层的五条总纪律 `[R]`

1. **事实与推理分开：** 行情、公告、规则写入事实表；主流、角色、节点和唯一性写入推理表，绝不互相覆盖。
2. **原始值与派生值分开：** 开盘价、成交额等保存原值；相对昨日成交、同组排名等另存派生字段，并记录算法版本。
3. **不同来源不静默合并：** 两套接口冲突时分别保存，说明最终采用哪个来源及原因。
4. **空值不是零：** `null`、空集合、接口错误、非交易日和“不适用”必须区分。
5. **每条事实可追溯：** 必须保存来源、方法或端点、请求参数、业务发生时间、抓取时间、请求 ID 或原始记录 ID。

### 15.2 Financial-API 与 eltdx 的明确分工

| 数据任务 | 首选来源 | 校验或备用来源 | 能解决什么 | 仍不能解决什么 |
| --- | --- | --- | --- | --- |
| 全市场多年日线 | Financial-API Market Dumps | eltdx 日 K | 历史价格、量额、复权、区间状态 | 盘中事件顺序 |
| 少量个股日线 | Financial-API 历史 K 线 | eltdx `bars.get()` | 逐票结构和临时补数 | 全市场高频逐股拉取效率低 |
| 指数和板块日线 | Financial-API 指数历史 K 线 | eltdx 指数 K 线 | 方向日线趋势 | Financial-API 不提供历史分钟 |
| 板块目录和当前成分 | Financial-API 板块目录/成分 | eltdx 概念板块 | 当前方向归组参考 | 不能恢复过去未保存的历史成分 |
| 历史涨停、跌停、炸板及原因 | Financial-API 特色数据 | eltdx F10 涨跌停列表 | 每日梯队、最终状态、涨停原因 | 原因是市场标签，不是因果证明 |
| 当日实时涨停梯队和封单 | eltdx 实时梯队 | Financial-API 当日涨停池 | 盘中梯队与候选监控 | 单次快照不能还原全部过程 |
| 09:15—09:25 竞价过程 | eltdx 竞价序列 | Financial-API `stage=live` 当前快照 | 价格、匹配量、未匹配量和排序迁移 | 历史留存不保证；快照不能代替序列 |
| 09:25 正式撮合 | eltdx `auction_data()`/opening match | Financial-API `stage=final` | 正式开盘价、量和金额 | 不能由结果反推中途撤单 |
| 历史 09:25 撮合 | eltdx `opening_match_history()` | 无稳定完整备用 | 可得日期的正式开盘 | 缺失日期属于真实数据缺口 |
| 分钟线 | eltdx `minutes.today/history()` | 无 | 下探、收回、低点抬高和分钟顺序 | 不能严格确认主动买卖和撤单意图 |
| 成交明细 | eltdx `trades.all_today/all_history()` | 无 | 更细成交事件顺序 | 不是完整逐笔委托队列 |
| 实时五档 | eltdx `full_quotes()` | 无 | 抓取时刻盘口和瞬时流动性 | 不连续采样就不能历史回放 |
| 个股长期题材 | eltdx F10 热点题材 | Financial-API 涨停原因 | 公司与题材关联 | 不能直接证明当天为何上涨 |
| 当日交易题材 | Financial-API 涨停原因 | eltdx 涨跌停原因 | 当日市场归组入口 | 仍需板块价格行为确认 |
| 公告发现 | eltdx 公告列表 | 交易所、巨潮原文 | 找到公告标题、时间和链接 | 列表摘要不能替代正式原文 |
| 监管规则 | 交易所、证监会正式规则库 | 软件计算值只作校验 | 当时有效涨跌停、异动和监管口径 | 不能拿现行规则回算所有历史 |

历史“主流”不在任何接口中。它必须由 Stage 1—2 使用逐日事实推演得到。数据源只能提供证据，不能返回“主流、龙头、卡位、伴生、二波”答案。

### 15.3 Financial-API 接入说明

#### 15.3.1 认证和响应

REST 基址：`https://fuyao.aicubes.cn`。公开数据端点当前使用 `GET`，认证头为 `X-api-key`。

统一响应：

```json
{
  "code": 0,
  "message": "...",
  "request_id": "...",
  "data": {}
}
```

只有 HTTP 200 且 `code == 0` 才算成功。`data=null`、空数组和字段 `null` 都不得补成 0。

API Key 放在环境变量 `HITHINK_FINANCE_API_KEY` 或系统凭据库，不得写入代码、文档、日志或 Git。

常见错误处理：

| 错误 | 处理 |
| --- | --- |
| `1001` | 补充必填参数 |
| `1002` | 修正参数格式 |
| `1003` | 缩短时间窗口或分页 |
| `2001/2003` | 检查认证和权限 |
| `3001` | 对股票代码、资产类型和交易所消歧 |
| `3002` | 保留 `request_id`，稍后重查 |
| `4001` | 有上限的退避重试 |
| `5xxx` | 有上限的重试并保留错误事实 |

任何错误都不能触发模拟数据或 AI 补值。

#### 15.3.2 代码表和交易日历

```text
GET /api/meta/tickers/search?q=贵州茅台&asset_type=a-share&limit=5
GET /api/meta/tickers/list?exchange=SH,SZ,BJ&asset_type=a-share&limit=1000&offset=0
GET /api/a-share/calendar/trading-days
```

主要字段：`thscode`、`ticker`、`name`、`exchange`、`asset_type`、`currency`。

- 名称或纯代码命中多个资产时，按资产类别和交易所消歧；
- 完整 A 股代码表必须显式包含 `SH,SZ,BJ`；
- 代码表按 `limit/offset` 完整分页；
- 交易日历当前只覆盖上海时区最近一年。更早日期由全量日线实际交易日期补建，再与可得官方日历核对。

#### 15.3.3 个股快照和历史日线

```text
GET /api/a-share/prices/snapshot?thscodes=600519.SH,000001.SZ
GET /api/a-share/prices/historical?thscode=600519.SH&interval=1d&start=<毫秒>&end=<毫秒>&adjust=forward
```

快照主要字段：`thscode`、`ticker`、`last_price`、`price_change_ratio_pct`、`open_price`、`high_price`、`low_price`、`prev_price`、`volume`、`turnover`。

历史日线主要字段：`date_ms`、`open_price`、`high_price`、`low_price`、`close_price`、`volume`、`turnover`。

- 历史接口单次一只股票，只支持 `1d`；
- `adjust` 保存为 `none`、`forward` 或 `backward`，不能混用；
- 竞价与盘中判断始终使用当日真实未复权价格；
- 长期结构可以使用明确版本的复权序列。

#### 15.3.4 指数、板块和成分

```text
GET /api/a-share-index/catalog/ths-index-list?tag=cn_concept
GET /api/a-share-index/catalog/ths-index-list?tag=industry
GET /api/a-share-index/constituents/ths-stock-list?thscode=886042.TI
GET /api/a-share-index/prices/snapshot?thscodes=000300.SH,000001.SH
GET /api/a-share-index/prices/historical?thscode=886042.TI&interval=1d&start=<毫秒>&end=<毫秒>
```

- 目录 `tag` 可取 `cn_concept`、`region`、`tszs`、`industry`；
- 板块目录字段：`thscode`、`name`；
- 成分字段：`thscode`、`ticker`、`name`；
- 成分接口返回当前成分。每日必须保存 `as_of_date` 快照，不能用今天的成员覆盖过去；
- 缺历史成员快照时，只能根据当日涨停原因和当时已经保存的题材事实重建部分归组，并标记 `PARTIAL`。

#### 15.3.5 涨停、跌停、炸板和当日原因

```text
GET /api/a-share/special-data/limit-up-pool?date_ms=<上海零点毫秒>&page=1&size=200&sort_field=limit_up_time&sort_dir=asc
GET /api/a-share/special-data/limit-down-pool?date_ms=<上海零点毫秒>&page=1&size=200
GET /api/a-share/special-data/limit-break-pool?date_ms=<上海零点毫秒>&page=1&size=200&sort_field=open_times&sort_dir=desc
GET /api/a-share/special-data/limit-up-ladder
```

涨停池主要字段：`thscode`、`ticker`、`name`、`is_st`、`is_new`、`last_price`、`price_change_ratio_pct`、`limit_up_time`、`limit_up_reason`、`continue_day_text`、`continue_day_cnt`、`seal_money`、`max_seal_money`。

炸板池重点字段：`open_times`、`turnover_ratio_pct`、`turnover`。`open_times` 是开板次数，不是连板数。

- 三个池均完整分页，单页最大 200；
- 非交易日空集合不等于请求失败；
- 连板天梯只是近 30 个交易日的有限矩阵，不能代替完整逐股涨停池；
- 当日方向归组以 `limit_up_reason` 为第一入口，但必须由方向内价格和角色协同继续确认；
- Financial-API 与 eltdx 最终状态冲突时，两条原始事实都保留，不能静默覆盖。

#### 15.3.6 集合竞价

```text
GET /api/a-share/auction/snapshot?thscodes=600519.SH,000001.SZ&stage=live
GET /api/a-share/auction/snapshot?thscodes=600519.SH,000001.SZ&stage=final
GET /api/a-share/auction/short-term-benchmark?date=2026-08-14
```

逐股快照主要字段：`auction_price`、`auction_pct`、`auction_volume`、`auction_amount`、`auction_unmatched`、`auction_turnover_pct`、`auction_yesterday_ratio_pct`、`auction_volume_ratio`、`pre_close_price`、`open_price`、`last_price`、`float_market_cap`。

- `stage=live` 和 `stage=final` 都没有历史日期参数；
- 它们可做当日快照和终态校验，不能恢复完整 09:15—09:25 序列；
- `short-term-benchmark` 可按日期恢复风向标列表和 `auction_pct/tags`，但不等于逐股竞价过程；
- 不能用当前终态反造中途撤单和排序变化。

#### 15.3.7 全市场历史文件

```text
GET /api/dump/market-dumps/daily-k/download-url
GET /api/dump/market-dumps/daily-k-10d/download-url
GET /api/dump/market-dumps/adjustment-factors/download-url
```

端点返回短时有效的 `data.presigned_url`，取得后立即下载 Parquet。

- 全量日 K 约覆盖最近十年；
- 近十日文件做日常增量；
- 复权文件保存分红、送股和配股事件；
- 日 K 按 `(thscode, trade_date, adjust)` 去重或更新；
- 本地落后超过七个交易日时，不使用十日文件猜缺口，应重新拉全量或逐日验收。

Financial-API 当前公开能力不包括分钟 K、逐笔成交、Level-2、A 股公告原文和研报。缺少这些数据时必须转向相应来源，不得对不存在的端点反复猜测。

### 15.4 eltdx 接入说明

#### 15.4.1 统一调用和代码格式

eltdx 常用代码是 `sz000001`、`sh600000`、`bj920856`。落库统一用 Financial-API 风格的 `thscode`，调用时转换：

```text

600000.SH → sh600000
920856.BJ → bj920856
```

转换函数必须通过沪、深、北交所样例测试，不能简单拼接错误后缀。

#### 15.4.2 日线和分钟 K 备用

`KlineBar` 主要字段：`time`、`open`、`high`、`low`、`close`、`volume_lots`、`amount`。

#### 15.4.3 竞价过程和 09:25 正式撮合

```python
auction = client.helpers.auction_data("sz000001")

```

`AuctionData` 包含：

- `series.points`：`time_label`、`time_seconds`、`price`、`matched_volume`、`unmatched_volume`、`unmatched_direction_raw`；
- `snapshot_0925`：`price`、`volume`、`order_count`、`event_kind="opening_match"`、`trade_amount_yuan`；
- 汇总字段：`pre_close_price`、`open_price`、`open_volume`、`open_amount`、`open_change_pct`。

重要边界：

1. 匹配量和未匹配量通常以“手”为单位，落库必须写明单位；
2. 竞价序列可能同时包含 14:57 后的尾盘集合竞价；
3. `auction_point` 只保存 09:15:00—09:25:00，14:57 后另存 `closing_auction_point`；
4. 竞价过程里的 09:25 虚拟点不一定是正式成交；
5. 正式开盘必须优先读取 `snapshot_0925` 或 `opening_match_history()`；
6. 只有正式开盘结果时，不能推断 09:15—09:20 是否撤单；
7. 历史数据是否存在由主站留存决定，接口方法存在不代表每个日期都有数据。

#### 15.4.4 分钟线


主要字段：`time_label`、`time`、`price`、`volume`、`avg_price`。

- 当日接口本身可能不返回交易日期，采集器必须按 `Asia/Shanghai` 补充并核对；
- 周末、凌晨和断线重连时要防止把上一交易日数据标成当天；
- 历史接口的 `open_price` 或 `avg_price` 可能为空；
- 分钟线可以确认下探、收回、翻红、低点抬高和分钟级先后；
- 分钟线不能严格证明主动买单、撤单者或账户动机。

#### 15.4.5 成交明细

`TradeTick` 主要字段：`time_label`、`trade_datetime`、`price`、`volume`、`order_count`、`event_kind`、`is_actual_trade`、`side`、`status_raw`、`trade_amount_yuan`。

### 15.5 监管规则和监管公告版本库 `[M/R]`

#### 正式来源优先级

1. 上海证券交易所规则库：`https://www.sse.com.cn/lawandrules/sselawsrules/`；
2. 深圳证券交易所规则库：`https://www.szse.cn/lawrules/rule/`；
3. 北京证券交易所业务规则：`https://www.bse.cn/business_rules/`；
4. 中国证监会规章规则：`https://www.csrc.gov.cn/csrc/c100028/common_list.shtml`；
5. 上市公司交易所公告或巨潮资讯原文：`https://www.cninfo.com.cn/`。

帖子、媒体文章和软件提示只能提供检索线索，不能作为规则正文。

#### 每一版规则至少保存

```text
exchange
board
security_scope
rule_name
rule_url
published_on
effective_from
effective_to
version
price_limit_rule
abnormal_move_window
deviation_formula
suspension_or_monitoring_consequence
source_file_hash
fetched_at
```

还要保存个股层监管事件：异动公告、风险提示、停复牌、重点监控公开信息及其生效时间。

#### 历史选择顺序

```text
T 日
→ 股票所属交易所和板块
→ T 日风险状态/ST/上市天数
→ effective_from <= T < effective_to 的规则版本
→ 计算当日涨跌停和异动窗口
→ 与官方公告结果核对
```

只能找到现行规则、找不到 T 日旧版时，输出 `RULE_VERSION_UNVERIFIED`。这会阻断精确监管空间结论，但不阻断日线、方向和角色的其他判断。

### 15.8 从事实表生成各阶段输入

| 阶段 | 最低输入 | 派生方式 | 缺少时的影响 |
| --- | --- | --- | --- |
| Stage 0 | 截止时间、数据目录、前日账本、规则版本 | 汇总覆盖清单 | 不知道覆盖就禁止继续推理 |
| Stage 1 | 指数日线/分时、宽度、涨跌停、昨日强股今日结果、大成交股 | 与过去窗口和昨日状态做相对比较 | 缺前日账本只能做今日截面 |
| Stage 2 | 涨停原因、方向成员、板块日线、跨日角色反馈 | 逐日维护方向状态，不读取“主流字段” | 缺历史成分时归组 `PARTIAL` |
| Stage 3 | 方向状态、涨停池、事件、关键结构、规则 | 根据 G1—G12 前态生成完整候选 | 前态缺失则相应节点不可用 |
| Stage 4 | 日线、量额、板位、带动关系、次日反馈 | 只赋功能角色候选 | 缺板块响应不能确认总核心/容量 |
| Stage 5 | 节点起算日、完整候选集、同时间轴和角色任务 | 分组后逐层淘汰 | 候选不完整不能确认唯一性 |
| Stage 6 | 今日角色和状态、环境、对手、规则 | 写竞价/开盘/盘中/失败四段任务 | 无前态不能判断超预期 |
| Stage 7 | 方向、节点、竞争组、逐票任务 | 建主、替代、不行动三路径 | 主路径无候选必须显式报错 |
| Stage 8 | 竞价序列、opening match、同组与板块快照 | 自身→对手→板块→可成交性 | 只有 09:25 不能判断撤单过程 |
| Stage 9 | 分钟、成交、板块和对手同步时间轴 | 卖压→停止走弱→收回→推进→外部响应 | 无分钟则承接和弱转强 `DATA_INSUFFICIENT` |
| Stage 10 | Stage 9 确认、预定支撑/阻力、盘口 | 确认发生位置决定动作类型 | 动作依赖数据缺失则不行动 |
| Stage 11 | 全日过程、最终日线、角色和板块结果 | 按原理由失效检查并更新账本 | 缺过程只能做收盘结构复盘 |

#### 昨日买方反馈怎样派生

它不是外部接口字段。对 T-1 日每个方向和角色保存候选集合，在 T 日计算：

- 竞价是否有溢价；
- 开盘后是否保持；
- 收盘收益分布；
- 晋级、炸板、跌停和大幅回撤比例；
- 核心、容量、助攻分别得到什么反馈。

作者没有统一样本窗口和阈值，因此输出分布和分层事实，不生成单一“买方反馈分数”。

### 15.9 每个交易日的采集时刻

| 时间 | 必须采集 | 用途 |
| --- | --- | --- |
| 盘前 | 上一交易日日线、涨跌停池、原因、板块日线、公告、当日规则 | 补齐盘后计划输入并核验缺失 |
| 09:15—09:20 | 作战候选、同组全体和关键验证股竞价过程 | 保存初始展示，不下最终结论 |
| 09:20—09:25 | 同一集合持续采样 | 观察不可撤单阶段的保持和排序迁移 |
| 09:25 后立即 | 09:25 正式撮合和 Financial-API `stage=final` | 固化正式开盘价、量和额 |
| 09:30—09:35 | 候选、全部对手、板块指数、核心/容量的分钟、成交和五档增量 | 第一轮卖压、承接和相对主动性 |
| 盘中关键事件 | 上板、炸板、回封、板块急涨急跌时追加快照 | 保存事件顺序而不只留收盘结果 |
| 14:57—15:00 | 尾盘竞价和最终撮合 | 尾盘确认及收盘事实 |
| 收盘后 | 最终日线、涨跌停、原因、板块、宽度、公告 | 角色重算、反馈和账本更新 |
| 数据就绪后 | 近十日日 K 增量或全量校验 | 长期仓库维护 |

竞价、五档和成交高频采集应围绕：动作候选、完整同组对手、情绪核心、容量核心和必要板块代理。只抓最终九只动作股票会破坏唯一性与卡位判断。

### 15.10 数据质量验收

每张表、每个交易日和每只关键股票都要保存：

```text
availability: AVAILABLE / PARTIAL / EMPTY / ERROR
expected_start
actual_start
expected_end
actual_end
row_count
duplicate_count
missing_intervals
unit_check
source_request_id
checked_at
```

专项检查：

1. 交易日是否按上海时区；
2. 日线是否覆盖完整股票池，是否混入未来上市状态；
3. 竞价是否错误混入 14:57 后记录；
4. `opening_match` 是否真的来自正式 09:25 撮合；
5. 分钟和成交是否覆盖 09:30—09:35；
6. 同一竞争组是否拥有同时间轴；
7. 成交量单位是否把手和股混在一起；
8. 涨跌幅是否重复乘 100；
9. 板位和全市场最高板是否混用；
10. 两个来源冲突是否被记录而非覆盖。

### 15.11 结论级降级矩阵

数据集“存在”不代表某个结论可得。每个结论单独判断证据级别。

| 现有数据 | 可以输出 | 必须禁止 |
| --- | --- | --- |
| 日线 + 最终涨跌停 | 日终结构、梯队、区间强弱、节点候选 | 竞价过程、五分钟承接、盘中先后 |
| 日线 + 09:25 正式撮合 | 最终开盘相对强弱 | 09:15—09:20 撤单和排序迁移 |
| 完整竞价序列，无分钟 | 竞价保持/衰减、最终开盘任务 | 开盘承接、弱转强最终确认 |
| 分钟线，无逐笔 | 下探收回、低点抬高、分钟级相对先后 | 严格主动买卖和撤单意图 |
| 逐笔成交，无委托队列 | 秒级成交事件顺序 | 完整挂单、撤单者和账户动机 |
| 单票过程，无板块/对手 | 单票价格路径 | 板块共振、卡位、唯一性、主动带动 |
| 板块当前成分，无历史快照 | 当前归组 | 历史完整竞争组 |
| 涨停原因，无正式公告/产业资料 | 当日市场叙事线索 | 催化真实性、产业瓶底确认 |
| 现行监管规则，无历史版本 | 当前规则判断 | 历史精确监管空间 |

### 15.12 什么是真正的 `BLOCK`，什么不是

#### 只阻断具体结论

- 无分钟线：阻断开盘五分钟承接、弱转强最终确认和分钟级主动性；不阻断盘后方向、节点和竞价终态。
- 无逐笔成交：阻断严格成交主动性；分钟级价格顺序仍可保留。
- 无委托队列：阻断撤单者、挂单动机和严格主动炸板；不阻断成交事件顺序。
- 无板块分时：阻断盘中板块共振和主动带动；不阻断日终板块结构。
- 无完整同组竞价：阻断卡位和唯一性确认；单票竞价事实仍可记录。
- 无历史监管版本：阻断精确监管剩余空间；其他市场推演继续。
- 无正式产业和公告原文：阻断瓶底或催化强度确认；涨停原因仍可作为方向线索。

#### 不是数据缺失

以下问题不能归咎于接口：

- 主流判断：本来就要逐日推演；
- 核心、容量、补涨和伴生：本来就要由角色关系推断；
- 次日预期：本来就要根据前态写可证伪任务；
- 洗盘/出货：本来就不能直接读取主力意图；
- A/B/C/D 完整算法：作者没有提供；
- 主动炸板统一算法：作者没有提供；
- 多个候选最终选谁：必须通过节点、竞争、竞价和开盘逐层淘汰。

#### 全阶段真正停止条件

只有以下情况才停止整个当次推理：

1. 截止时间不明确；
2. 不知道事实是否包含未来数据；
3. 股票代码、日期或单位无法可靠解析；
4. 事实包来源不可追溯；
5. 关键事实与未来结果混在一起且无法分离。

其他缺口原则上只让对应结论变成 `DATA_INSUFFICIENT`，不能把整份分析伪装成完成，也不能让所有已知步骤一起瘫痪。

## 16. 作者没有讲清楚、只能条件化使用或自身冲突的地方

这一章不是附带免责声明，而是执行规则的一部分。AI 每次碰到这些问题，都必须按本章降级，不能为了输出完整而自行补公式。

### 16.1 如何区分“未知”“个案”和“冲突”

| 类型 | 含义 | AI 应怎样处理 |
| --- | --- | --- |
| `UNKNOWN_METHOD` | 作者没有给出可以跨案例执行的定义或算法 | 明确写不知道，不由模型自由发挥 |
| `CASE_ONLY` | 作者讲过一个或少数案例，但缺少通用参数、边界或反例 | 只做相似关系候选，必须继续验证 |
| `CONFLICTING_GUIDANCE` | 不同文章对同一问题给出不同口径 | 只执行稳定交集，冲突部分并列展示 |
| `EXTERNAL_FACT_REQUIRED` | 结论依赖交易所、公司、产业或行情事实 | 到正式数据源核验，不能从帖子取得 |

“全文找到过这个词”不等于方法已经完整。只有前提、观察、比较、确认、取消和适用范围都能说明，才可以称为稳定执行规则。

### 16.2 只有局部案例，没有通用答案 `[K]`

| 编号 | 问题 | 原文能确认到哪里 | 不能自动做什么 | 当前工程处理 |
| --- | --- | --- | --- | --- |
| U01 | A/B/C/D 载体 | A、B、D 在少数周期中有助攻、承接或后段续命描述 | 不能推出 C 的定义、完整等级、稳定排序和升级降级算法 | 实时只使用总核心、容量、助攻、补涨、伴生、二波等功能角色；字母仅留离线研究 |
| U02 | 主动/被动分歧 | 有板块先弱、个股后回落，以及新核心先强、旧核心后反抽等判例 | 不能自动二分所有分歧 | 记录参照物和事件顺序，输出候选或无法确认 |
| U03 | 主动炸板 | 少数案例使用过标签 | 没有统一订单流、撤单、卖单和时间阈值 | 不生成自动分类，只描述炸板、承接和回封事实 |
| U04 | 次日具体高开幅度 | 前一日状态决定次日强弱惯性，案例中出现过具体百分比 | 不能从前态计算通用高开百分比 | 写相对任务：应强于自己和同组谁，不生成固定数字 |
| U05 | 封单和竞价量标准 | 案例出现 10 万手、20 万手、400% 等数字 | 不能跨股本、价格和环境照搬 | 保存原始值及相对自身、流通盘和同组的位置 |
| U06 | 卖压充分释放 | 有回踩、换手、收回和继续推进的关系 | 没有多少成交、多少分钟即充分的标准 | 以“卖压出现→停止走弱→收回→保持→推进”过程确认 |
| U07 | 容量核心固定门槛 | 稳定部分是大成交、流动性、推进、承接和带动 | 不能选择 10 亿、30 亿、40 亿或成交排名作为统一门槛 | 在方向内相对比较，按角色功能确认 |
| U08 | 赚钱/亏钱效应 | 作者观察隔日溢价、晋级、跌停、强势股和大成交反馈 | 没有统一样本池、窗口和阈值 | 分核心、容量、助攻和后排输出反馈分布，不生成总分 |
| U09 | 增量资金有效标准 | 成交放大和大票推进被反复重视 | 没有统一市场成交金额或增量阈值 | 与自身历史和方向结构相对比较 |
| U10 | 超买、超卖和背离 | 用于顶部风险、底部修复和反人性节点的个案很多 | 没有统一指标、参数、周期和阈值 | 只作为辅助候选，必须由价格和角色确认 |
| U11 | 时间周期和“第几天” | 有三日确认、三四日竞争、若干节点日案例 | 不能建立固定第 N 天买卖算法 | 以角色跨日协同和任务完成为主，天数只作案例背景 |
| U12 | 等距浪 | 单篇案例使用过第一波与第三波等距关系 | 没有波段起终点、容差和适用市场定义 | 只作高位风险线索 |
| U13 | 高低位巨量 | 有低位换手确权和高位放量滞涨案例 | 没有统一倍率；位置本身也不证明资金意图 | 结合位置、价格结果、板块与次日反馈 |
| U14 | 筹码干净、锁仓、控盘、吸筹 | 原帖有这些解释词 | 公开行情不能直接观察账户动机 | 改写为换手、成交密集区、价格保持和后续反馈 |
| U15 | 新资金是否足够接棒 | 低位扩散、补涨、伴生和次日溢价可做间接观察 | 没有直接的“接棒资金足够”指标 | 继续看梯队延续和下一日买方反馈 |
| U16 | 效应复制何时耗尽 | 有破局后同类结构继续获得奖励的案例 | 没有衰减次数和终止阈值 | 保存全部匹配及失败对照，逐次更新反馈 |
| U17 | 瓶底各因素权重 | 产业、政策、估值、资金、高低切和筹码都被提及 | 没有固定组合权重 | 各层独立核验，只形成中周期假设 |
| U18 | 尾盘确认 | 可用于监管、回流和突破保持等不同目的 | 没有统一时间窗口和成交要求 | 盘前先写明等什么事实，再决定是否需要尾盘 |
| U19 | 多个不同角色同时成立时的固定优先级 | 核心、容量、助攻可以同时存在 | 没有“某角色永远优先”的通则 | 当前节点需要谁完成任务，就进入谁的竞争组 |

### 16.3 作者自身冲突 `[X]`

| 编号 | 冲突问题 | 并存口径 | 稳定交集 | 执行方式 |
| --- | --- | --- | --- | --- |
| X01 | 容量成交标准 | 10 亿以上、30 亿以上、40 亿附近、排名前 10/50 等 | 大成交、可进出、价格能推进、分歧后承接、能稳住或带动板块 | 不设固定成交额门槛 |

| X06 | 上升停顿 | 可作为该涨不涨和退出信号；也可解释为控速和蓄力 | 停顿后方向未定，必须等向上或向下确认 | 先标 `PAUSE_PENDING_DIRECTION` |
| X07 | 仓位和“重仓” | 满仓、重仓、总仓七成、单票三成或四成、核心二至三成等并存 | 没有跨时期统一百分比 | 本项目不输出仓位比例 |

### 16.4 依赖外部正式事实的问题 `[M]`

| 问题 | 正确来源 | 帖子在系统中的地位 |
| --- | --- | --- |
| 涨跌停、异动、停牌和重点监控规则 | 当时有效的交易所、证监会规则和正式公告 | 只作为离线方法线索 |
| 公司公告、业绩和风险提示 | 交易所、巨潮和公司正式披露 | 不能作为公司事实来源 |
| 政策和产业催化 | 发布机关原文、正式行业资料和可核验数据 | 只能提示需要核验的方向 |
| 历史价格、竞价和成交顺序 | 独立行情数据 | 不能用作者复盘恢复盘口 |
| 作者实际买卖和收益 | 可核验交割记录；当前没有 | 一律不作为规则有效性证据 |

### 16.5 碰到未定义问题时的固定响应

```text

分类：UNKNOWN_METHOD / CASE_ONLY / CONFLICTING_GUIDANCE / EXTERNAL_FACT_REQUIRED
```

## 17. 稳定规则 ID 与 AI 运行契约

### 17.1 版本规则

本稿发布时的方法版本定义为：

```text
manual_version = roubing-executable-manual-v1.0.0
rule_registry_version = rr-v1
```

规则 ID 一旦发布，不得改变原意。以后发现错误时：

- 小幅文字澄清但逻辑不变：升级补丁版本；
- 新增规则或兼容字段：升级次版本；
- 改变执行顺序、判断含义或删除核心规则：升级主版本；
- 废弃旧规则：保留 ID 并标 `DEPRECATED`，不得把旧 ID 分配给新含义。

| `CMP-005` | 先淘汰前态、任务、方向、结构、规则或数据已失败者，再比较强弱 |
| `CMP-006` | 比较顺序为任务→主动→承压→外部功能→次日反馈→监管空间 |
| `CMP-007` | 卡位必须超过同组角色任务、保持、带动并由后续确认 |
| `CMP-008` | 唯一性按 GROUP_OPEN→候选→暂时唯一→确认→替代/取消维护 |
| `CMP-009` | 竞争组不完整或缺同时间轴时禁止确认卡位和唯一性 |
| `CMP-010` | 完整候选池用于防后验；次日动作名单必须另行收敛为唯一或条件唯二 |
| `CMP-011` | 同一节点仍有三只及以上无法排除时只观察，等待后续唯一性节点 |

#### 次日预期 `EXP`

| ID | 稳定含义 |
| --- | --- |
| `EXP-001` | 预期是角色的可证伪任务，不是预测具体涨幅 |
| `EXP-002` | 任务按角色义务→今日状态→环境/方向→同组对手生成 |
| `EXP-003` | 每只候选必须写竞价、开盘卖压、盘中角色和直接失败四段任务 |

| `EXP-009` | 盘后必须写明 PRIMARY、BACKUP、各自触发、切换条件和全部放弃条件 |

#### 三条路径和最终选择 `PTH`

| ID | 稳定含义 |
| --- | --- |

### 17.3 离线规则编译与在线推理必须隔离

系统分成两个完全不同的过程：

```text
离线规则编译
原帖 → 人工/AI 复核 → 稳定规则、个案、冲突、来源映射 → 发布手册版本

在线每日推理
已发布手册 + 当时事实包 + 前日账本 → Stage 0—11 → 当日结论
```

在线推理进程不得拥有原帖路径、向量库、帖子检索器或历史作者答案的读取权限。不是“提示模型不要看”，而是输入和文件权限层面都不提供。

本文件为了让人工评审只读一个文档，后面同时保存了离线来源映射和纸面答案。这不表示在线模型可以读取全文。构建发布版本时必须只提取：

文件顶部的 `ONLINE_RUNTIME_RULES_START` 标记，到第 18 章前的 `ONLINE_RUNTIME_RULES_END` 标记。

之间的内容，生成只读 `online_rule_projection`，并保存内容哈希。第 18 章以后均属于离线审计区，不得进入在线上下文。若运行输入出现结束标记以后的任意内容，本次运行直接标记 `INVALID_RUN`。

### 17.5 在线运行明确禁止的输入

- roubing 原帖正文、截图、标题、作者回复和检索片段；
- 任何包含“作者当时买了什么”的答案文件；
- 当前截止时间之后的开盘、涨停、收盘和收益；
- 用未来结果整理出的赢家名单；
- 当前版本的板块成分回填历史；
- 当前监管规则回填旧日期；
- 其他投资 skill、外部交易提示或未经登记的知识库；
- 模型上一次自由文本结论，除非已经通过审计写入正式状态账本。

运行环境必须输出 `loaded_external_skills=[]` 和 `retrieval_sources=[]`。任何非空结果都使本次正式运行作废。

### 17.6 阶段门禁

| 进入阶段 | 必须已经存在 | 缺少时怎样处理 |
| --- | --- | --- |
| Stage 1 | 明确截止时间和最低市场事实 | 停止或只记录数据缺口 |
| Stage 2 | Stage 1 环境结果及方向归组事实 | 不判断主流 |
| Stage 3 | 方向状态和节点前态 | 相应节点不得生成候选 |
| Stage 4 | 合法候选和功能事实 | 不赋予确认角色 |
| Stage 5 | 节点起算日、角色任务和完整候选 | 不判断卡位/唯一性 |
| Stage 6 | 仍有效的竞争候选 | 不生成逐票预期 |
| Stage 7 | 方向、节点、组和逐票任务 | 不生成作战路径 |
| Stage 8 | 盘前冻结路径和任务 | 只记录竞价事实，不评预期差 |
| Stage 9 | 竞价结论、预定参照和分钟覆盖 | 承接/弱转强数据不足 |
| Stage 10 | 路径、角色、竞争和开盘确认 | 强制不行动 |
| Stage 11 | 原动作理由和全日可得事实 | 只做允许精度的复盘 |

任何阶段不得通过自由文本重新创造上一阶段缺失的对象。

### 17.7 每个判断必须输出的“可审计理由”

这里要求的是面向用户和审计器的证据摘要，不要求模型展示无法验证的内部思维过程。

```text
stage：
as_of_time：
读取的 fact_id：
使用的 rule_id：
看到了什么：
比较对象和比较结果：
怎样得到当前状态：

最强反方证据：
为什么反方暂未胜出或已经推翻原结论：
下一步只验证什么：
取消条件：
当前禁止推出什么：
```

“看到了什么”必须是事实，“怎样得到当前状态”必须引用规则 ID。只写“综合判断”“逻辑较好”“资金认可”视为不合格。


```text

当前真实节点：

完整候选：

仅用于验证的对象：
```

若没有唯一动作对象，只允许输出已经盘前命名的条件唯二或不行动，不能保留三只以上动作候选，也不能为了满足接口字段随便选择第一名。

### 17.10 五类自动审计器

#### 1. 时间审计

- 所有 `available_at <= as_of_time`；
- 09:25 结果不得出现在 09:20 快照；
- 09:35 之前不得使用最终涨停和收盘；
- 历史规则版本和板块成员日期正确。

#### 2. 事实忠实审计

- 每个事实句都有 `fact_id`；
- 数值、单位、代码和日期与事实表一致；
- 空值没有被解释成零或弱；
- 没有把涨停原因写成已证实因果。

#### 3. 规则忠实审计

- 每个推断引用有效 `rule_id`；
- `[K]` 没有被写成通用公式；
- `[X]` 只使用稳定交集；
- `UNKNOWN` 没有被语言包装成确认。

#### 4. 流程门禁审计

- 候选确实来自节点；
- 角色确实来自合法候选；
- 竞争组完整且同功能；
- 主路径有动作候选；
- 替代路径有独立成立条件；
- 动作对象通过了竞价和开盘所需确认。

#### 5. 来源隔离审计

- 实际加载内容的哈希与 `online_rule_projection_hash` 一致；
- 输入只包含在线标记区，不包含第 18 章以后内容；
- 运行输入和日志中没有原帖正文、标题、URL 和历史案例名；
- 没有“原帖说、作者记载、作者关注”等表达；
- `loaded_external_skills=[]`；
- `retrieval_sources=[]`；
- 没有调用未列入 `data_contract_version` 的外部研究源。

任一时间泄漏、原帖泄漏或外部 skill 污染都使整个运行 `INVALID_RUN`。一般结构或字段问题可在不改变事实的前提下重试；不得通过补充未来信息修复。

### 17.11 独立审计与重试顺序

每个阶段先经过程序 Schema 和硬规则校验，再交给独立审计模型检查语义忠实度。审计模型只能读取：该阶段输入、输出、规则 ID 摘要和事实行，不能读取原帖。

重试顺序：

1. 修复 JSON、字段、枚举或引用错误；
2. 删除没有事实支持的句子；
3. 将越权确认降级为候选、未知或数据不足；
4. 若仍失败，标记阶段失败并停止后续依赖阶段；
5. 禁止为了通过审计而添加新叙事或未来事实。

### 17.12 面向用户的真实过程报告

每次正式执行结束，必须用普通话逐阶段说明：

1. 这一阶段原本要解决什么；
2. 实际读取了哪些事实；
3. 事实是否完整；
4. 按哪些规则比较；
5. 得到了什么结论；
6. 哪个反方证据最强；
7. 哪些候选被淘汰，具体因为什么；
8. 下一阶段要验证什么；
9. 哪些环节因数据或方法未知没有完成；
10. 最终为什么选择或为什么不行动。

报告不得美化：阶段没有数据就直接说没看到，规则没有算法就说不知道，模型判断被审计推翻也要保留原错误与修正记录。

#### Stage 2 执行卡：方向和主流

```text
输入：Stage 1 环境、题材/原因/催化归组、历史方向账本、板块指数、先锋/容量/扩散和买方反馈

取消/停止：先锋不延续且容量不推进；核心、容量和扩散连续失效；方向只剩孤立反抽

下一步：把每个仍有效方向的当前阻力交给 Stage 3
输出：direction_state[]、provisional_main_direction、alternative_directions、direction_gaps、next_tests
```

```text
观察：原阻力是什么、什么事实正在改变、受益角色是谁、自然候选池是谁
比较：先检验前态，再检验阻力变化、候选池完整性和次日可验证性
最强反方：只有相似 K 线或日期，没有真实前态；候选池由结果赢家倒推；所需过程数据不存在
取消/停止：前态不存在、阻力未改变、候选池不完整且无法恢复、方向已结束时取消相应节点
数据降级：节点事实可见但确认链缺失时只标 CANDIDATE；起算日不明时禁止 G2/G4/G5/G8
下一步：将合法节点和完整候选池交给 Stage 4
```

#### Stage 4 执行卡：功能角色

```text
观察：每只股票当前为方向完成了什么外部任务，而不是它叫什么称号
比较：先与该角色最低义务比较，再与承担同一功能的候选比较；不同角色不混排
最强反方：只有涨幅、成交或历史人气，没有推进、承接、带动或扩散
取消/停止：角色任务失败、被新候选接管、方向关系断裂时角色降级或失效
数据降级：缺板块同步不能确认带动；缺分钟不能确认承接；只有大成交只能标容量候选
下一步：按节点、功能和截止时间建立 Stage 5 竞争组
输出：role_hypothesis[]、role_status、role_evidence、role_counter_evidence、role_failure_conditions
```

#### Stage 5 执行卡：竞争组和唯一性

```text
输入：节点、起算日、方向、角色任务、资金类型、完整候选和统一截止时间
观察：任务完成、谁先主动、谁承压、谁完成外部功能、后续反馈和监管空间
比较：只比较同任务、同阶段、同时间轴候选；按六层逐项淘汰，不做总分
最强反方：直接对手缺失；候选承担不同任务；暂时涨幅领先但没有带动和后续确认
取消/停止：组不完整时停止唯一性确认；方向或节点取消时整组结束；新候选接管时原领先者 REPLACED
数据降级：缺同时间轴只保留 GROUP_OPEN 或 LEADER_CANDIDATE；三只及以上无法排除时该节点不得生成动作叶子
下一步：只把 action_shortlist 交给 Stage 6 写动作任务；validation_only 只写验证任务
输出：competition_group[]、complete_candidate_pool[]、action_shortlist[]、validation_only[]、excluded_with_reason、group_state、unknowns
```

#### Stage 6 执行卡：次日预期

```text
输入：环境、方向、节点、角色、竞争组、action_shortlist、validation_only、今日状态、监管和可用数据说明
观察：角色基础义务、今日状态修正、环境修正、与自己/对手/板块的关系
比较：动作对象与自身惯性、直接对手和板块三重比较；验证对象只判断其支持或否定哪条路径
最强反方：任务依赖没有的数据；前态并不弱却被写成弱转强；案例数字被复制为通用阈值
取消/停止：无法写清动作角色、直接失败条件或比较对象时，将该票移出 action_shortlist；不得把验证卡伪装成作战卡
数据降级：前态或对手缺失时只记录表现，不评价预期差；精确高开和封单保持 UNKNOWN
下一步：把已经明确到股票的 PRIMARY/BACKUP 决策卡组织成 Stage 7 封闭条件树
输出：action_decision_card、PRIMARY、BACKUP、各自竞价/开盘触发、切换条件、全部放弃条件、validation_task[]
```

#### Stage 7 执行卡：主、替代和不行动路径

```text
输入：方向优先级、合法节点、action_decision_card、验证角色和验证任务
观察：主路径能否独立成立；替代路径是否有自身正向条件；不行动条件是否明确
比较：先确认每条路径盘后是否已有唯一或条件唯二动作对象，再写主备切换；不在本阶段扩充名单
最强反方：主路径没有命名动作对象；替代路径只依赖主路径失败；只有验证股票没有可执行对象
取消/停止：任一路径无法收敛到两只以内时，该路径只观察；所有路径均无动作对象时直接冻结 NO_ACTION
数据降级：无法拉开候选时只能 PRIMARY=NONE、BACKUP=NONE；不能为接口强选唯一股票
下一步：冻结 PRIMARY、BACKUP 和 ELSE=NO_ACTION，交给 Stage 8 竞价验证
```

```text
最强反方：初始强单衰减、正式开盘失真、直接对手更强、板块不响应或核心不可成交
取消/停止：PRIMARY 只是数据不足时不切备用；PRIMARY/BACKUP 均未命中时直接 NO_ACTION；没有盘前动作叶子时只验证路径
数据降级：只有 09:25 时不描述撤单过程；组不完整时不确认卡位；无板块竞价时不确认共振
下一步：最多一个 current_action_candidate 进入 Stage 9；其余对象继续只作验证
输出：auction_validation[]、path_status、condition_tree_hit、current_action_candidate 或 NONE、data_insufficient_relations、open_tests
```

```text

观察：只对该对象检查第一轮卖压→停止走弱→收回→继续推进→同组/板块事件顺序→角色任务
比较：与盘前支撑、开盘价、均价、直接对手和板块响应比较
最强反方：只有止跌没有收回；只有收回没有推进；板块先动目标后跟；很快跌回原位
取消/停止：无 current_action_candidate 时动作流程已经结束；目标跌破预定关系且不能修复、角色任务失败或对手先接管时取消，不换新票
数据降级：无分钟不确认承接/弱转强；无逐笔不确认严格主动买卖；无委托不解释撤单意图
下一步：只有这一个对象完成所需确认时才进入 Stage 10；否则 NO_ACTION
输出：current_action_candidate、open_validation、support_status、initiative_status、sequence_evidence、cancelled_without_replacement
```

#### Stage 10 执行卡：动作选择

```text
输入：唯一 current_action_candidate、已确认路径、真实节点、开盘验证、支撑/阻力和可成交性
观察：该对象的低吸、半路、回封、尾盘确认触发链，或不行动条件
比较：哪种预写动作与当前节点和角色相符；本阶段不再比较或替换股票
最强反方：只有形态没有路径；错过触发后降低标准；核心不可成交便自动买后排
取消/停止：任一关键前提、竞争关系或所需数据不足时不行动；触发后立即失败则取消动作理由
数据降级：不能确认分钟路径时不输出依赖该路径的动作；动作对象为 NONE 时直接不行动
下一步：若形成动作，进入 Stage 11 持有检查；无动作则只做收盘回评
输出：action_research_decision、action_object、trigger_type、trigger_facts、cancel_conditions、no_action_reason
```

#### Stage 11 执行卡：持有、退出和账本

```text
输入：原动作理由、全日事实、方向/角色/竞争组状态、监管和催化更新
观察：动作是否立即失败→角色是否继续→板块路径是否有效→是否出现替代和结构破坏
比较：实际表现与原任务、直接对手、板块和原支撑/阻力比较
最强反方：成本和历史称号造成持仓偏见；单一指标被当成顶部；反抽被当成角色恢复
取消/退出：该强不强、角色被替代、板块秩序恶化、高位推进失败、结构或外部前提失效
数据降级：缺盘中过程只评价日终任务，不还原买卖点和主动性；规则冲突时只用稳定交集
下一步：收盘去除持仓立场，生成下一交易日唯一状态账本
输出：hold_or_exit_review、role_migration、failure_reason、close_review、next_state_ledger
```

每张执行卡完成后都必须写 `最强反方证据`。若没有找到反方，只能写“尚未找到，可能是数据覆盖不足”，不能写“没有风险”。

推演分成三个互相隔离的时间切片：

1. `T = 2026-01-05 CLOSE`：只生成环境、方向、节点、角色、竞争组、次日任务和三条路径；
2. `T+1 = 2026-01-06 09:25`：只用早盘竞价过程和正式开盘结果验证盘后计划；
3. `T+1 = 2026-01-06 CLOSE`：只用于复盘当天任务是否完成，不得倒推 09:25 或 09:35 当时不存在的买点。

本次测试有一个必须如实披露的限制：交接材料已经记载了部分 1 月 6 日结果，因此它不是统计意义上的全盲回测。本文仍按 `available_at` 做时间隔离，但只能用于检查流程和结论降级，不能作为策略胜率证据。

### 19.4 Stage 1：市场环境只能得到“偏强截面”

按 `ENV-001` 的顺序逐项检查：

1. **指数风险：** 指数数据缺失，不能确认是否不存在系统性快速下行；
2. **昨日买方：** 数据缺失，不能判断昨日强势股是否普遍得到奖励；
3. **大成交推进：** 事件池中存在中国卫通等大成交涨停，也存在金风科技、五洲新春等大成交炸板，结论是“分化中仍有推进”，不是全部良好；

因此输出：

```text
market_environment：UNKNOWN
cross_section_description：STRONG_BUT_NOT_HISTORICALLY_CONFIRMED
current_status：DATA_INSUFFICIENT
```

普通话解释：1 月 5 日当天很强，成交也明显放大，允许继续找结构化机会；但系统不知道前一天哪些人赚钱、指数路径怎样，也没有旧方向账本，所以不能把“当天很强”包装成“已确认主升环境”。

### 19.16 与作者事后复盘的离线答案对照

3. **本次不能复现处：** 作者的“超级主流”判断依赖 12 月以来的逐日状态，本次缺前日账本，不能合法复现；
4. **本次不能复现处：** 作者称北斗星通 1 月 5 日存在分时低点机会，但当前 1 月 5 日分钟线缺失，无法检查那个低点的卖压、承接、同组顺序和当时可成交性；
5. **不能倒推出的结论：** 北斗星通 1 月 6 日最终三板，不证明系统在缺开盘分钟线时应该于 09:25 或 09:35 买入；

### 19.17 本次纸面推演发现并固定的流程修正

1. 主路径必须实际拥有该方向的动作竞争组，不能出现“主线是 A，所有作战卡却来自 B”；
2. 同日起算组必须保存完整候选，不能盘后凭静态叙事从 27 只先删到 9 只；
3. 高度、二进三、容量和首板扩散承担不同任务，不能做全方向综合排名；
4. `09:15` 虚拟涨停、竞价末端虚拟价和 `opening_match` 正式开盘必须分列；
5. 竞价强只说明需要进入开盘验证，不自动等于承接或弱转强；
6. 缺一个直接竞争者，就不能确认完整组卡位和唯一性；
7. 多只股票共同晋级时，应保留多人有效状态，不为满足接口强选一个“唯一龙头”；
8. 日终涨停时间可以评价任务完成，不能恢复早盘不存在的分钟路径；
9. 方向延续和个股买点是两个结论：本次商业航天和人脑工程日终都得到延续反馈，但由于 Stage 9 数据缺失，动作层仍然是不行动；
10. 作者事后答案只用于离线审计，不能进入正式每日推理输入。

### 19.18 本次验证证明了什么、没有证明什么

已经证明：

- 手册可以在单日事实下生成方向、节点、角色、完整竞争组和条件路径；
- 主路径和候选股票能够保持一致；
- 竞价数据不完整时，系统可以只降级唯一性，而不否定所有方向事实；
- 开盘分钟缺失时，系统能停在“不行动”，不会用日终赢家补故事；
- 多角色、多候选可以同时存在，不需要综合总分或强制唯一股票。

没有证明：

- 这套方法具有怎样的历史胜率或收益；
- 1 月 5 日以前商业航天如何逐日从启动变成超级主流；
- 北斗星通 1 月 5 日分时低点是否满足本手册的低吸触发；
- 1 月 6 日 09:30—09:35 谁先承接、谁带动谁；
- 城建发展、北斗星通或中国卫通谁最终成为跨日唯一角色；
- 人脑工程 27 只候选后续如何淘汰到唯一载体；
- 任何主动炸板、主力吸筹、洗盘或资金账户迁移结论。

因此本次结果是“流程通过有限数据测试，动作层因数据不足正确停止”，不是“策略已经回测有效”。
